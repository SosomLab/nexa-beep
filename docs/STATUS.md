> **직전(08-08 14차)** — **ADR-0010 개정 — "대체 알림"을 [수신자 릴레이](24-adr-0010-message-priority-notification.md#6-수신자-릴레이-요구--내-메시지를-내가-정한-외부-채널로)로 재정의 + 다중 어댑터 팬아웃**(사용자 요구 ④):
> ① ⚠️ **용어부터 갈랐다** — 이 프로젝트에는 **DR-8 ②의 전송 릴레이**(`nexa-beepd`)가 이미 있다. **전송 릴레이는 경로를 바꾸고**(같은 메시지가 같은 수신자에게 다른 길로) **수신자 릴레이는 매체를 바꾼다**(내 알림이 나에게 다른 채널로). 한정어 없이 "릴레이"라고 쓰면 문서·코드가 섞이므로 **항상 한정어**를 붙이고 타입도 `RelayChannel` vs `TransportRelay`로 가른다.
> ② ★ **주체가 수신자라는 점을 설계의 중심으로** — *"내 메시지를 내가 정한 규칙으로 내 채널에"*. **발신자는 채널을 고를 수 없고 존재조차 모른다.** 메일 클라이언트의 **필터·전달 규칙**과 같은 성격이라 동의·연락처·악용이 한꺼번에 정리된다.
> ③ **규칙 = `조건 → 채널 집합`** — 조건 3종(등급 · 발신자 범위 · 내 상태[부재·미확인]) → 동작 2종(채널 집합 · **채널별 노출 수준**). **룰 엔진으로 키우지 않는다.** *"본인이 직접 의사 결정"* 의 가장 순수한 형태인 **1회성 수동 릴레이**("이 알림을 내 메일로")도 함께.
> ④ ★ **다중 어댑터 동시 팬아웃**(요구 ④) — **병렬 발송 · 채널별 개별 타임아웃 · 부분 실패 정상 취급 · 채널별 결과 표시**(*"메일 ✓ / 웹훅 ✗"*) · 메시지당 채널당 1회 · **묶음도 채널별** · 재시도 백오프 + **큐 상한**. 순차 단계는 옵션. ★ **구조가 `수신자 = PeerId 집합` 팬아웃(FR-G-6)과 같은 모양** — 원소만 `RelayChannel`로 바뀌어 **개념이 늘지 않는다**.
> ⑤ **노출 수준은 채널마다 따로**(기본 L0=사실만) — *"개인 메일엔 본문, 팀 웹훅엔 사실만"*. 유출이 목적이 아니어도 **L1/L2에는 "이 채널은 E2E가 아니다" 고지**를 유지한다(사실은 사실대로).
> ⑥ **R-13 재정의** — *"증폭 공격"* → ***"내가 켠 규칙이 나를 때린다"***. 수신자 통제라 위험의 대부분은 이미 사라졌지만 **무인증 상대가 내 규칙을 격발**시키는 건 남는다. 그래서 **차단이 아니라 안전한 기본값**(신규 규칙은 검증된 상대만 · **사용자가 넓힐 수 있다** — 결정권을 뺏지 않는다) + **속도·일일 상한은 끌 수 없게**(외부 서비스·타인은 내 결정권 밖이라서).

> **직전(08-08 13차)** — **[24 ADR-0010](24-adr-0010-message-priority-notification.md) 메시지 등급 · 알림 강도 · 수신 확인 · 대체 알림 채널**(사용자 요구 2건) — 📐 **Proposed · 확정 대기**:
> ① ★ **축이 두 개다** — **등급은 발신자의 "요청"**(`Normal`/`Notice`/`Urgent`), **알림 강도는 수신자의 "판정"**(`Silent`/`Badge`/`Toast`/`Alarm`). 하나로 합치면 **제로 컨피그(DR-1)라 누구나 발신할 수 있으므로 무인증 상대가 내 스피커와 화면 최상단을 직접 제어**하게 된다. 이미 세 번 쓴 패턴의 재적용(발견=미검증 힌트 · `UserId`=상대의 주장 · 수신 파일=누가 보내든 안 믿는다).
> ② **신뢰 등급이 강등표의 세로축** — **미검증 상대는 소리·최상위 창을 얻지 못한다**(자동 강등 · **강등 사실은 표시**) · 그룹·브로드캐스트 `Urgent`는 1단계 강등 · **24h `Urgent` 횟수를 수신자에게 표시**(남용은 막기보다 **보이게**).
> ③ **미리보기 규칙** — 무해화 텍스트만 · **이미지·원본 파일명·활성 링크 금지**(FR-S-7/12/14) · 잠금·화면공유·발표 모드에서 내용 숨김 · ★ **최상위 창은 포커스를 훔치지 않는다**(훔치면 타이핑 중 Enter가 팝업 기본 버튼을 누른다 — ADR-0004 "기본 버튼은 취소"와 같은 계열).
> ④ ⚠️ **Linux 소리가 실제 문제** — 표준 인박스 오디오가 없고 **libcanberra는 LGPL(DR-12 위반)** → **D-Bus 알림 데몬에 `sound-name`** 을 넘겨 데몬이 울리게 하고(오디오 스택 미접촉 → NFR-B-5 유지), 없으면 **무음 폴백을 표시**한다.
> ⑤ **수신 확인은 수동 버튼만** — **전달(`Delivered`)/확인(`Acknowledged`) 구분**, ⚠️ **"읽음"은 만들지 않는다**(창이 열린 건 사람의 의사가 아니고 자동 읽음은 감시 채널이 된다). 강제 불가 · 미확인은 **발신자 쪽에만** 표시(압박 방지) · ack는 무음 · 제어 스트림.
> ⑥ ★ **대체 알림은 "수신자가 자기 채널로"** 보낸다 — 발신자가 남의 이메일로 보내는 구조는 **연락처 수집·동의 주체·악용**이 전부 어긋난다. **외부 채널에도 봉투만**(기본 L0 = *"긴급 1건 도착"* · 내용은 옵트인 + **"E2E 아님" 고지**). **Webhook 하나로 Slack·Discord·Teams·Telegram·자체 서버 커버** — 개별 SDK는 넣지 않는다(크기·API 변경 유지보수).
> ⑦ 🔴 **신설 위험 R-13 증폭 공격** — 무인증 상대의 `Urgent` 한 발이 **내 폰·메일 폭격**이 되고 **앱을 꺼도 계속된다**(피해가 앱 밖으로 나가는 첫 사례) → **4중 게이트**(SAS 검증 상대 · 부재 · 미확인 · 상한) + 묶음 발송 + 기본 비활성. **R-14** = **TLS 첫 도입**의 크기 위험 → **SP-2 실측(M0-2b)이 FR-S-43의 v1 포함 여부를 가른다**.
> ⑧ **감수 명시** — **인터넷으로 나가는 코드 경로가 처음 생긴다**(LAN 전용이라는 성격이 옵션 하나만큼 흐려진다 · **FR-S-20에 예외 1건** 명시) · **N-1~N-4 프로토콜 자리는 M2-4와 같은 슬라이스에**(등급 1바이트·ack 제어 타입·기록 상태 필드·`ActionKind` 5종 — 나중이면 포맷 변경).

> ④ 🔴 **신설 위험 R-12 — 키 파일 복제**(포터블 폴더 복사·골든 이미지·VM 클론·동기화 폴더). **모든 계층이 "설계대로" 동작하면서 결과만 틀린다**(두 PC가 한 노드로 병합 · 양쪽 다 TOFU/SAS 통과 · **복제본이 원본 기록을 연다**). 제안 = **U-P1 발견 패킷 `instance` 난수 + U-P2 자기 `PeerId` 세션 거부** — **탐지이지 방지가 아님**을 명시. ⚠️ **발견 와이어 포맷 확정 전에 답해야 필드 추가가 공짜**([D-22](TODO.md)).
> ⑤ 🔴 **안전번호 자릿수 부족 발견**(M2-2 구현 검토 중) — 12자리 ≈ **40비트**인데 MITM은 **양쪽에 다른 키**를 보여주며 쌍을 맞추면 되므로 **생일 공격에 2²⁰**(노트북 수 분). Signal 60자리 기준 상향 필요([M2-2b](TODO.md) · Q-21-5).

> ⑦ **v1→v2 승격 시 `UserId` 값이 바뀐다**는 점을 명시 — V1-1이 사 준 것은 *"마이그레이션 없음"* 이 아니라 **레코드 병합 → 식별자 한 컬럼 remap**으로의 **등급 하향**이다.

> 도출 4건 — ⓐ **국내에 제로 컨피그 P2P LAN 메신저가 없다**(일본산 IP Messenger가 20년째 대체 중)
> ⓑ 현대적 크로스플랫폼은 Squiggle(.NET)·LocalSend(Flutter) 둘뿐이고 **둘 다 런타임 의존 = 크기·메모리 축이 비어 있다**
> ⓒ **제로 컨피그와 암호화는 정면 충돌**(신뢰 앵커 부재 → MITM) — TOFU/지문/공유비밀 3안 비교
> ⓓ 기업 무선망의 **클라이언트 격리·VLAN이 멀티캐스트를 차단** → 다단 발견은 선택이 아닌 필수
> ③ **결정 14건 확정**([10 DR-1~14](10-decision-record.md)) — 사용자 확정 사항 반영:
> 크로스플랫폼 4타깃(Win x64/**ARM64**·mac·Linux) · 설치본+포터블 2채널 · 최소 크기/메모리/누수0 예산 게이트 ·
> **전 렌더링 자체 구현 커스텀 컨트롤**(프레임워크 UI 금지) · **E2E 암호화 필수** ·
> **전송 2모드 추상화**(서버리스 기본 + 릴레이 선택, v1은 서버리스만) · 릴레이 서버는 별도 저장소 **`nexa-beepd`** ·
> 라이선스 **PolyForm NC**(nexa-dir2 동일, 의존성 퍼미시브 온리) · 발견 사용자 **그룹 관리 + 그룹 전송**
> ④ **[04 안전 송수신](04-safe-transfer.md)** — 페이로드 3종(Text/Image/File) + **수신 파일 무해화 4단계 게이트**
> (협상→`.beepq` 격리[헤더 봉인·콘텐츠주소 파일명·실행권한 없음]→검사[AMSI·매직 대조]→승인 실체화).
> 업계 표준 5종 정리(MotW·Gatekeeper 격리·AMSI·CDR·디팽잉) — **헤더 변조 단독은 불충분**함을 명시(DR-13)
> ⑤ **[06 네트워크 스택 L1~L4](06-network-stack.md)** — 계층별 역할·인터페이스별 바인딩·**발견 폴백 사다리 S1~S6**·
> **능력 등급 T0~T2**(L2 원시 소켓은 권한/드라이버 필요 → DR-1·DR-4와 충돌하므로 **선택 기능**)·실측 항목 E-1~E-9 (DR-14)
> [journal/2026-08-08.md](journal/2026-08-08.md).
