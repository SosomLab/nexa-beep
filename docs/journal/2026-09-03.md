## (Win) ★ 목록 증발 — 세션 종료 시 핀·이력 상대 행 제거 결함(`528453c`) — 1차

### 발단
사용자 실기(Win · 3신원 · mac/linux 상대 오프라인): "접속이 안 돼도 이력이 있으면 목록에 떠야 하는데
직전에 목록이 비어 보였고, 재시작하니 다시 뜬다 → 여러 번 시도하다 목록에서 제거하는 로직이 있는지 점검"
(상태바 = `연결 실패(kiros33@mac): Unreachable · 서버 사다리 NotFound`).

### 점검 — 목록 행이 사라지는 경로 전수
목록 행 = `table.list()`(발견) ∪ `extra_peers`(비발견 시드) ∪ `server_peers`(roster) → `list.filter.*` 3칩 AND.
행을 없애는 경로는 넷뿐이었다.
1. `forget_peer` — 사용자 "목록에서 삭제". 명시 조작이라 무관.
2. roster `Down` — `server_peers`만 뺀다. 핀·시드에는 손대지 않는다. 무관.
3. 발견 이탈 — `sweep`(60s 만료)은 "핀·대화·수동 주소 = 오프라인 행으로 강등 유지"를 이미 지켰다.
   **goodbye(`Vanished`)는 그 시드를 타지 않았다**(부팅 시드가 이미 있어 우연히 버텼을 뿐).
4. ★**`AppEvent::Closed`(세션 종료)** — 제거 조건이 **"수동 주소 없음 ∧ 발견 테이블 없음"** 둘뿐. 핀·이력을
   보지 않는다. 08-13 "인바운드 전용 스쳐간 상대 유령 방지"로 넣은 분기가, 그 뒤 생긴 부팅 핀 시드
   (`restore_cached_profiles`)·서버 사다리·"비발견 상대 목록 유지" 확정과 어긋난 채 남아 있었다.

### 재현 순서(코드로 확정 · 실기 미대행)
상대가 앱을 종료 → **goodbye 비컨이 먼저** 와 `table`에서 빠짐 → TCP 종료가 `Closed`로 뒤따름 → 수동 주소 0
∧ 테이블 0 → `extra_peers.remove` → 행 소멸. 재시작하면 핀 전부를 다시 시드하므로 "재시작 후엔 뜬다".
순서가 반대(Closed가 먼저)면 테이블이 아직 있어 살아남고, 이후 sweep이 강등 시드 → 증상이 **간헐**인 이유.
서버 사다리로 성립했던 세션(테이블에 애초에 없음)이 끊겨도 같은 조건으로 즉시 사라진다.
`ConnectFailed`(스크린샷의 실패 자체)는 행을 지우지 않는다 — 여러 번 실패해도 그 경로로는 안 빠진다.
