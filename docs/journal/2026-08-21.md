### ① dir_writable PID 프로브 경합 (`ea96094` · CI red의 범인)

- 프로브 파일명이 `.probe.{pid}` 하나 → **같은 프로세스의 병렬 테스트 스레드가
  한 파일을 공유**. Windows에서 한쪽 remove가 만든 delete-pending 순간에 다른 쪽
  `File::create`가 ACCESS_DENIED → **false 오판** → `data_dir()`가 그 호출만
  %APPDATA% 폴백으로 튐 → `save_partial`/`load_partial`이 **다른 루트**를 봄.
- 제품에서도 다중 스레드 `data_dir()` 호출 시 같은 순간 이동 가능(격리물이 순간
  다른 루트로 — 신원 durable 계열 구멍).
- 수정 = AtomicU64 시퀀스 접미(호출마다 유일) · 회귀 = 8스레드×50회 전부 true.

### ② 클립보드 use-after-free (`35a6160` · ★T-flake 08-20 2회 관측의 정체)

- 전량 테스트가 간헐 nbeep-plat **0xc0000374(STATUS_HEAP_CORRUPTION)**·드물게 AV로
  중도 사망. 60개 중 31개 시점 abort = T-flake의 "정확히 29개 모자람"과 일치.
- **재현 확립이 반이었다**: 직접 exe 루프는 희귀(2/171) · **cargo 문맥 4/20**.
  모듈 이분 탐색: 전체 → 초반 5모듈(3/20) → autostart+clipboard(5/25) →
  **clipboard 단독 2/25**.
- 원인 = **`OpenClipboard(NULL)`의 거짓 성공**: 내부 오픈 상태를 "연 창 핸들"로
  대조하는데 NULL==NULL → 둘째 호출자(스레드·프로세스 불문)도 성공 → 한쪽
  `EmptyClipboard`가 상대가 `GlobalLock` 중인 HGLOBAL을 해제 = use-after-free.
  **제품 실버그**(이미지 워커 x UI 복사 · 3-신원 다중 인스턴스 간).
- 수정 3겹 = **호출마다 메시지 전용 창(진짜 HWND)으로 열기**(둘째 = 정직한 실패) ·
  프로세스 내 뮤텍스 직렬화 · `get_text` 널 스캔 GlobalSize 상한.
- 왕복 테스트 환경 플레이크 2종 skip 흡수(set 직후 클립보드 히스토리 서비스 잠금
  = 300회 루프 실측 2% · 타 프로세스 덮어씀). 왕복 검증은 조용한 CI가 지킨다.
- **실측 = 수정 전 4/20·2/25 크래시 → 수정 후 0/70**(clipboard 40 + 전체 30).
