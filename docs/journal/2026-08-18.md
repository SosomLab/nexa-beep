## 지문 기반 검증 흐름 — /fingerprint + /verify 직접 검증 (사용자 요청)

SAS(안전 번호) 카드+버튼 대신 **키 지문 비교**로 검증하도록 사용자가 흐름을
바꿨다. 새 흐름 = **① /fingerprint 로 지문 확인 → ② 전화·대면 등 다른 채널로
대조 → ③ /verify 로 직접 대조 완료**.

- **/fingerprint 신설**: 내·상대 키 지문을 대화 안내로 출력("키 지문 — 나: … ·
  상대(이름): … — 다른 채널로 맞춘 뒤 /verify"). 별칭 `fp`/`fpr`/`지문값`
  (Verify의 별칭 `지문`과 구분 — 파싱 회귀로 박제).
- **/verify = 직접 검증**: 종전엔 SAS 카드를 열어 '대조 완료' 버튼을 누르게
  했는데(창+버튼), 이제 **바로** `verify_peer`(trust.verify → 목록·카드 파란 실
  배지 즉시 갱신). 사람이 먼저 지문을 다른 채널로 맞춘 뒤 부르는 전제(SAS의
  "통로 안 문답 금지" 원칙은 지문 비교가 대신 진다). 이미 검증됨/1:1 아님 분기
  유지. 카드의 '대조 완료' 버튼도 그대로(두 진입점 공존).
- 안내 문구(SuggestVerify·CmdHelpVerify·help_text)를 새 흐름으로 갱신.

★ 참고 — /fingerprint 는 짧은 지문(`peer.short()` 8-hex)을 쓴다(카드 "키 지문"과
같은 값). 더 긴 지문은 후속(원한다면 전체 키 hex 출력 옵션).
