### ② A-1 — beep 실측: `settings.cfg`만이 아니었다

clip은 *"`profile.sec`·`server.pin`·`trust.seg`·`keys.seg`가 664인데 `write_atomic`을 타는지는 beep이 확인"* 이라 했다.
확인 결과 **하나도 안 탄다** — 파일마다 temp+rename을 손으로 짰고(`trustfile`·`groupfile`·`keytable`·`app.rs` 기록/대기/그룹 기록),
`profile.sec`는 `fs::write` 직접(**비원자**), `server.pin`은 `nbeep-relay::pinfile`이 `fs::write`. 이 PC 실측(mac umask 022):

| 폴더 | 결과 |
|---|---|
| `~/.nexa-beep-multi/A/data` · `B/data` | `identity.key`만 600 · `groups.seg`·`keys.seg`·`server.pin`·`settings.cfg`·`trust.seg`·`profile.sec`·`history/*.seg` **전부 644** |
| `~/Library/Application Support/nexa-beep`(설치본) | 동일 — `identity.key` 600 · 나머지 644 |

위험 판정: 내용은 AEAD 봉인(신원 키 파생)이라 노출은 **암호문**에 그친다. 그러나 Linux 664는 **같은 그룹 계정의 쓰기 = 훼손·삭제**를
허용하고(fail-closed라 결과는 기록·핀 소실), **`server.pin`은 평문**이라 훼손 = 서버 바꿔치기(핀 불일치 모달은 *바뀐 뒤*에 뜬다).
크기·갱신 시각 노출도 남는다. → **한 벌로 정리**:

- **`nexa-conf`**: `write_atomic` temp를 `OpenOptions::mode(0o600)`(rename이 모드를 나른다) · `Store::open`이 기존 파일을 0600으로 죈다(`tighten` — clip은 안 넣었다 · beep은 부팅마다 idempotent).
- **`nbeep_store::privfile` 신설**: `write_atomic(path, bytes)`(0600 · sync_all · rename · 실패 시 temp 제거 · 부모 생성) · `tighten` · `tighten_data_dir`(폴더 바로 아래 `*.seg|sec|pin|key` + `history/`·`pending/`의 `*.seg` — 격리물·이미지 캐시는 목록 밖 = 불변). `trustfile`·`groupfile` 인라인 블록 교체(−20줄) · `keytable` · `app.rs` 봉인 쓰기 4곳(`profile.sec` 원자화 포함) · `run()` 부팅 1회 스윕.
- **`nbeep-relay::pinfile::store`**: 의존 추가 없이 인라인 0600(nbeep-store를 끌면 clip 사본이 갈라진다 — B-3 정신).
- Windows = 전부 no-op(프로필 ACL이 같은 역할). `.locked` 보관본(`groups.seg.locked`)은 확장자가 달라 스윕 밖 — 옛 잠긴 세그먼트라 그대로 둔다.

### ⑤ 질문 2 — beepd "일정 시간 이상 연결 안 되는 대상 제외" 기준 → [41 §3-2](../41-beepd-ops-guide.md) 신설

결론: **서버에 시간 기준 명부가 없다.** 대상 = 살아 있는 TCP 제어 연결. 연결 죽음 = 즉시 회수(RID·토큰·채널·공개 목록·`PeerDown`).

| 단계 | 기준 |
|---|---|
| 미등록 | 10s 안에 `Register` 없으면 절단(`HANDSHAKE_TIMEOUT`) |
| 등록 후 유휴 | **앱 계층 타임아웃 없음** — 클라 `Ping` 20s는 NAT 유지용 · 서버는 `Pong`만(수신 시각 미기록) |
| 죽음 감지 | **TCP keepalive**(`TcpLink::new` — 10s/5s/재시도 3 = Linux·mac ≈25s · Win ≈1분) + 쓰기 30s → `Err` → 스레드 종료 |
| 느린 소비자 | 큐 8MiB 초과 = kill |
| 재접속 잔재 | `Register` 최신 우선 덮어쓰기 — 죽어가는 옛 연결이 자리 못 막음 |
| 감지 전 창 | ≈25s 동안 죽은 conn에 `Open` = `status 0`+큐 적재 → 감지 시 `ChClosed` · 클라 사다리 12s 상한으로 먼저 포기 |

유휴 타임아웃을 **추가하지 않은 이유**도 적었다 — keepalive가 커널에서 같은 일을 더 정확히 한다(추정 금지). 필요하면 `Ping` 수신 시각 필드 1개 · 와이어 무변경.
