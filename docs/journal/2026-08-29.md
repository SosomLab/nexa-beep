## (Linux) ★ 설치본(.deb) 런처가 InMemory 데모를 띄우던 결함 — `Exec=nexa-beep --window` → 무인자

### 증상 (사용자 보고 · v0.2.9 .deb 설치)

앱 메뉴에서 실행하니 목록에 **7명**(`beep-4ccc8f5b`… 전부 온라인 초록 점)이 뜨는데, 같은 PC에서 `relaunch.sh`로

"relaunch.sh는 정상인데 설치본만 잘못 실행된다."

### 실측 → 원인

| 확인 | 결과 |
|---|---|
| `pgrep -af nexa-beep` | `/usr/bin/nexa-beep --window` — **`--live` 없음** |
| `/usr/share/applications/nexa-beep.desktop` | `Exec=nexa-beep --window` |
| `main.rs:178~` | `--window` 단독 = **InMemory 데모(에코 봇 · 네트워크 없음)** · 실물은 무인자 또는 `--window --live` |
| `--discover-probe 6` (데모 실행 중) | LAN 광고 **0건** — 7명은 전부 가짜 에코 봇 |
| `--whoami` | `99fb676e` · data = `~/.config/nexa-beep`(M5-4f 폴백 정상 · `/usr/bin` root) |

08-13 "무인자 = 창+실물"로 의미가 확정될 때 **런처 인자는 갱신되지 않았다** — Windows NSIS는 `--window --live`(정상),
mac 번들·choco·winget은 인자 없음(정상), **Linux `.desktop`과 brew 포터블 caveats 2곳만 `--window` 잔존**.
v0.2.2~v0.2.9 Linux .deb 전부 해당(사용자가 첫 실기라 이제 발각). 서버 "Testing…" 표시는 별건 —
설정 `net.server.mode=managed`·`net.server.test=run`이 첫 실행 settings.cfg에 있었다(데모와 무관 · 사용자 조작 여부 미확인).
