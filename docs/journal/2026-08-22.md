## ① X-UDP-e 원격 사다리 — `connect_via`/`accept_via` (nbeep-relay)

- **여는 쪽** `connect_via`: 랑데부(에폭 RID 오늘→어제→내일) → **홀펀칭 시도** →
  실패 = **릴레이 폴백**. 각 단이 독립 핸드셰이크라 단 사이 오염이 없다.
  인증 키 ≠ 지정 지문 = `WrongPeer` 폐기(RID는 힌트 — 근거는 암호학적 증거).
- **받는 쪽** `accept_via`: 펀치를 병행하며 **첫 프레임이 온 링크**로 종단 수락 —
  여는 쪽이 어느 단을 골랐든 따라간다(`PrefixedLink`가 첫 프레임을 재생).
- **구조 변경 = 지연 수락** — 액터의 자동 Accept를 소비자 호출로 미뤘다. 이유:
  수락 **전에** UDP 프로브를 마쳐야 서버 OpenResult에 내 신선한 관측 엔드포인트가
  실린다(프로토콜 순서가 자연히 보장 — Open 전 프로브/수락 전 프로브). **펀치
  소켓 = 관측 소켓, 시도마다 신선하게** — 소켓 공유의 recv 경합(두 링크가 서로의
  데이터그램을 훔침)을 원천 차단. 서버는 미수락 CloseCh를 열기 거절(2)로 즉시
  알린다(여는 쪽 타임아웃 대기 제거).
- 부수: `pinfile`(서버 TOFU 핀 영속 — v1 텍스트·원자적 교체·손상 줄 = 핀 부재) ·
  `parse_peer_hex`/`peer_hex`(지문 교환 단위 = 64hex 전체 — 짧은 지문으론 키 복원
  불가) · `incoming_rx` Mutex화(수락 스레드 공유 — Receiver !Sync 실측).
- 검증: 사다리 e2e 2종 — 루프백 = **UDP 단**(양쪽 `taken` 일치) · 받는 쪽 무펀치 =
  관측 부재 → 여는 쪽 조용히 **릴레이 단**.

## ② X-2c CLI Managed — `--server`·`--chat-connect-via`·`/connect <지문>` (P0+P1+P2)

- **P0 신원 영속**: `--identity <파일>`(기본 `data/identity.key` — GUI와 같은 노드
  DR-18). 서버 사용 = 영속 강제(RID·핀이 키에 묶임) · 시작 시 **내 지문 64hex**
  출력. 서버 없인 기존 임시 신원 그대로(3-신원 실기 격리 불변).
- **P1 서버 등록**: `--chat-live --server <주소>` — 핀 규약(`data/server.pin` · 첫
  접속 TOFU 저장 · **불일치 = 접속 중단** + 파일 경로 안내 = 재핀은 사람의 결정) ·
  접속 실패 = LAN만으로 계속(S-2). 인바운드 랑데부 = 기존 **수신 전용 채널** 합류
  (`accept_via` — 08-20 구조 재사용 · 파일 거절·대화 미진입 그대로).
- **P1+P2 발신**: `/connect <64hex지문>`(대기 중) · `--chat-connect-via`(독립 단말)
  — `connect_via` 사다리 → `run_interactive` **무변경 합류**(경로 등급 = 성립 링크
  실주소 → CLI 원격 파일 게이트 곱 판정 그대로).
- 호스트명 서버 주소 = DNS 해석(DDNS 경로 — 정규화 실패 시 폴백).

## ③ 실물 스모크(3프로세스 자동 · 파이프 stdin) — 전 구간 실측

프리페치까지 기존 스택 무변경 동작**(DR-21 — mux·ack·프로필이 사다리 위에서 그대로)
→ 서버 로그 = 봉투만(conn#·rid 앞 4B·ch#). 절차 = [26 §3-7](../26-run-and-manual-test.md).
