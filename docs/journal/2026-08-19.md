## 그룹 초대 유실 실기 연쇄 — "초대 대기" 가시화 + 초대받은 방 자가 수락 (main · `8d37247`·`9924a01`)

**실기(사용자 · 3신원)**: ① 초대받은 구성원에게 수락 버튼이 안 떠 그룹 대화창이
안 생겼다 → 소유자가 대화를 시도하니 버튼이 다시 생겼다 ② 재시작 후 초대받은
A·B에서 그 방이 목록에 아예 안 보였다.

**원인 2겹** —
 1. **첫 초대 전달 실패**: 초대는 세션 성립 시 전달된다(`pending_invites` flush +
    `flush_group_sends` resync). 첫 초대 시점에 세션 미성립(실기 중 상단
    "Network change… reconnecting" = 네트워크 churn)이라 자동 연결이 실패했고,
    백오프 소진 시 `fail_group_sends`가 대기 초대를 폐기했다. 소유자가 대화 =
    세션 성립 = resync 재전달(회복 경로는 살아 있었다 — 계기가 없었을 뿐).
 2. **Invited 방의 유령화**: 종전 설계는 수락 전(Invited) 그룹을 행 미표시
    ("초대는 카드로만" G-4)했는데, 카드는 수신 순간의 일회성 모달이라 **재시작
    후엔 수락할 길이 없었다**(groups.seg에 Invited로 영속돼 있는데 안 보임).

**대응 4종**(가시화 + 자가 치유 + 명시 재전달 + 자가 수락) —
 - **"초대 대기" 표시**(`8d37247` · 사용자 요청): 소유자 구성원 목록에서 미수락
   구성원에 `invite pending` 표기. 수락은 `group_accepts`(uid→수락자)가
   `G::Accept`에서 기록(소유자만 수락 통지를 받는다 — 비소유자 가시화는 roster에
   수락 상태를 실어야 하는 후속).
 - **자가 치유**: 이미 수락한 방의 재초대(resync) 수신 시 Accept를 되보낸다 —
   소유자가 재시작으로 수락 기록(메모리)을 잃어도 세션 성립 시 복원(멱등).
 - **재전달 넛지**: 소유자가 구성원 목록을 열면 미수락·미연결 구성원에 재연결
   시도(백오프 리셋 + 자동 연결 — 성립하면 resync가 초대 재전달). "누가
   들어왔나" 확인 동작 = 복구 계기(저churn · 명시 동작에만).
 - **초대받은 방 자가 수락**(`9924a01`): Invited 그룹도 목록에 표시("초대됨 ·
   클릭하여 수락" 표식) + **클릭 = 수락/거절 모달**(기존 `AlertCtx::GroupInvite`
   재사용). 소유자 재초대 없이도 초대받은 쪽이 언제든 수락에 닿는다.

**실기 확인(사용자)**: "초대 대기" 표시 ✓(구성원 모달 — 미수락 2명 표기 + 재연결
스피너) · 새 방 생성 + 대화 경유 수락 전 사슬 ✓. **703 green** · clippy 0 ·
3신원 재기동. 잔여 = 초대받은 방 클릭 수락 실기 육안(재시작 후 Invited 행).
