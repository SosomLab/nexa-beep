### 2. ★ 함정 — `RUSTFLAGS`가 `.cargo/config.toml`을 이긴다

cargo는 `RUSTFLAGS` 환경변수가 있으면 `target.*.rustflags`를 **합치지 않고 통째로 버린다**. 이 저장소의 CI·릴리스 워크플로는 전부 `RUSTFLAGS: -D warnings`를 두고 있어, config만 고쳤다면 **로컬은 정적·CI 산출물은 동적**이라는 최악의 형태가 됐다(고쳤다고 믿는 동안 계속 깨진 물건이 나간다). → Windows 매트릭스 항목에 `rustflags`를 직접 얹고 잡 `env`로 받게 했다.

**그리고 그 함정이 같은 날 실물로 재현됐다** — `d609607`에서 **cross-build 잡의 `env` 오버라이드만 빠뜨렸고**(test·package에만 넣었다), run `35204594889`의 Win ARM64 잡이 빨강: `FAIL nexa-beep.exe — vcruntime140.dll` + 환경 덤프 `RUSTFLAGS: -D warnings`(덮였다는 증거). `366bcc1`로 수정 → 전 잡 green. **게이트가 없었다면 arm64 산출물만 조용히 깨진 채 나갔다.**

### 4. ★ `Validation-Executable-Error`의 정체 = 진짜 런타임 의존(NFR-B-5 위반)

winget 봇(09-11)이 남긴 것:

```
Executable ...\NexaBeep\nexa-beep.exe  returned exit code: -1073741515
Executable ...\NexaBeep\nbeep-imgdec.exe returned exit code: -1073741515
| C0000135 | STATUS_DLL_NOT_FOUND | Possibly due to a missing dependency.
  (The most common dependency is Microsoft.VCRedist.2015+.x64) |
```

처음엔 **검증기 VM 환경 문제로 읽었다**(같은 로그 머리에 검증기 자신의 `System.Management`/`wminet_utils.dll` 타입 초기화 예외가 있고, 같은 바이너리를 담은 포터블은 같은 날 수동 verify로 병합됐기 때문). **틀렸다.** 릴리스 자산을 직접 뜯어 임포트 테이블을 확인했다:

```
nexa-beep.exe     -> vcruntime140.dll, api-ms-win-crt-{heap,locale,math,runtime,stdio}-l1-1-0.dll
nbeep-imgdec.exe  -> vcruntime140.dll, api-ms-win-crt-*
nexa-beepd.exe    -> vcruntime140.dll, api-ms-win-crt-*      (beepd-v0.2.5 자산)
```

- `api-ms-win-crt-*`(UCRT)는 Windows 10+ **인박스**라 문제없다.
- **`vcruntime140.dll`은 인박스가 아니다** — VC++ 2015+ 재배포 패키지가 깔린 PC에만 있다. 원인은 `.cargo/config.toml`에 `crt-static`이 없어 **MSVC 타깃 기본값(동적 CRT)** 으로 링크되는 것. musl 정적 전환(08-22)은 **Linux(beepd) 타깃에만** 걸어 뒀다.

따라서:
- winget 자동 검증은 **참 양성**이다. 깨끗한 Windows에서 실제로 실행되지 않는다.
- **이미 병합·게시된 `SosomLab.NexaBeep.Portable`도 VCRedist 없는 PC에서는 실행 불가**다(모더레이터 수동 verify는 VCRedist가 있는 기계에서 통과한 것).
- **[05 NFR-B-5] "외부 런타임 의존 0 · OS 인박스 라이브러리만"이 Windows에서 깨져 있었다.** 그 항목의 검증 수단으로 적혀 있던 **"임포트/링크 테이블 화이트리스트 CI 검사"가 구현된 적이 없어서** 여기까지 온 것이다 — 불변식은 선언만으로 지켜지지 않는다.

처방 후보(미결정 · **M5-4g** 등재):
- ⓐ `-C target-feature=+crt-static`(MSVC 4타깃) → 의존 소멸 · 산출물 소폭 증가(예산 1.7/10MB라 여유) · **NFR-B-5 원복 = 권고**
- ⓑ winget `Dependencies`·nuspec `<dependencies>`에 VCRedist 선언 → 설치는 되지만 **"런타임 의존 0"을 포기**하는 선택 · 포터블 zip(DR-4)은 여전히 못 고침
- 어느 쪽이든 **NFR-B-5 CI 검사(임포트 화이트리스트)** 를 같이 붙여야 재발이 없다.
