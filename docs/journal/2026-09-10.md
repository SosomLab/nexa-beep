## (Win · main) 보안 프로그램 탐지 가능성 검토 + mac 이웃 테이블 `arp -an` 스폰 폐지(사용자 요청 "네트워크 기능에 의해 보안 프로그램에서 탐지되는 경우가 있는지 검토")

**결론** — 네트워크 동작 자체는 IDS·EDR 기준으로 얌전하다(스캔·원시 소켓·HTTP·텔레메트리 없음 · 재연결 4회 후 중단). 문제는 개별 요소가 아니라 **조합**이다: *무서명 exe + HKCU Run 자동 실행(기본 on) + 고정 포트 리스너(47200) + 고정 호스트 아웃바운드(릴레이) + AMSI 동적 로드*가 EDR 행위 점수에서 RAT와 같은 모양을 띤다. 조합을 푸는 가장 큰 지렛대는 **코드 서명(M5-4a)** 이고, 나머지는 위생 개선이다. 이 검토는 **코드 전수 조사 기반 판단이지 실측이 아니다** — 실제 탐지 여부는 Defender·Snort/Suricata 실기로 확인해야 한다(R-22 ②).

**전수 조사 범위**(코드 기준 · `nbeep-net`·`nbeep-relay`·`nexa-beepd`·`nbeep-plat`·`packaging/`·`.github/`) — 발견 와이어(멀티캐스트 `239.255.77.77`·`ff02::0beb`·브로드캐스트 255.255.255.255·**IF별 지향 브로드캐스트** · UDP 47100 · 800ms) · S4 유니캐스트(ARP 이웃 · 서브넷 안 · 상한 64 · 16주기≈12.8s) · S5 미구현(X-8 ⏸) · 원시 소켓 = mac PF_ROUTE·Linux NETLINK 라우팅 알림뿐(pcap·AF_PACKET 0) · TCP 47200(폴백 임시 포트) · 재연결 백오프 `[5,15,60,300]s` 후 중단 · 릴레이 TCP+UDP 47300 Noise 평문(TLS 없음 · 기본 Unmanaged · Test+핀 통과 전 미접속 · Ping 20s) · 홀펀칭 = 관측 프로브 1발 + SYN ≤10발/3s 단일 엔드포인트 · HTTP·업데이트 확인·텔레메트리 0 · DNS = 수동 주소·릴레이 호스트 2곳 · 스폰 = mac `arp -an`(S4마다)·imgdec·open_path(로그 폴더만)·mac/Linux 알림·테마 · Win FFI = iphlpapi 3종·advapi32 Run·Shell_NotifyIcon·클립보드(온디맨드)·Toolhelp(부모 셸 판별)·**AMSI `LoadLibraryW`+`GetProcAddress`+`transmute`** · MotW는 쓰기만(ZoneId=3) · 훅(`SetWindowsHookEx`) 0 · 방화벽 규칙 조작 0(NSIS도) · 패커 0 · 수신 파일 실행 0(0644 고정) · netmon 경고선 = disco TX 25pps·RX 100pps·연결 30/min · 실측 유휴 3.7~10pps.

**권고 2·3번의 목적·효용·필요성(사용자 질문) — 정정 포함**
- **2번(mac arp 스폰 제거)**: 기능상 필요 없음 · 효용 확실(exec 이벤트 자체가 사라진다) · 원래 코드 주석 "복잡도 대비 이득 없음"은 EDR 텔레메트리 관점이 빠진 판단 · 대상 사용자가 기업 관리 mac이면 가치 있음 → **구현**(저우선이지만 비용이 작아 지금).
- **3번(S4 버스트 → 틱 분산)**: 앞선 답변의 "총량 무변경으로 형태가 사라진다"는 **과했다**. IDS sweep 판정은 마이크로초 버스트가 아니라 **관측 창(수십 초) 안의 고유 목적지 호스트 수**를 세므로 12.8초에 펼쳐도 판정이 바뀐다는 보장이 없고, 더 강한 신호인 ICMP port unreachable 64건도 줄지 않는다. 호스트 EDR·Defender 방화벽은 페이싱에 무관심. 효과가 있을 방향은 **대상 수 축소**(S1~S3로 최근 발견됐으면 S4 주기 16→64주기 적응형)인데 혼합망 발견 지연을 늘리는 설계 변경이라 결정 필요 → **보류 · 실측 후 재검토**(추정 금지·실측 필수).
