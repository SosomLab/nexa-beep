### 발단
08-29 Linux 11차가 L-1을 "3-OS 자체 구현 통일"로 확정했고 mac 몫(`NSPasteboard`)만 남아 있었다.
종전 mac 경로 = `pbcopy`/`pbpaste` 스폰(텍스트) · `osascript`가 PNG를 **임시 파일**에 쓰고 되읽기(이미지 —
사용자 보고 "안 됨"). 셋 다 프로세스 스폰 + 임시 파일 왕복이라 DR-5(런타임 의존 0)·DR-4(임시 폴더 규약)
정신에 어긋났다.

### 구현 — `nbeep-plat::macclip`(의존 신규 0)
- **`NSPasteboard` objc2 직접** — keytap·트레이·알림과 **같은 판**(objc2 0.5 / app-kit 0.2 · Cargo.lock 신규 0).
  feature만 추가(`NSPasteboard` · foundation `NSData`).
- 텍스트 = `stringForType(NSPasteboardTypeString)` / `clearContents`+`setString:forType:`(짝 필수).
- 이미지 = **PNG 타입 직접** → 없으면 TIFF를 AppKit `NSBitmapImageRep`으로 PNG 재포장 → 서명 확인 후에만 반환.
  R-5("본체는 이미지 코덱을 링크하지 않는다")는 **우리 코드에 디코더가 없다**는 뜻 — AppKit은 이미 프로세스에
  링크된 OS 코드라 새 공격면이 아니다. 상한 64MiB(Linux와 동일).
- ★ **프로세스 안 직렬화**(실측) — 테스트 병렬 실행에서 스레드 둘이 동시에 `clearContents`/`setString`을
  부르자 AppKit이 **SIGABRT**(각각은 통과 · 함께 돌리면 즉사). Windows 경로의 뮤텍스와 같은 처방(뮤텍스 1개 +
  호출마다 `autoreleasepool`). 3회 반복 통과.
- `clipboard.rs` 비-Windows 모듈 = mac이면 `macclip` · Linux면 `linuxclip` · 도구 스폰은 그 밖의 unix 폴백.
  `read_from`/`write_to`/`osascript` 경로는 mac에서 컴파일 제외(dead code 0).

설치본 설정 `ui.theme`가 현재 `light`다. 설정 › 모양 › 테마 = **시스템**으로 바꾼 뒤 아래 중 하나:
