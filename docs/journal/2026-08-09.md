## M4 실물화 — macOS 표식·조립 배선·파일 전송 종단 (feat/m4-marks · "다음 진행" 3회)

도메인만 있던 무해화가 **실제로 파일을 받아 격리하는 경로**가 됐다. 순서:
표식 어댑터 → 조립 지점 배선(데모) → 전송 와이어 → 세션 연동. 전부 **실기 실측 동반**.

### ① macOS 격리 표식 실물 어댑터(plat)

`quarantine::apply_quarantine_mark` — `libc::setxattr`로 `com.apple.quarantine` 직접 기록
(`0081;<hex 시각>;Nexa Beep;` — Gatekeeper·XProtect 발동). 비-macOS는 `Ok(false)`로
**미지원을 명시**(§5 "조용히 넘어가지 않는다"). **실측 2중** — 테스트가 `getxattr`로 재독 +
OS 도구 `xattr -p` 교차 확인. 수동 도구 `--example qmark` 동봉.
⏸ Windows MotW(IAttachmentExecute→Zone.Identifier ADS)는 실기 필요.

### ② 조립 지점 배선 + `--quarantine-demo`(bin)

포트에 실물을 꽂았다(DR-21): `HashPort` ← `nbeep-crypto::sha256`(sha2 = snow가 이미 끄는
의존 · **트리 증가 0**) · `MarkPort` ← plat 어댑터. 데모 CLI가 판정→봉인→격리→상태 기계→
실체화→표식을 한 번에 관측한다(⚠️ **데모 한정 자동 승인** — 제품 경로엔 없다).
실측: `report.pdf`(MZ 위장) → **Executable + 형식 불일치 경고** · 실체화본 xattr 부착 확인.

### ③ 전송 와이어 + 수신 조립기(core · [04] 협상 게이트)

`StreamId::File`(=2) 신설(대화를 막지 않는 별도 스트림) · `XferMsg` 6종 ·
`XferInbox`: **수락 전 청크 = 프로토콜 위반** · 연속 오프셋 강제 · 선언 크기 초과 거부 ·
위반 시 해당 전송 **즉시 폐기**(부분물 잔존 금지) · 완료 시 크기 대조.
해시 대조는 조립 지점 몫(core는 크립토를 모른다) → 통과분만 `.beepq`로.

### ④ 세션 연동 + ★ 수신측 용량 제약(사용자 요청)

CLI `/send`·`/accept`·`/reject`. **크기 상한은 발신 상수가 아니라 수신측 정책**으로 뒤집었다
— `XferInbox::with_max_file`, 초과 오퍼는 거부하며 **거절 와이어에 자기 상한을 공지**
(`Reject.limit` 8B 추가)해 발신자가 재시도를 판단한다. CLI `--xfer-limit-mib`.

### ★ 실측이 잡은 버그 — 청크 64KiB는 애초에 나갈 수 없었다

128KiB 전송이 **첫 청크에서 세션 끊김**. 원인: Noise 프레임 상한 65535에 AEAD 태그 16 +
mux/xfer 헤더 27이 더해져 64KiB 청크가 **구조적으로 초과**. 32KiB로 낮춰 해결.
*"보냈다는 닿았다가 아니다"* 가 또 맞았다 — 단위 테스트는 전부 통과하고 있었다.

## M4-1 무해화 도메인 완성 — 방치 브랜치 회수 + 슬라이스 2~4b (feat/m4-quarantine)

"다음 진행" 지시 2회로 **M4(전송·무해화)를 재개**했다. 슬라이스 1(.beepq 코덱)이 8커밋
전 main 기준으로 방치돼 있던 것("main에 없다" — STATUS 명시)을 리베이스로 회수(충돌 0)
하고, ADR-0004의 나머지 도메인을 수직 슬라이스 4개로 쌓았다. **무해화 게이트의 도메인
전 구간이 코드**가 됐다 — 남은 것은 OS 표식 실물 어댑터와 전송 경로 연동(M4-2)뿐.

### 슬라이스 2 — 위험 등급 판정(risk.rs · [11 §3])

`classify(이름, 선두 바이트)` = **max(확장자 등급, 매직 등급)**(fail-closed).
- 설계 선택: 실행형 확장자 표를 **전 플랫폼 합집합**으로 — 내 OS에서 안 도는 `.sh`도
  포워드되면 다른 OS에서 돈다.
- 매직 없는 형식(lnk/url/scf/desktop)은 **확장자가 유일한 방어선**(ADR 명시 그대로) ·
  이름 속인 실행 파일은 매직(MZ/ELF/Mach-O 4형/셔뱅)이 잡아 **불일치 경고** 동반.
- ISO 9660은 선두가 아니라 **오프셋 0x8001 `CD001`** — MotW 우회 경로라 능동 문서 등급.
- Unknown 매직은 경고에서 제외(매직 없는 형식이 흔해 소음이 된다).

### 슬라이스 3 — 격리 상태 기계(state.rs · [11 §4])

8상태 + `step()` 순수 전이 함수. **불변식이 타입/표로 고정**됐다:
해시 불일치 = 즉시 Discarded(부분 수신물 금지) · 검사 실패 = `Inspected{Unavailable}`
(`friction_raised` — Failed 상태 자체가 없다) · **승인은 검사 후에만**(자동/생략 승인
경로가 존재하지 않음) · 실체화 실패 = Quarantined 롤백 · 잘못된 전이 전부 = 상태 유지 +
오류(NFR-S-4) · 종결 4상태 × 전 사건 거부 **전수 테스트**.

### 슬라이스 4a — 파일명 정규화(sanitize.rs · [11 §4]-2)

수신 파일명 = 공격 벡터: **RLO 스푸핑**(`invoice_[RLO]txt.exe` → exe로 정체 노출) ·
bidi/0폭/BOM 제거 · 경로/ADS(`:`) 구분자 치환 · Windows 예약 장치명(`CON.txt` 포함) ·
끝 점/공백 · 120자 확장자 보존 절단. 순수 함수 — 원본 바이트는 `Meta.orig_name` 감사 보존.

### 슬라이스 4b — 격리 저장소 + 포트(store.rs · [11 §4~5])

- **포트 2종**(DR-21): `HashPort`(실물 = `nbeep-crypto::sha256` — sha2는 snow가 이미
  끄는 의존이라 **트리 증가 0**) · `MarkPort`(MotW/quarantine — 실물 어댑터는 플랫폼
  슬라이스 · `NoopMark`는 `Unsupported`를 **명시** — §5 "조용히 넘어가지 않는다").
- `QuarantineDir`: save(해시 헥사 이름·임시→fsync→원자 rename) · list · **materialize** —
  재검증(불일치=무기록) → 정규화 이름 → 덮어쓰기 금지(뒤 번호) → 실행 비트 미부여(0o644)
  → rename → **표식은 rename 직후**(§5 — 먼저면 유실) → `.beepq` 보존.

## 아이콘 규약·툴바 UX·도움말 배지·더블클릭 (feat/m3-toolbar-svg · 사용자 대화형 반복)

### 아이콘 소스 규약 확정(사용자)

- **SVG = 모양만 참조, 색은 테마 기준색** — 다크=밝은 회색·라이트=아주 어두운 회색(`Theme::text`).
- **PNG = 원본 색 그대로**(기존 `ToolIcon::Image`).
- 구현: SVG를 `rsvg-convert`로 96×96 사전 래스터 → **1채널 알파 마스크 임베드**
  (`icons::REFRESH_ALPHA` — 런타임 SVG 파서 의존 0) · `ToolIcon::Mask` + gfx
  `IconImage::from_alpha_tinted` · 틴트는 항목별 색 키 캐시(`TintSlot`). 새로고침 버튼을
  사용자 제공 SVG(회전 화살표 2개)로 교체(폴리라인 글리프 폐기).

### 툴바 상호작용 UX(사용자: "세련된 눌림")

hover = 기준색 10% 반투명 배경(다크/라이트 공용) + **SVG 선색 accent 전환** ·
pressed = 20% 배경 + **아이콘 1px 내림**. 기본 크기 32→**24**(설정 옵션 16/24/32/64
오름차순 · 기본값은 `RADIO_DEFAULTS` 분리) · 메인 창 기본 **460×640**(스크린샷 기준).

### hot-swap 원칙(사용자 지시 — 영구 규약)

모든 설정은 특별한 사유 없는 한 **재시작 없이 즉시 적용**. 점검 결과 현 키 전부
(테마·언어·툴바·타입어헤드 4·글꼴)가 `apply_settings` 단일 통로에서 이미 즉시 반영 —
유일 예외 `chat.window_mode`(새 대화부터 · 설계 의도)는 설명에 명시. **새 설정 키는
반드시 이 통로에 배선**한다.

### 도움말 "?" 배지 — 활성 반전 + 재클릭 토글 버그

- 열림 = **밝은 파랑 채움 + 흰 "?"** 반전(눌림 식별 · 비활성 창 무채 규칙 공유).
- ★ 재클릭이 안 닫히던 원인: `set_focused(false)`의 툴팁 자동 닫기. 호스트가 클릭마다
  포커스를 재계산하는데 "?" 배지는 컨트롤 bounds **밖** → 배지 클릭이 "닫기(포커스 아웃)
  →토글(열기)" 순서가 되어 **항상 열림**. 자동 닫기를 제거 — 바깥 클릭 닫기는
  `handle_help_click`이 원래 담당(**중복 책임이 상쇄 버그를 만든 사례**).

### 더블클릭 = Enter(목록)

같은 행 500ms 내 재클릭 = 활성화(대화 열기). 마우스 이벤트에 시각이 없어 `now_hint`
(~5Hz 틱 · ±200ms) 재사용 — 활성화 직후 판정 해제로 트리플클릭 중복 방지.

## 30 종단 동작 설명서 — 대화·파일 시퀀스 (사용자 요청)

요청: *"두 PC에서 프로그램이 실행되고 **실질적인 메시지를 주고받는 전체 과정**을 시퀀스 다이어그램으로. 그 후 **파일 송수신이 별도 세션으로 처리되는 과정**을 붙여서, 개념·기술·흐름이 순서에 따라 **어떻게 설정되고 어떻게 실행되며 어떤 결과를 만드는지** 이해할 수 있는 상세 설명서를."*

### 쓰기 전에 코드부터 확인했다

시퀀스는 **틀리면 해로운 문서**다. 실제 프레이밍·스트림 번호·봉투 구조를 코드에서 확인하고 그렸다 — `TcpLink`의 `[len u32 BE][payload]`(≤64KB), `MuxSession`의 `[stream_id 1B][payload]`와 3스트림(`Control`/`Chat`/`File`), `ChatMessage`의 `sender_device`+`seq`, 발견 패킷 71B 고정부.

### 구조 — 원칙 셋을 먼저 세우고 시작한다

순서만 나열하면 *"왜 그 순서인가"* 가 안 남는다. 그래서 맨 앞에 세 개를 뒀다:

- **발견은 주장, 세션은 증명** — 1단계의 `PeerId`가 왜 못 믿을 값인지가 여기서 설명된다
- **암호는 전송 위** — TCP는 바이트 관, 암호가 그 위, 다중화가 그 위
- **봉투만 본다** — 계층마다 보는 것이 다르다(링크=길이 / Mux=스트림 번호 / 게이트=메타)

그리고 **스택 그림**을 붙여 이 셋이 그림에서 어떻게 나타나는지 보이게 했다.

### 대화 시퀀스 — 7구간을 색으로 갈랐다

기동 → 목록 → 연결 → **핸드셰이크** → 다중화 → 대화 → 종료. 각 구간을 mermaid `rect`로 묶어 **어디서 성격이 바뀌는지**(평문 → 암호, 주장 → 증명)를 눈에 보이게 했다.

단계별 해설은 **네 칸 고정**이다 — *정해지는 것 / 실행 / 결과 / 왜*. 여기에 ⚠️로 **한계**를 붙였다(최초 접촉 MITM은 못 막는다 · 핀이 메모리 전용이다 · 발견 구간은 평문이다).

### ★ 파일 — "별도 세션"이 아니라 "별도 스트림"이다

사용자 표현이 *"별도 세션"* 이었는데, **우리 설계에서는 세션이 아니라 스트림**이라 그 구분을 문서의 중심에 놓았다:

| | 별도 **스트림**(우리) | 별도 **세션** |
|---|---|---|
| 얻는 것 | 대용량 파일이 **대화를 굶기지 않는다** | — |
| 잃는 것 | — | 핸드셰이크·소켓 **배증** · 신뢰 상태 **분리** |

★ **분리되는 것은 스케줄링이지 보안 경계가 아니다.** 파일도 **같은 암호 세션**을 탄다 — 별도 평문 경로를 만들지 않는다(W-9). 이걸 흐리면 "파일은 따로 보내니까 따로 암호화하나?" 하는 오해가 생긴다.

### 파일 게이트 — 시퀀스로 그리니 성질이 드러났다

[0]협상 → [1]격리 → [2]검사 → [3]승인을 시퀀스로 그리니, 각 단계의 **거부 분기**가 눈에 보였다. 특히 세 가지가 그림에서 명확해졌다:

- **[0]에서 거절하면 1바이트도 오가지 않는다** — 메타만으로 판단한다
- **[1] 동안 원본 파일명이 디스크에 없다** — 콘텐츠 주소(`<sha256>.beepq`)로만 존재
- **[2]의 실패·판정 불가는 전부 "격리 유지"로 모인다** — fail-closed가 **간선의 모양**으로 드러난다

### 마지막에 구현 현황표를 붙였다

이게 없으면 **문서를 읽고 "다 된 줄" 안다.** 대화까지(①~⑥)는 ✅ 실증이고 **파일은 📐 설계만**이며 `.beepq` 코덱조차 아직 브랜치에만 있다. 종단 문서일수록 **어디까지가 진짜인지**를 같은 문서 안에서 밝혀야 한다.

구간별 **"무엇이 새고 무엇이 안 새나"** 표도 넣어 [29](../29-wire-security-audit.md)와 연결했다 — 발견은 평문(이름·공개키·IP·포트), AEAD 구간은 **길이·타이밍만** 샌다.

## 🔐 보안 — 와이어 점검 기준 신설 · 실측 · 상시 관찰 체계 (사용자 요청)

요청 두 개가 이어졌다: *"봉투를 열어보거나 패킷 스니핑으로 내용을 확인하는 시도에 안전한지 **보안 점검 기준**을 만들고, **할 일에 실제 테스트 과정**을 넣어 보안 설계를 업데이트해 달라"* → *"**보안상 취약점은 TODO에 반영해 지속적으로 관찰·보완**하도록 해 달라."*

### 기준을 만들기 전에 먼저 캡처했다

[10 §0 관통 원리](../10-decision-record.md)는 *"어떤 계층도 필요한 만큼만 본다"* 는 **주장**이다. 주장 위에 기준을 세우면 주장이 두 겹이 될 뿐이라, **실제 패킷부터 떴다.**

우리 프로토콜은 멀티캐스트라 **그룹에 조인만 하면 `sudo` 없이 받아진다.** 파이썬 20줄로 88B ANNOUNCE 3개를 캡처했고, **그 난이도 자체가 공격 비용의 측정치**다.

### 🔴 두 개가 바로 나왔다

**R-19 — 표시 이름이 실명을 평문 방송한다.** ASCII 덤프에 `홍길동-MacBook`이 그대로 읽혔다. FR-D-9가 기본값을 **호스트명 기반**으로 두는데 macOS 호스트명은 대개 `{실명}의 MacBook`이다.

가장 아픈 건 이거다 — [22 ADR-0008](../22-adr-0008-profile-disclosure.md)이 *"브로드캐스트에는 어떤 프로필 필드도 싣지 않는다 — 평문 수확·사칭"* 으로 **정확히 이 위험을 막아 뒀는데, 이름 필드는 그 통제 밖**이었다. 프로필의 실명은 막고 표시 이름의 실명은 방치했다. **규칙이 있는데 적용 범위가 좁았던 전형적인 구멍**이다.

**R-18 — 고정 공개키가 영구 재식별자다.** `static_pubkey` 32B가 3개 패킷 모두 같고 신원 초기화 전까지 계속 나간다. ⚠️ [21 §4-3](../21-identity-spec.md)에서 **하드웨어 파생을 거부한 이유 4번이 "영구 추적자가 된다"** 였는데, **우리가 앱 계층에서 되살린 셈**이다.

완화가 어렵다 — 식별자를 회전시키면 **재접속 시 같은 상대를 못 알아본다**(TOFU와 정면 충돌). 그래서 감수+고지가 현실적이고 Q-29-2로 올렸다.

**부수 발견** — `Noise_XX`는 정적 키를 암호화해 교환하는데(identity hiding), **발견 패킷이 같은 키를 먼저 평문으로 뿌린다.** 세션의 그 성질이 우리 설계에선 이득이 되지 않는다. 결함이 아니라 **제로 컨피그의 대가**로 기록했다.

### 통과한 것도 적었다

허용 목록 준수(88B·필드 정확) · **`epoch`가 실시각이 아니라 카운터**라 가동 시간이 안 샌다 · `instance`는 프로세스마다 회전(추적자 아님) · 이름 무해화 통과. **통과를 적어야 다음에 무엇이 바뀌었는지 안다.**

### ★ 그리고 "상시"로 만들었다 — 주기가 아니라 트리거

두 번째 요청이 중요했다. 일회성 점검은 문서가 되고 문서는 잊힌다. 그래서 [TODO §9](../TODO.md)를 **달력이 아니라 사건에 걸었다**:

## 설계 3건 반영 — 핀 영속 · 상태 아이콘 · 설정 직렬화 표준 (사용자 요청)

### ① TOFU 핀 영속 — ADR-0005의 모순을 찾았다

[GUI 실증](#-신뢰-배지) 중 *"`Pinned`가 재시작하면 사라진다"* 를 발견해 설계에 반영하려는데, [17 암호화 범위 표](../17-adr-0005-history-at-rest.md)가 서로 반대되는 말을 하고 있었다:

| 대상 | 초판 | 이유 |
|---|:--:|---|
| 상대 `PeerId` | ✅ 암호화 | *"누구와 대화했는지도 보호 대상"* |
| TOFU 핀(공개키) | ❌ | *"공개키다. 암호화 이득 없음"* |

**핀 파일이 곧 상대 `PeerId` 목록**인데 한쪽만 암호화하면 위 줄이 무의미하다. *"공개키라 이득 없음"* 은 **키의 비밀성**과 **관계의 비밀성**을 혼동한 것이다 — 키는 비밀이 아니지만 **"내가 그 키를 안다"는 사실은 비밀**이다. H-1·H-4에서 **대화는 안 열려도 인간관계는 읽힌다.**

✅로 정정하고, 원래 이유에 있던 *"부팅 초기 필요"* 는 **기록과 분리된 작은 세그먼트**로 풀었다. 사용자 암호 승격에서만 잠김이 생기고 그때는 **fail-closed** — ★ **"핀 없음 = 처음 보는 상대"로 조용히 넘기면 재핀으로 이력이 오염된다. 모르는 것과 없는 것을 구분해야 한다.**

일정도 갈랐다 — **M2-5a**(핀 영속 최소 슬라이스)는 ADR-0005 **전체가 아니라 §3(키 관리)만** 확정되면 착수 가능하다. D-18을 통째로 기다릴 이유가 없다.

### ② 원형 상태 아이콘

FR-U-19 · M3-14. 근거 = 글자 배지는 한눈에 안 들어오고 **번역마다 길이가 다르다**(i18n을 막 넣은 참이라 바로 걸린다). 단 [14 §4](../14-control-ux-architecture.md) *"색만으로 구분하지 않는다"* 를 지켜 **모양도 함께 달리하고**(빈 원/채운 원/체크) 툴팁으로 등급명을 준다. 기존 `IconImage`(투명 RGBA) 경로 재사용.

### ③ 설정 직렬화 표준 — `nexa-dir2`를 전수 조사했다

사용자가 짚은 핵심은 *"여러 변경이 나도 **Tick당 1회만**, 최종 요청만 남기고 나머진 버린다"* 였고, **그 기법이 `nexa-dir2` `docs/20-session-coalescing.md`에 이미 문서로 있었다.**

조사에서 배운 정수는 **큐를 아예 만들지 않는다**는 것이다. 변경 지점은 플래그 하나만 세우고 **스냅샷은 flush 시점에** 뜬다 — 중간 상태를 저장하지 않으니 **버릴 것이 없다**. 함정 둘(`|` vs `||`로 한쪽 플래그 누수 · `KillTimer` 선행)까지 원문에 적혀 있어 그대로 계승했다.

**결함 4건은 고쳤다** — 미지 키 소실(구버전이 신버전 파일을 저장하면 사라진다) · 비원자적 덮어쓰기(`remove`→`rename` 사이 창)+fsync 없음+고정 temp 이름 · **starvation**(최대 지연 상한 없음 — 원문이 스스로 한계로 남겼다) · **스키마 4중 표현**(설정 1개 추가에 11~16곳).

★ **재사용을 막던 진짜 이유는 시계였다.** `nexa-dir2`는 Win32 `SetTimer`의 "같은 id면 교체" 성질이 **곧 메커니즘**이라 옮길 수 없었다. 우리는 **호스트가 `tick(now)`을 주입**한다 — 그리고 이건 새 발명이 아니라 **M1-2 링크 이벤트 `Debouncer`와 같은 부품의 두 번째 적용**이다.

[28 ADR-0011](../28-adr-0011-settings-persistence.md) · DR-27 · FR-P-8~12 · FR-S-48 · D-25 · M3-15. 조사 중 **설정값이 지금 전혀 저장되지 않는다**는 것도 확인했다(M3-11은 화면만).

## 전수 검증 — "코드는 있는데 동작을 본 적 없는 기능" 점검 (사용자 요청)

요청: *"지금까지 개발된 내용 중 **직접적으로 확인되지 않은 기능**을 모두 정리해 달라. 동작을 확인하고 완료 처리 및 문서 최신화를 하고 싶다."*

### 🔴 점검을 시작하자마자 나온 것 — CI가 red였다

기능을 세기 전에 CI 상태부터 봤는데 **main에서 3회 연속 실패** 중이었다. `main은 항상 green`([18 §3](../18-build-and-test.md))이 규약인데 깨진 채로 "완료 처리"를 할 수는 없어 이걸 먼저 잡았다.

원인은 **rustdoc `-D warnings` 6건**이고 전부 **문서 주석 링크**였다 — 코드 동작과 무관하다:

| 위치 | 오류 | 원인 |
|---|---|---|
| `core/i18n.rs` ×2 | public documentation links to private item | `Msg::row`가 private인데 public 문서에서 링크 |
| `ui/settings.rs` ×2 | unresolved link / redundant target | `[`TextBox`](글꼴명)` — **링크 문법 오용**(괄호 안이 링크 대상이 아니라 설명 텍스트였다) |
| `ui/controls/combo.rs`·`tree.rs` | redundant explicit link target | `[`Control`](super::Control)` → `[`super::Control`]` |

lint 잡만 실패했고 build·test는 통과하고 있었다. 그래서 **기능은 멀쩡한데 게이트만 막혀 있던 상태**였다.

### 게이트 재확인

`fmt` ✅ · `clippy` **0건** · **테스트 243 통과** · `rustdoc` ✅.

| # | 기능 | 방법 | 결과 |

### 미확인을 성격별로 갈랐다 — "왜 아직 못 봤나"가 다르기 때문

- 🖥 **육안(GUI) 필요 7건** — 피어 목록·신뢰 배지 3종 · 다중 창(M3-12) · 설정 화면(M3-11) · 컨트롤 갤러리 · 이미지 아이콘 · i18n 전환 · 고DPI/한글 IME. **헤드리스로 대행할 수 없다.**
