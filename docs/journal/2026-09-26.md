### 1. 코드 전수 — 형제 자격이 지워지는 자리와 돌아오는 조건

`siblings`(살아 있는 형제 집합)는 **세션 수명**이다(ADR-0015 — 다음 세션이 재판정). 지우는 자리는 둘뿐: `AppEvent::Closed`(세션 종료) · `user_apply_runtime` 비활성(값 변경·인증 실패). 설정 변경 디스패처는 `user.handle`/`user.passphrase`만 값 변경으로 보므로(`user.list_ver` 갱신은 무관) 후자는 사용자가 값을 만지지 않는 한 발생하지 않는다 → **세션 종료 후 재성립 경로**가 범인이다.

| # | 결함 | 왜 장시간 뒤에 나타나나 |
| --- | --- | --- |
| ① | 재성립 시 XXpsk3/세션 내 증명은 **60s 안의 LAN 힌트**(`sibling_hints`)가 있을 때만(`is_sibling_candidate`). 서버 경유 경로엔 힌트가 없다 | 세션은 keepalive(≈22s/Win ≈1분)·쓰기 30s·**절전 복귀**·**서버 재접속**(`relay_reattach_soft` = RelayLink 소멸)로 언젠가 끊긴다. 끊긴 뒤 서버 사다리로 XX 재성립 → 형제 아님. 릴레이 페어 RID 탐색(`user_tick`)은 30s마다 있지만 ③ 조건에 걸린다 |
| ② | 세션 내 증명은 세션당 1회(`proof_sent`). 상대가 **미준비**(부팅 PBKDF2·기능 켜는 중)면 내 증명은 버려지고(`proof_fails` 소진) 뒤에 상대 증명을 내가 대조해도 **회신이 no-op** | 한쪽만 형제(비대칭) — 재부팅·재인증이 겹치는 장시간 운용에서 누적 |
| ③ | `user_tick` 재탐색 조건 = `siblings.is_empty()` | 기기 3대에서 하나가 XX로 남으면 영영 재탐색 없음 |
| ④ | 목록 행·카드 배지 = 살아 있는 형제만 / 툴바 링 = 서명 목록(`devices_known>1`) | 세션이 끊기는 순간 **행 배지만 사라지고 링은 남는다** — 사용자가 본 "배지 소실"의 직접 모양 |

### 2. 수정(`8dedd1b` · 순수 규칙 3종 + 회귀 1)

- **후보 확장**: `is_sibling_candidate` = 살아 있는 형제 ∨ 신선 힌트 ∨ ★**서명 기기 목록의 내 기기**(`trust.seg` `devices_of_user(my_pub)` — 그 기기 자신의 세션에서 내 사용자 공개키를 서명 제시한 기록 · A-1). 효과 = 재연결 사다리(LAN `initiate_psk`·서버 `connect_via(psk)`)가 XXpsk3를 고른다(실패 = XX 1회 폴백은 기존) · XX로 섰어도 `install_conversation`→`send_user_proof(false)`가 나간다. **노출 등급** = 힌트 후보(같은 LAN 태그를 방송한 상대)보다 좁다(이미 내 UserKey 보유를 증명한 상대).
- **증명 회신 1회 추가**: `proof_send_allowed(sent, replied, force)` — 대조 성공 후 회신은 이미 보냈어도 한 번 더(`proof_replied` 상한). 내 쪽 미준비로 온 증명은 **실패로 세지 않는다**(트레이스 `deferred`).
- **재탐색 조건**: `seek_siblings_wanted(known, me, siblings)` — 아는 기기 중 형제 세션이 없는 것이 있으면(목록이 나뿐이면 종전 규칙). 트레이드오프 = 영구 오프라인 기기가 목록에 남아 있으면 30s마다 랑데부 1회(10s 타임아웃) — 종전 "형제 0"일 때와 같은 비용.
- **배지 근거**: `is_own_device` = 살아 있는 형제 ∨ 서명 목록(행은 `known_devices` 집합 1회 계산 · 피어 500 대비). ★**`effective_trust`는 세션 기준 그대로** — 승인·SAS·원격 대기 해제는 여전히 psk/증명이 선 세션에서만(ADR-0015 §4 불변).
- 진단: `NEXA_USER_TRACE=1`에 `closed <peer> sibling= known=` · `proof … deferred (not ready)`.
