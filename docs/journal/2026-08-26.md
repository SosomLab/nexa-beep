## (Win) [44] nexa-clip 연계 규약 수용 — RID 도메인 = 앱 식별자 주석 · prologue 실측 답신

자매 프로젝트 **`SosomLab/nexa-clip`**(크로스플랫폼 클립보드 매니저 · 같은 개발자)이 릴레이 서버
`nexa-beepd`와 와이어 `nbeep-relay`를 **그대로 재사용**하기로 하면서, 같은 서버에 두 앱 사용자가
함께 붙을 때 지켜야 할 규약을 정리한 **[44 nexa-clip 연계](../44-nexa-clip-liaison.md)** 가
외부(clip 쪽 세션)에서 들어왔다. 이 세션은 내용 검증·빌드 게이트·기록 동기를 수행했다.

핵심 규약 셋:

1. **RID 도메인 문자열 `"nbeep-rid-v1"` = 앱 식별자** — clip은 `"nclip-rid-v1"`을 쓴다.
   같은 공개키라도 도메인이 다르면 RID가 달라 **두 앱 사용자는 같은 만남 지점에 서지 않는다**(앱 격리).
   서버는 RID를 계산하지 않고 받은 16바이트를 라우팅할 뿐이라 **서버 코드·배포 무변경**
   (`nexa-beepd`는 `rid_for`를 안 부른다 — 44 §5-1 실코드 확인). ⚠️ 이 문자열을 바꾸려면
   **양쪽을 같은 시점에** 고쳐야 한다 — 주석이 그 취지를 코드 옆에 박제한다.
2. **glare(양쪽 동시 `Open`) 타이브레이크 부재** — clip이 릴레이 코드를 읽다 발견해 공유.
   beep에도 그대로 있는 문제(채널 이중 성립 가능). clip 채택안 = **PeerId 사전순 작은 쪽 = initiator**
   (결정적 · 추가 왕복 0 · 서버 중재는 봉투 원리 위반이라 배제) → **TODO X-11 등재**(채택 검토).
3. **나중에 앱 간 교환을 열 땐 브리지 옵트인**(`"nexa-bridge-rid-v1"`) — 기본 격리 유지.
   반대(기본 개방 후 차단)는 이미 섞인 것을 못 되돌린다.

### ② §1-2 prologue 질문에 대한 실측 답 — beep은 Noise prologue를 쓰지 않는다

문서 44 §1-2가 *"beep이 prologue를 쓰신다면 `"nexa-beep/<major>"` 형태로 — 현재 구현을 확인하지
못했습니다"* 라고 물었다. **실측: `crates/` 전체 grep `prologue` = 0건** — beep은 종단·서버 Noise
어디에도 prologue를 넣지 않는다. 현재 격리는 RID 도메인 분리(1차)만으로 성립하고, clip이 자기
prologue(`"nexa-clip/1"`)를 넣으면 **비대칭이어도 격리는 유지된다**(prologue 불일치 = 핸드셰이크 실패
— clip 쪽만 넣어도 beep↔clip 교차 핸드셰이크는 수학적으로 실패). beep 쪽 `"nexa-beep/<major>"` 채택은
**와이어 비호환 변경**(구버전 beep끼리 못 만나게 됨)이라 즉답하지 않고 X-11과 함께 검토 항목으로 묶었다
— 채택한다면 버전 경계(major)에서만.
