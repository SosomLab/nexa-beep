## (mac) [46 ADR-0015] UserId 기반 사용자 관리 설계 — Handle + Passphrase · 브랜치 `feat/userid-handle`

사용자: *"브랜치 추가 · UserId 기반 사용자 관리 · 개발 전에 방향 정리 · clip의 Handle/Passphrase처럼 두 값이 같으면 같은 사용자 · 같은 사용자면 승인/Verify 없이 · 메시지 동기화 · 릴레이까지는 Peer 단위 · 컨텐츠 모드는 일반 메신저처럼 · 난이도 평가"*.

### 조사(에이전트 2 · 요약)
- **clip**: `RID = PBKDF2-HMAC-SHA256(passphrase, "nclip-rid-v1"‖handle‖day, 60k)[..16]`(`nclip-sync/src/rid.rs:78`) — 패스프레이즈는 **만남 지점 파생만**, Noise에 안 들어감(PSK 0건), "같은 사용자" 판정 = **기기별 수동 승인**(6자리 육안 · `devices.rs:102`). DeviceList 서명은 문서만(T-24 ☐). `sync.passphrase`는 `settings.cfg` **평문**. 동기화 = 오프라인 큐 없음 · 도착순 LWW · 밀린 항목 최신 1개.
- **beep**: `UserId`는 타입 자리만(사용처 0) · **V1-1 미반영**(문서 32 §8 P-1이 "반영"이라 오기 — 스레드·기록·차단 전부 PeerId) · V1-2·3·4 실물 · `trust.level(peer)` 직접 호출 12곳 → `TrustStore::level` 한 곳에서 10곳 흡수 가능 · beepd RID 1:1(공유 URID 불가 · clip과 같은 우회) · Control 태그 4~9 비어 있음 · `ProfileMsg::Info` flags bit7 여유 · `snow 0.9.6` psk 수식자 지원.

### 설계 요지([46](../46-adr-0015-userid-handle-passphrase.md))
- 만남은 clip 식 그대로(도메인 `nbeep-user-*` 분리) · **신뢰는 Noise XXpsk3**(PSK = KDF(passphrase)) — 승인 0회의 근거를 사람의 습관이 아니라 핸드셰이크 성립에 둔다. 오프라인 사전 공격 불가(온라인 추측만) + 인바운드 실패 백오프.
- `UserId = SHA-256("nbeep-user-id-v1"‖handle‖KP)` — 두 값이 같으면 같은 사용자. ADR-0007 서명 체인은 v2에 `user_tag`로 얹는다.
- 제약 해제 = "사람을 믿느냐"만(TOFU·SAS·파일 승인·원격 대기·알림) · "파일을 믿느냐"(격리·무해화·기기별 실체화)는 유지(DR-13).
- 동기화 = sender copy(V1-2 집합 확장) + **따라잡기**(같은 사용자 기기 간 `SyncPull` 200줄 · append-only · 저장 키는 각 기기 것) · 컨텐츠 모드 = [32 §3-8] 동기 저장소 + 사용자 마스터 키(래핑 재검토 조건 발동 · 봉투 ①) · 파일 1회 업로드 + 보관함 온라인.
- 난이도: S0 하 · S1~S4 중(약 2주 · 서버 무변경) · S5 대(2주+). 🔴 **D-32 7문항**(권고안 굵게).
- 회신 예정(clip): 패스프레이즈 평문 저장 · 도메인 등재 · XXpsk3 채택.
