### ① 항목 ✕ = 개별 파일만 — 연쇄 취소의 뿌리 2개

- **와이어 축(핵심)** — 개별 `Cancel` 프레임을 받은 쪽의 처리(`xfer_step`)가
  `fail()` = **배치 전체 실패 이벤트**(`XferFailed`)였다. 앱의 배치 실패 처리는
  큐·배치를 통째로 비우므로, 한 파일의 취소가 같은 배치의 **나머지 파일까지**
  쓰러뜨렸다(스크린샷 "2.sna Failed 2"의 정체 — 1:1의 "수신 ✕ = 전체 취소"
  의미론이 남아 있던 것). 처방 = `XferFailed`에 `name`/`mine` 확장(빈 이름 =
  종전 배치 실패 그대로): Cancel 수신 = **그 파일만** 종결(sent/recv 장부로
  방향 판정 · 미지 xid만 배치 fail-closed 유지). 받은 Cancel이 보관 정지분
  (`parked`)·정지 의사도 정리하도록 `xfer_step`에 두 인자 추가.
- **발신 축** — `group_exclude_file`이 **대기 파일 제외 후에도 무조건 펌프**를
  돌려, 활성 전송 중에 다음 오퍼가 겹쳤다(`current_send` 덮임 = 이후 이벤트
  오배달 = 멀쩡한 파일 실패). 펌프는 현재 파일을 끊었을 때만.
- **수신 축** — 항목 ✕가 `cancel_active_xfer`(= 배치 전체 취소)로 배선돼 있던
  것을 **개별 취소**로 교체: xid 조준 `CancelXfer` · 오퍼 전이면 자동 거절
  무장(`batch_declined`) · 승인 대기 큐에서도 그 파일 제거 · 공용 장부 정리
  `drop_recv_file`(배너 총량 수축 — 안 올 바이트를 분모에 남기면 100%가 영영
  안 된다 · 자동 수락 잔여 제거 · **활성 슬롯은 그 파일일 때만 해제** — 아니면
  다른 파일의 진행 배너가 얼어붙는다(취소 경합 가드가 active를 봐서)).

### ② 그룹 수신 합산 배너 (수신자만)

발신 풍선은 카운터가 전부(확정 유지)지만, **수신자는 전체 진척과 전체취소가

> 수신은 그룹 스레드에서 1:1과 동일 동작. 전송 기계는 기존 1:1 스택 그대로(통합 로직).

### 배경 · 사용자 확정 사항 (08-23~24 문답)

기존(08-13 M5-1g)의 그룹 파일 팬아웃은 **와이어에 그룹 컨텍스트가 없어** 수신자가
"어느 방에서 온 파일인지" 알 수 없었고, 그래서 발신 진행 풍선·수신 승인 카드가
전부 구성원별 1:1 창에 흩어졌다(조사로 재확인 — `XferMsg::Offer`에 uid 없음 ·
`push_xfer_line`은 1:1 스레드만 · 그룹창에는 상태바 1줄+note뿐).

사용자 확정(AskUserQuestion 3건 = 전부 권고안 + 대화 확정 2건):

1. **수신측도 그룹창 표시** — 와이어에 그룹 표식 추가, 구버전 수신자는 1:1 폴백.
2. **발신 게이트 1:1과 동일 적용** — 종전 그룹 드롭은 batch_max·폴더 제외·크기
   상한·원격 파일 차단(FR-S-24)을 전부 건너뛰고 있었다(조사에서 발각).
3. **합산 배너 없음** — 풍선 카운터가 전부.
4. **송신측 개별 진행률 미표시** — "몇 명이 완료/진행/대기인지 숫자로만"(1:N에서
   송신율 관찰은 무의미 — 차후 컨텐츠 서버 경유 시 더더욱).
5. **제어는 ✕(전송 제외) 하나** — 1:N에서 일시정지는 송신자가 제어하기 어렵다.
   대기 = 철회 · **이미 송신 중 = 수신측에 "사용자 취소" 실패 처리** · 완료 = 불변.
6. **통합 로직**(사용자 지시) — 그룹/1:1이 분리된 메커니즘으로 갈라지지 않게.
7. **원복 대비**(사용자 지시) — 전용 브랜치·전방 호환 와이어/영속만.

### 설계 — 더한 것은 두 겹뿐

전송은 구성원별 1:1 스택(`send_queue`→`pump_send_queue`→세션 액터 `ActiveSend`→
File 스트림→무해화 게이트) **무변경**. 정책 단일 지점(`judge_offer`·
`send_xfer_decision`·`handle_xfer_ctl`)도 그대로 — 정책 두 벌 금지.

- ① **와이어 그룹 표식** — Control 태그 **18 `GROUP_HINT`**
  (`uid(32) ‖ size(8 LE) ‖ name_len(2 LE) ‖ name`). manifest(13)·qpause(17)와 같은
  **이름 기반** 문법(오퍼 전 xid 부재 시점 커버). manifest·오퍼보다 **먼저** 보내고
  오퍼 직전에도 멱등 재공지(수신 재시작 대비). 구버전 = 미지 Control 태그 무시 =
  **1:1 창 수신으로 자연 강등**(전방 호환 — 원복해도 프로토콜 잔재 무해).
- ② **표시·집계 라우팅** — 공용 라인 헬퍼 4곳(`push_xfer_line`·`set_xfer_line`·
  `set_xfer_line_named`·`set_xfer_line_named_or_fifo`)의 **머리 분기 하나**가 전부:
  같은 이벤트 축을 타되, 그룹발 발신이면 구성원 상태로 접어 카운터에 ·
  그룹발 수신이면 그룹 스레드의 그 라인에.

### 구현 — 발신 축

- **`XferLineState::GroupAgg`**(nbeep-ui) — 풍선 하나에 `완료 n · 진행 n · 대기 n`
  (+정지/실패/제외는 발생 시만). 진행 막대 없음 · 제어 아이콘 = ✕ 하나.
  `update_xfer_named`가 GroupAgg도 잡고(**FIFO `update_xfer_in`은 안 잡는다** —
  1:1 이벤트가 집계 풍선을 오염시키지 않게), 전 구성원 종결 시 Done/Failed
  요약("완료 2 · 실패 1 · 제외 1")으로 전환 — **그때만 `g-*.seg` 기록**
  (기존 tag 2 재사용 = 영속 포맷 무변경 · 구버전이 읽어도 무해).
- **집계 원료** — `GroupXfer { name, size, path, members: HashMap<PeerId, GxState>,
  closed }` · `GxState = Waiting|Active|Paused|Done|Failed|Excluded`(terminal 판정).
  단일 지점 `gx_note`(상태 반영+태그 정리)→`gx_refresh`(카운터 재계산·종결 전환).
- **라우팅 키** — `group_send_tags: (구성원, 원본 경로) → 방`. 오퍼·이벤트가
  파일명으로 되찾는다. 종결 시 제거 · 상한 64/상대(13 §12-1).
- **게이트 정합**(전부 1:1과 같은 판정 함수·상수): 폴더 제외 → 제외 풍선만 ·
  batch_max = **미종결 그룹 풍선 수** 기준(드롭 묶음 선판정도 그룹 분기) ·
  핀 미고정/차단 = 그 구성원 제외(모달 대신 카운터 — 나머지는 진행) ·
  상호 미왕래 = 1:1과 동일 경고 후 진행 · 원격×미대조(`remote_file_blocked`) =
  제외 · 크기 상한 = 발신 상한 × **구성원별 CapAdvert** 중 낮은 쪽(걸린 구성원만
  제외 + 그 상대 manifest에 excluded 동행).
- **세션 축 이벤트 접기** — `Closed` = 재-Offer 대기 복귀(**닿을 수단이 없으면
  실패로 닫는다** — 유령 "대기" 방지) · 자동 연결 소진(`fail_group_sends`)·
  거절(`XferFailed`)·전체취소 = 실패 · 세션 채널 사망(`pump` sent=false) = 실패.
- **✕(제외) 처분** — `group_exclude_file`: 보관 정지분 = 액터 parked까지
  CancelXfer · 현재 파일 = Cancel 통지 후 그 상대 다음 파일로 · 대기 = 큐·
  `pending_group_files` 철회(와이어 없음) · 종결분 = 불변. 상태는 전부 Excluded
  카운트.
- **중복 드롭 가드** — 같은 (이름, 크기) 풍선이 미종결이면 거절(라인 갱신이
  이름+크기 대조라 두 풍선이 서로 어긋난다 — 라우팅 모호성 원천 차단).

### 구현 — 수신 축

- **판정 = fail-closed** — 표식(hint)은 주장일 뿐: `recv_group_gid` =
  표식 존재 ∧ **수락한 방** ∧ **발신자가 명부에 있음**일 때만 그룹 라우팅.
  아니면 종전 1:1(모르는 방·명부 밖 발신·구버전 발신자 전부 이 폴백).
- 그룹 스레드에 **발신자 라벨 동반** 라인(manifest 대기·오퍼·진행·정지·종결·
  제외 전부) — 1:1과 같은 상태 전이·⏸▶✕(`drain_group_effects`에서 대상 상대를
  `recv_group_live` 장부로 되찾아 기존 `handle_xfer_ctl`로 보낸다).
- 승인 카드에 **"그룹" 행**(방 이름) · OS 알림 = 방 제목·`NotifyTarget::Group` ·
  미읽음 = `gunread`(G::Msg와 같은 문법). 승인·무해화·재개(.part)는 기존 그대로.
- 썸네일 부착·확대 미리보기도 그룹 스레드 배선(1:1에 대상 없으면 그룹 폴백).
- 배치 거절·전체취소·수신 취소 = `fail_group_recv_lines`(1:1 `fail_pending`과 짝).

### 알려진 한계(기본값 처리 — 사용자 통지분)

- 그룹 수신 종결 라인의 발신자 라벨은 **재시작 후 소실**(tag 2에 from 없음 —
  tag 신설은 구버전 판독기가 그 지점에서 멈춰 원복 안전을 해쳐 보류).
- 발신자가 **대기(오퍼 전) 파일을 제외**하면 수신측 manifest 대기 라인은 남는다
  (1:1 `cancel_one_send` 큐 철회와 동일 한계 — 와이어에 이름 기반 철회 통지 없음).
- 진행 중 재시작 = 집계 풍선 소실(1:1 진행 라인과 동일 규약 — 종결만 이력).
- N배 업링크는 그대로(32 §5-1) — 해법은 컨텐츠 서버 축(X-3 · P-9 kind 8 예약 완).
  이번 개편은 표식·집계 축만이라 **서버 전환 시 UI 무변경으로 하부만 교체** 가능.
