## 정렬 플리커 해소 + 온라인 우선 구조화 + 설정 스크롤 (main)

**실기 보고(사용자 2건)** — ① "온라인 대상이 먼저 보였다가 처음 목록처럼 보였다가
반복" ② IME 설정 카테고리에서 "내용이 더 있는데 스크롤이 안 된다".

**① 플리커 — 원인은 "갱신 때 정렬 누락"이 아니라 정렬 키 자체의 요동**:
최근 접속(last_seen)이 발견 비컨(800ms)마다 ms 단위로 갱신돼, **마지막 비컨의
주인이 매 갱신 바뀌며 동률 상대의 순서가 뒤집혔다**. 처방 2겹 —
접속을 **3계층**(0 세션 중 · 1 발견됨 · 2 오프라인 — 발견만 된 상대와 대화 중
상대를 같은 층에 두지 않는다)으로 가르고, 최근 접속은 **분 단위 버킷**으로
비교(버킷 동률 = 이름순 → 안정). "온라인이 더 위" 요청은 계층을 전 모드 공통
선두(이름순 제외)로 구조화 — 설정의 "접속 우선" 옵션은 중복이라 제거(저장값
관용 폴백). 그룹 섹션은 원래 인덱스 공간에서 피어보다 먼저라 항상 최상단.
**실측**: 재기동 후 3초 간격 스냅샷 3장 픽셀 해시 동일(플리커 0) · 순서 =
그룹 → 발견 상대(이름순) → 오프라인(beep-*).

**② 설정 스크롤** — 우측 패널 총높이 합산이 **설명 워드랩 예약분(2~3줄)을 빼고**
계산돼, IME처럼 긴 설명이 많은 카테고리에서 스크롤 상한이 실제 끝보다 작았다.
배치 루프와 같은 추정식으로 합산(회귀: 상한 스크롤에서 마지막 행이 뷰포트 안).

## H-27 — 같은 문자 반복이 판정을 무너뜨린다 ("ㅇㅇㅇ222" · 대화창/갤러리/프로필 공통)

**실기 보고(사용자, "제어 없이 대기")** — "ㅇㅇㅇ222" 순서대로 타이핑 →
"ㅇㅇ2ㅇ22". 자동 실기(osascript key code + `NEXA_IME_TRACE` + 스크린샷 픽셀
판독)로 합성 재현 = "ㅇㅇ22"(ㅇ 1·2 하나씩 유실). 트레이스 + 재생으로 원인 3중
확정 — 공통 뿌리는 **문자 "내용" 대조가 같은 문자 반복을 못 가른다**:

① 유출 첫 ㅇ(보류)이 다음 키의 preedit "ㅇ"에 starts_with로 중복 오폐기 →
   `SAME_KEY_MS`(40ms) 신선도 조건(같은 keypress의 keydown→Ime는 수 ms — 시각이
   가른다) ② 삼켜진 '2'가 다음 '2'의 정상 도달로 오인 소진 + 배달 증거 링이 잔여
   주입까지 차단 → **증거 링 폐기, 선배달 장부(owed)로 교체**(프록시 지연 짝을
   관측 도착 시점에 상쇄 — 큐 잔여 = 전부 진짜 삼킴. 불변식: 관측 수 = 도달 수 +
   삼켜진 수) ③ 조합 중 stale 틱 주입이 Commit보다 앞에 박힘(실타의 "2ㅇ") →
   조합 중엔 대기 + 주입 경로도 leak 선확정(`inject_char`) + 조합 중 keydown 관측
   짝 소진 + `PRE_CLEAR_SLACK`(300ms).

**검증** — 재생 3종 박제 + 기존 G1 2종("나!@#"·"다123") 새 의미론에서 통과(회귀 0)
+ 합성 자동 실기 재검: 삼켜진 셋째 '2'의 틱 폴백 주입 트레이스 실측 + 입력창
**"ㅇㅇㅇ222" 픽셀 확인**(이번 세션은 스크린샷 Read 가능 — 판독 루프가 살았다).
