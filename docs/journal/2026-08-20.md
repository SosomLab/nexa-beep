## (Windows 세션 3-c) 대화형 CLI 입력 경합 — 자기 콘솔 창으로 분리 (`2ae9f2a`)

**실기(사용자 · 3-b 직후)** — pwsh에서 `--chat-live` 실행: 프롬프트가 즉시
돌아오고("바로 종료"처럼 보임), 이후 셸 키 입력이 증발한다(스크린샷 —
`/help`·`exit` 타이핑이 앱/셸에 반반 배달).

**원인** — 3-b(windows 서브시스템 전환)의 예고된 트레이드오프가 실사용에서
문제화: cmd/pwsh는 **GUI 서브시스템 앱을 기다리지 않는다** → 프롬프트 복귀 +
**셸과 앱이 한 콘솔의 입력 버퍼를 나눠 읽는 경합**. 문서 안내(`start /wait`·
Git Bash)로는 부족 — 자연스러운 호출이 곧바로 이 경로다.

**수정** — `launch::own_console_for_interactive()`: ① stdin이 실제 콘솔인가
(`GetConsoleMode` — 파이프·mintty·CI면 경합이 없어 no-op) ② 부모 프로세스가
기다리지 않는 셸인가(Toolhelp 스냅숏 2회 조회 — cmd/powershell/pwsh/ise만 ·
**bash는 서브시스템 무관 대기라 그 자리 유지**) ③ 해당되면 옛 콘솔에 사유
1줄 고지 후 `FreeConsole`+`AllocConsole` — **대화형 세션이 자기 콘솔 창에서
입력을 독점**한다. Rust std는 표준 핸들을 호출마다 조회하므로 pivot 후
println/read_line이 새 콘솔로 자연히 이어진다. 배선 = `chat_interactive`
(--chat-serve/--chat-connect 공용)·`chat_live` 첫 줄(첫 출력 전 규약).

**실측** — 파이프 무회귀(bash `printf '/quit\n' |` → 배너 2줄·정상 종료 rc=0 —
relaunch.sh·CI 경로 보전) · 회귀 2종(비콘솔 stdin = no-op 박제 · 부모 이름
무패닉/소문자 형식). ⚠ **pwsh 실창(새 콘솔 창 열림·입력 독점) 육안은 실기
몫** — 헤드리스 하네스는 콘솔 stdin이 아니라 pivot이 안 걸린다. docs/26

## (Windows 세션 3-b) 콘솔 창 근절 — windows 서브시스템 전환 (`5d992c6`)

**실기(사용자)** — nexa-beep.exe 실행마다 터미널 창이 뜬다(스크린샷 = 빈
Windows Terminal 창이 앱 옆에 상주).

**원인** — 바이너리가 **콘솔 서브시스템**(CLI 겸용)이고, GUI 실행의 콘솔은
`from_gui_shell`(GetConsoleProcessList==1) + `FreeConsole`로 떼는 설계(M5-4d ·
08-11)였다. 이 트릭은 클래식 conhost에서만 유효 — **Windows 11 기본 터미널
(Windows Terminal)은 ConPTY 세션 창이 detach가 아니라 루트 프로세스 종료에
묶인다**. FreeConsole은 성공하지만 창은 앱이 살아 있는 내내 남는다.

**수정 3겹** —
1. **`#![cfg_attr(windows, windows_subsystem = "windows")]`** — 콘솔 창이 아예
   생기지 않는다(더블클릭·바로가기·자동 실행 M3-25 전부). mac·Linux 무변경.
2. **`launch::attach_parent_console()` 신설**(main 첫 줄 — 어떤 출력보다 먼저):
   터미널에서 불렸으면 부모 콘솔에 붙어 `--help`·검증 도구 출력 보전. ⚠
   AttachConsole은 **표준 핸들 셋을 콘솔로 덮으므로** 리다이렉트로 물려받은
   유효 핸들은 떠 뒀다가 `SetStdHandle`로 되살린다 — 안 그러면 `--version >
   파일`·테스트 캡처가 콘솔로 샌다. `from_gui_shell`/`hide_gui_console` 폐기.
3. **콘솔 자식 스폰 = CREATE_NO_WINDOW** — 콘솔 없는 부모가 콘솔 서브시스템
   자식을 그냥 스폰하면 창이 번쩍인다: imgdec 워커 2곳(`worker_command` 깔때기 —
   디코드마다 번쩍일 뻔) · `open_path`의 `cmd /c start`(로그 보기). `arp`
   (neigh.rs)는 macOS 한정이라 해당 없음 확인.

**실측(Windows)** — PE 헤더 subsystem=2(GUI) · GUI 실행 = "Nexa Beep" 창만·
신규 conhost 0 · **bash 캡처/리다이렉트 ✓ · PS 파이프 ✓ · cmd 리다이렉트 ✓** ·
**PS 맨 `>`만 빈 파일**(PowerShell이 GUI 앱을 안 기다리는 셸 quirk — 앱 측
해결 불가 · [26 §7](../26-run-and-manual-test.md) 유의 명기). 실측 중 부팅
자동 실행이 디버그 경로를 등록한 것은 원상 복구.

**셸 대기 관례 변경(Windows 한정 · 트레이드오프 명기)** — cmd·pwsh는 GUI
서브시스템 앱을 기다리지 않는다: 인터랙티브 CLI(`--chat-live` 등)는
`cmd /c start /wait` 또는 **Git Bash**(bash는 서브시스템 무관하게 대기 —
relaunch.sh·CI 경로는 전부 bash라 무영향). **715 green** · clippy 0 · rustdoc 0.
