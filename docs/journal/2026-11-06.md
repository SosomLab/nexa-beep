## 2차 — X-2 릴레이 Transport 승격(통산 14차 · 코드 = 개발 세션 · 검증 실행·기록 = 협업 세션)

> 사용자 결정 11-05 #7 "지금 착수 · 코드까지". 커밋 `8237f8e`(크레이트 5 · +902/−171).

### 왜

어댑터(`nbeep-relay` 08-21)와 GUI 배선(X-2b 08-22)은 있었지만 `Transport` 구현체가 없어 DR-8 ②(2모드 추상화)가 실물로 닫히지 않았다. App은 세 단(발견 `transport.connect` → 수동 `add_endpoint` → 릴레이 `connect_via`)을 `start_connect`에서 직접 꿰었고, **릴레이 단만 세션을 들고** 돌아와 경로마다 핸드셰이크 코드가 달랐다(인바운드도 `spawn_inbound_accept`와 `spawn_relay_accept` 둘). ADR-0003 핵심 규칙 "암호화는 Transport 위"가 릴레이 경로에서만 어긋나 있던 것.

### 설계 요지

- **단 선택을 링크 수준으로 내렸다** — 여는 쪽 `LadderLink`(1단 UDP 펀치 직결 · 2단 릴레이를 한 `Link`로 · 확정 전 send는 1단 + 사본 · 1단 recv 실패(UDP 상한 5s) 시 사본을 2단으로 재전송하고 2단 고정 = **첫 회신이 온 단에 고정**) · 수락 쪽 `accept_link_via`(**첫 프레임 링크 추종** · `PrefixedLink`). 그래서 **핸드셰이크는 전 경로 호출자**가 같은 코드로 얹는다 — ADR-0003 "암호화는 Transport 위"가 릴레이에도 성립.
- `connect_via`/`accept_via`는 그 위에 핸드셰이크만 얹는 얇은 층(CLI·기존 호출자 무변경 · 단 판정은 공유 원자값).
- **`RelayTransport`**(서버 접속 1개 위 `Transport` · Weak 수명 · 인바운드 펌프) + **`LadderTransport`**(로컬 임의 `Transport` + 기억한 수동 주소 + 릴레이 hot-swap `set_relay` · 우선순위 **로컬 > 수동 > 릴레이** · `incoming` 합류 · 발견·설정류는 로컬 위임).
- nbeep-net `Transport::note_endpoint/forget_endpoint`(수동 주소 = 사다리 2단 재료 · 기본 no-op) · `ConnectError::{Busy, Lost}` · nbeep-core `Link::rendezvous()`(표시 전용 — 헤더·M3-27 배지 `via_server` · 기본 false).
- **App 배선** — 실물 전송 = `LadderTransport`(부팅·respawn) · 서버 접속 성공 = `set_relay` · `spawn_relay_accept` 제거(릴레이 인바운드가 LAN 펌프로 합류 → RL-13 ⓐ 상한·타임아웃·psk 백오프가 릴레이에도 적용) · `start_connect`/64hex 지문 연결 = `transport.connect` + 같은 핸드셰이크 · Outbound 처리기 랑데부 단 **WrongPeer fail-closed**(종전 `connect_via` 동작 보존) · 수동 주소 insert/remove 시 `note/forget_endpoint`.
- **roster는 App 유지** — 발견 명부(X-2e)를 `Transport::discovery`에 합치려면 `PeerHint` 출처 표식·`PeerTable` 수명 모델(광고 타임아웃이 없는 상대)이 먼저 필요 → **ADR-0003 개정 후보 = TODO X-2f**(P3 ⏸). 여기서 "발견 증강" = 발견 밖 상대(roster·지문)도 `connect` 하나로 닿는다는 뜻.

## 4차 — X-2f 발견 스트림 합류 구현(통산 15차 · 코드 = 개발 세션 · 검증 실행·기록 = 협업 세션)

> 커밋 `31e7e10`(크레이트 7 · +784/−274) · ADR-0003 §9(3차) ②③④. **서버 와이어 무변경 — OCI beepd 교체 불필요.**

### 왜

X-2로 connect·incoming은 사다리 전송 하나로 합류했지만 **발견만 두 갈래**였다 — LAN은 `Transport::discovery` → PeerTable(60s TTL), 서버 명부는 App `server_tick`이 `poll_roster`를 직접 드레인해 `server_peers`·`server_cards`·`roster_known/pending/capped`에 넣고 행을 따로 합쳤다(App이 릴레이 와이어·카드 인코딩을 알고, 병합·이탈 규칙이 흩어져 시험 불가). "Transport = 발견하고 Link를 만드는 것"의 반쪽.

### 구현 요지

- **② nbeep-core `PeerTable`** — `HintOrigin{Local,Rendezvous}` · `Liveness{Advertised,Eventful}` · `PublicCard{name,email,bio}` · `PeerEvent::Updated`(출처 집합·카드 변경). 항목 = 경로별 (출처, 수명) + 카드 · `observe_with` — 이름·세대 우선권은 **로컬 광고**(카드 이름은 로컬 광고가 없을 때만) · `last_seen`은 Advertised 관측만 · `goodbye` = 마지막 경로만 이탈 · `sweep` = 만료 시 **광고 경로만 거둔다**(이벤트형이 남으면 강등 `Updated`) · `rendezvous_only()`. 기존 `observe`/`observe_gen` 호환 · 단위 +5.
- **③ nbeep-net** — `PeerHint{origin, liveness, source, profile}`(source = 경로 토큰 · LAN 0 · 랑데부 세대별 1+) · `DiscoveryEvent::Withdrawn{peer, source}`(`Vanished`는 LAN 의미 그대로 · LocalDirect·InMemory는 필드만).
- **③ nbeep-relay `transport.rs`** — `RelayTransport` 펌프가 매 폴 `poll_roster`를 발견 이벤트로(자기 PeerId 제외 · 상한 `ROSTER_MAX` 4096 · 카드 정제 = DisplayName/제어 문자 제거·200자 **경계에서** · 빈 카드 바이트 = None · 접속 소멸 시 일괄 `Withdrawn`) · `set_announce(false)` = 일괄 `Withdrawn` · `LadderTransport` 발견 합류(로컬 + 랑데부 세대별 토큰 · `set_relay`는 옛 세대 명부를 즉시 `Withdrawn` 뒤 새 세대 장착 — 늦은 이탈이 새 명부를 못 지운다) · 단위 +2.
- **④ App** — `poll_discovery` = `observe_with` + `Withdrawn` → `goodbye(SourceId(source))` · 랑데부 힌트는 광고 감쇠·LAN 프로필 동기 재연결 제외(4096명 재연결 폭주 방지) · `refresh_rows`의 server_peers 블록 삭제 · 칩·대표 경로 = 테이블 출처 · 카드 폴백 = `entry.profile` · `server_tick` roster 블록(≈80줄)·`clear_server_peers`·필드 5·상수 2 삭제 · announce 3곳 사다리 경유 · respawn 뒤 재공지. **차단 상대·차단 이름 `forget`이 서버 상대에도 적용**(종전 비대칭 해소).
- 비범위 — M3-27 경로 배지(성립 세션 기준) · 오프라인 큐.

### 왜

- N-3 — 전달·읽음 상태가 메모리(`ChatLine.delivered/read`)에만 있어 재시작하면 전부 "미전달"로 보였다. 확인 시각은 **봉인된 레코드 안**(세그먼트 헤더 아님 · 규칙 8).

- Bye — 정중한 종료 신호가 없어(DEVLOG 08-13) 상대가 `/quit`·종료한 뒤에도 백오프 재연결(5s·15s·60s·300s)이 죽은 상대를 두드렸다.

### 구현 요지

- **nbeep-ui `ChatLine`** — `delivered_at`/`read_at: Option<u64>`(Unix ms) + `with_acks` · `mark_ack`/`mark_read_upto`가 처음 참이 될 때 시각 기록.
- **기록 코덱 tag 8** — tag 4 머리 ‖ flags(bit0 전송 · bit1 전달 · bit2 읽음 · bit3 답장 꼬리) ‖ [시각 u64 ×≤3] ‖ from ‖ text ‖ [답장 꼬리]. 상태가 있을 때만 — 없는 줄은 tag 4/6/7 **바이트 불변** · 구판은 첫 tag 8에서 멈춤(tag 6/7 선례). ack로 상태가 바뀐 스레드마다 `record_history`(RL-7 디바운스).
- **nbeep-core `action.rs`** — `AlertLevel{Silent,Badge,Toast,Alarm}` · `ChannelKind{Webhook,Smtp}` · `SuppressReason{Untrusted,RateLimited,DoNotDisturb,Disabled,Blocked}` · `ActionKind::{NotificationRaised, AckSent, AckReceived, EscalationSent, EscalationSuppressed}` = `0x0601~0x0605`(골든·유일성 시험).
- **nbeep-core `bye.rs`(신규)** — `Bye{reason: ByeReason{Shutdown, Other(u8)}}` · `BYE_TAG = 23` · 와이어 2B · 미지 사유는 Other로 받되 Bye로 인정.
