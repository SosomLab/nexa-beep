## 실기 지적 5건 — 클립보드 실물 · 스크롤바 시간 기반 · 우클릭 메뉴 · 설정 계층 (main 직커밋 5)

08-10 심야~08-11 새벽에 걸친 한 세션. 전부 **사용자 실기 지적에서 출발**했고,
다섯 건 중 **네 건이 "보이는데 동작하지 않는다"** 유형이었다 — 화면에는 멀쩡히 그려지는데
입력이 닿지 않거나, 성공한 척만 하고 아무 일도 하지 않는 코드.

### ① macOS·Linux 클립보드 실물 (`5ad0c3d`)

지적: *"채팅입력란에서 붙여넣기 단축키가 미동작(⌘V, Ctrl+V)"*.

★ **원인은 단축키 배선이 아니라 클립보드 자체였다.** `app.rs`의 ⌘C/⌘X/⌘V 핸들러는
멀쩡히 있었고 라우팅도 정상이었다. `plat::clipboard`의 **비-Windows 구현이 통짜 스텁**
(`None`/`false` 반환 + "M3-1b에서" 주석)이라, ⌘V는 제대로 도착하고도 **읽어 올 내용이
없었다**. ⌘C도 마찬가지로 아무 데도 쓰지 않고 성공한 척만 하고 있었다.

> 08-10 9차에 "클립보드 왕복 테스트 실통과 = 어댑터 정상 확증"이라고 적었는데,
> **그 테스트가 Windows 경로만 태우고 있었다**. 스텁이 조용히 성공을 반환하니
> 테스트도 통과했다. **"성공한 척하는 스텁"은 테스트까지 속인다** — 이번에 추가한
> 왕복 테스트는 실제 OS 도구를 태우고, 도구가 없는 환경은 건너뛴다(거짓 green 금지).

- macOS `pbcopy`/`pbpaste` · Linux **Wayland `wl-copy`/`wl-paste` 우선, X11 `xclip` 폴백**.
  외부 크레이트 0(DR-5) — OS 기본 도구를 파이프로 쓴다.
- 도구가 없으면 **실패를 그대로 보고**한다. stdin을 명시적으로 닫아야 자식이 입력 끝을
  안다(안 닫으면 `wait`에서 멈춘다).

### ② 스크롤바 자동 숨김 — 호출 횟수 → 벽시계 (`f9a82d6`)

지적: *"드래그를 하면 잠깐 횡스크롤이 표시되었다가 금방 사라짐 (사라지는 시간 확인해줘)"*.

★ **원인 — 자동 숨김을 시간이 아니라 `tick()` 호출 횟수로 셌다**(`HIDE_TICKS = 6`).
호스트는 유휴일 때만 `wait_duration(200ms)`로 틱하고, **이벤트가 들어오면 그때마다**
`about_to_wait`를 돈다. 그래서 마우스 이동이 초당 수십 건 쏟아지는 드래그 중에는
6회가 **0.2초 만에** 다 깎였다. 질문("사라지는 시간")에 대한 답은 **"상황에 따라 다르다"** —
유휴 1.2초, 드래그 중 0.2초. 같은 코드가 6배 다르게 동작했다.

- `tick(now_ms)`로 **벽시계 마감**을 잰다 → 호출 빈도와 무관하게 항상 같다.
- 지연 **기본 2000ms**(사용자 확정) · 설정 `ui.scrollbar_hide`(숨기지 않음/1000/2000/
  3000/5000/10000 + 직접 입력). **0 = 항상 표시.**
- 지연은 **프로세스 전역**(`AtomicU64`) — 스크롤바가 목록·트리·갤러리·대화·설정에
  흩어져 있어 값을 인스턴스마다 들고 다니면 한 군데만 옛 값으로 남는다(핫스왑 원칙).
- **호버 유지 + 두껍게는 코드에 이미 있었는데 보이지 않았다** — 호버 전환에 재그리기
  요청이 없어 화면이 그대로였다. `dirty` 플래그를 `tick`이 호스트에 전달하게 했다.
- 드래그를 놓는 순간부터 지연을 다시 시작(놓자마자 사라지지 않는다).
- 회귀 테스트: **tick을 500번 몰아쳐도** 시계가 지연 안이면 유지.

부수: 툴바에서 **컨트롤 갤러리 제거**(사용자 요청) — 메뉴·⌘/Ctrl+G로 연다.

### ③ 우클릭 컨텍스트 메뉴 (`052cb4c`)

지적: *"우클릭으로 복사/잘라내기/붙여넣기 메뉴"* · *"글상자 우클릭시 바로 클립보드로
저장되는데 메뉴를 보이게 하고 복사할 수 있도록"*.

★ **우클릭이 곧바로 동작하면 되돌릴 수도, 확인할 수도 없다** — 풍선을 우클릭하는 순간
클립보드가 덮어써졌고, 사용자는 무엇이 복사됐는지(혹은 됐는지) 알 수 없었다.

- 새 컨트롤 **`ContextMenu`**(커스텀 16종째) — 커서 자리 팝업 · 호버 강조 · 구분선 ·
  **비활성 항목** · 화면 밖으로 나가면 **경계 안으로 접는다**. **무엇을 할지는 모른다**
  — 항목 id만 돌려주고 실행은 호스트 몫(DR-21 이음새 · UI 크레이트는 OS를 모른다).
- 위치로 대상이 갈린다 — **입력란** = 복사/잘라내기/붙여넣기/전체 선택,
  **말풍선** = "메시지 복사". **빈 곳에는 열지 않는다**(무엇에 대한 메뉴인지 모르니까).
- 활성 여부는 실제 상태로 — 선택 없으면 복사 불가, 입력이 비면 전체 선택 불가,
  **클립보드가 비면 붙여넣기 불가**. 클립보드 유무는 UI가 알 수 없어 호스트가
  우클릭 순간 한 번만 확인해 알려준다(매 프레임 긁지 않는다).
- 붙여넣기는 위젯이 **요청만** 남기고 호스트가 채운다. 읽기 실패도 상태줄에 밝힌다.
- 메뉴가 열린 동안의 클릭은 팝업이 **소비**한다 — 닫으려던 클릭이 뒤로 새서 캐럿이
  옮겨가거나 드래그 선택이 시작되면 안 된다.

### ④ 설정 화면 VS Code식 그룹 구성 (`ca8c48b`)

지적(스크린샷 3장): *"Appearance를 고르면 다크 색 → 라이트 색 → 언어가 섞여 나온다.
순서와 그룹핑 조정이 필요하다."* + 계층 고정 표시 요구.

★ **원인은 정렬이 아니라 정렬의 부재** — 우측 목록이 registry 선언 순서를 그대로 썼다.
같은 라벨("Accent", "Received bubble")이 그룹만 다른 채 반복되는 구조라, 순서가 섞이는
순간 **화면에 남는 단서가 하나도 없다**. 가운데의 "Accent"가 다크의 것인지 라이트의
것인지 알 방법이 없었다.

- **순서**: 상위 직속 설정 먼저 → 하위 그룹이 사이드바 순서대로(안정 정렬로 그룹 안
  registry 순서 유지).
- **하위 섹션 제목**을 각 그룹 첫 행 위에. 직속 구간에는 붙이지 않는다(상위 제목은
  고정 밴드가 늘 보여주므로 두 번 적을 이유가 없다).
- **상단 고정 밴드** — 윗줄 상위 / 아랫줄 현재 하위(직속이면 비움). 하위 설정이 길어
  제목이 스크롤로 사라져도 **무엇에 속한 값인지 계속 보인다**. ★ 밴드 높이는 하위 유무와
  무관하게 **고정** — 그룹 경계를 넘을 때 아래 내용이 튀면 읽던 자리를 잃는다.
- 밴드는 내용 **위에** 불투명하게 덮으므로 본문은 밴드 아래에서 시작하고, 밴드 영역의
  클릭은 삼킨다(안 막으면 **보이지도 않는 행의 콤보가 열린다**).

### ⑤ 긴 한 줄 가로 스크롤 · 제목 위계 (`28b48f4`)

지적: *"좌우 스크롤을 클릭해서 드래그할 수 없다"* · *"트랙패드 두 손가락 좌우 이동에도
스크롤바가 뜨지 않는다"* → 추가 관찰: *"5줄일 때는 되는데 1줄일 때는 안 된다"*.

★ **원인 — 가로 이벤트를 세로 조건으로 막고 있었다.** 입력창 스크롤바 처리 **전체**가
`count > INPUT_MAX_LINES`(세로 4줄 초과) 안에 들어 있어, 줄바꿈 없는 긴 한 줄은
**세로로 1줄**이라 통째로 걸러졌다. 그런데 **그리는 쪽은 따로** `needs_v || needs_h`를
보고 있었다 — 그래서 막대는 그려지는데 클릭·드래그·가로 휠은 닿지 않는,
정확히 "보이는데 잡히지 않는" 상태가 됐다. 사용자의 "5줄/1줄" 관찰이 조건을 정확히 짚었다.

> 교훈: **같은 판정을 두 곳에서 따로 쓰면 언젠가 갈라진다.** 그리기와 이벤트가 서로
> 다른 조건을 보고 있었고, 갈라진 지점이 곧 버그였다. 판정을 하나로 맞췄다.

설정 제목 위계(사용자 확정):
- 상위 제목 = 본문 글꼴 **+2px 굵게** · 하위 제목 = **+1px 굵게**. 절대 크기를 박지 않고
  **증분**으로 얹는다(`DrawCtx::select_font_sized` 신설) — 사용자가 글꼴 크기를 바꾸면
  제목도 같이 커야 위계가 유지된다.
- 하위 제목 상자 34→52px, 글자를 **아래쪽에 붙였다** — 남는 높이가 그대로 위 여백이
  되어 앞 그룹과 끊긴다.

### 관찰

- 이번 5건 중 **4건이 "보이는데 동작하지 않는다"** — 스텁이 성공을 반환하고(①),
  타이머가 호출 횟수로 돌고(②), 호버 상태가 재그리기 없이 바뀌고(②), 그리기와 이벤트가
  다른 조건을 보고(⑤). 공통점은 **화면과 동작이 서로 다른 근거를 본다**는 것이다.
  단위 테스트는 각각 통과했는데, 둘을 잇는 단언이 없었다.
- ★ **M3-1b(OS 동작 어댑터)의 클립보드 부분이 실물로 채워졌다** — mac/Linux 잔여는
  스크롤 관성·창 닫기 관례. 컨텍스트 메뉴도 M3-1b 항목이었는데 이번에 컨트롤이 생겼다.
- 설정 화면(M3-11)의 **다단 계층 잔여**가 해소됐다 — 2단 카테고리가 실제로 생겼고
  순서·제목·고정 밴드까지 붙었다. 남은 잔여는 확인 훅과 **값 영속(M3-15 · D-25 대기)**.
- ⏸ **트레이 상주(M3-2)는 착수하지 않았다** — 사용자 요청은 받았으나 트레이 아이콘

  되찾을 방법이 없다**(창 닫기=상주가 기본이면 더 심각). 판단 대기.
