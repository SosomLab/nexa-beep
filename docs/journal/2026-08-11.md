## M3-16 — 주소 입력 모달 창 (`feat/m3-16-addr-modal`)

DR-19 수동 엔드포인트 진입을 상태바 인라인 입력에서 **별도 모달 창**으로 승격(사용자 요청).
인라인은 `adding: Option<String>`에 문자를 밀어넣는 짜깁기라 선택·클립보드·캐럿 이동·형식
검증이 없었다.

**위젯(`addr_prompt.rs`).** 제목 + `TextBox`(Beam 캐럿·선택·클립보드 재사용) + host:port/
`[v6]:port` **형식 검증** + Connect/Cancel. `valid_endpoint()`는 포트 1~65535 필수·v6는 대괄호
필요로 오타를 즉시 잡고, 화면에 유효=초록 "Enter로 연결" / 무효=위험색 형식 안내를 실시간
표시. 위젯은 I/O를 모르고 **유효 주소 문자열만** `take_submit`으로 내놓는다(연결·최근 주소
기록은 호스트 몫 — 계층 분리).

**호스트(app).** `Role::AddEndpoint` 창(380×150·비리사이즈·IME 허용) · `⌘/Ctrl+K`·툴바 `+`가
이 모달을 연다 · submit → `commit_manual_add` · Esc/취소 → 닫기. ★ **인라인 `adding` 경로를
완전히 제거**(필드·상태바 Beam 캐럿 렌더·키 핸들러 40여 줄) — 두 입력 경로가 공존하면 한쪽만
고쳐지는 순간 갈라진다(같은 이유로 08-10 격리 게이트도 공용 함수로 합쳤다).

**검증** — addr_prompt 테스트 4(형식 v4/v6/쓰레기 · Enter는 유효만 확정 · Esc·취소 버튼) ·

동기 경로 — M2-8 워커 이관과 합류하면 죽은 주소 입력도 UI를 막지 않는다.

## M4-9 — 전송 완료 종단 확인(ack) + 종료 가드 (`feat/m4-9-transfer-ack`)

08-10 사용자 점검("송신 후 수신 완료 전 종료하면?")으로 등록한 P0. 발신 "전송 완료"가
**소켓에 쓴 시점**일 뿐이라, 수신측 격리 성공과 무관하게 완료로 남던 거짓 완료를 없앤다.
와이어에 수신 완료를 알리는 메시지가 아예 없었던 게 근본 원인.

**와이어(전방 호환 규약이라 필드 추가가 안전).** `XferMsg::Received{id}`(kind 7)·
`Failed{id}`(kind 8) 신설 — 수신측이 SHA 재검증·격리까지 마친 뒤 발신자에게 돌려준다.
라운드트립 테스트에 두 종류 추가.

**상태 기계 — `AwaitingAck` 신설이 핵심.** 발신 청크+Done을 다 보내면 완료가 아니라
**"전달됨 · 확인 대기"**(비종결)로 둔다. 여기서 함정 하나를 설계로 막았다: 배치 다중 파일에서
A가 확인 대기인데 B가 진행 중이면, `update_xfer_in`(가장 오래된 진행 항목 갱신)이 A의 확인
대기를 덮을 수 있다 → **`update_xfer_in`은 `AwaitingAck`을 건너뛰고**, ack 전용
`update_xfer_ack`가 확인 대기 항목만 종결로 닫게 분리했다(Received→완료 · Failed→"상대가
받지 못함"). A=확인 대기·B=진행 중이 섞여도 각자 정확히 닫히는 것을 단위 테스트로 고정.

**종료 가드.** 미확인 전송(`awaiting_ack`)·진행 중(`awaiting_accept`·`send_batch`)이 있으면
주 창 **첫 닫기는 경고만**("N건 확인 대기 — 다시 닫으면 종료"), 두 번째로 확정 — 격리함
비우기·실행형 승인과 같은 2단계 문법. ack가 다 오면 자동 해제.

**정직한 경계.** 2노드 실물 왕복은 대화 성립(양방향 1회)+승인 클릭이 필요해 헤드리스
스크립트로는 불안정하다 — 상태 기계·와이어는 단위 테스트로 고정하고, 실물 왕복(전달됨 →
확인 대기 → 완료, 수신측 강제 종료 시 실패 표기)은 GUI+chat-live 실기 확인 대기로 남긴다.
CLI(`--chat-*`)도 같은 ack를 주고받고 "상대 수신 확인 — 완료"/"상대가 받지 못함"을 출력한다.

**검증** — 워크스페이스 **432 green**(xfer 라운드트립 + AwaitingAck/ack 순서) · clippy 0.
⇒ 열려 있던 마지막 P0(M4-9) 코드 완료.

## M5-4d — Windows 더블클릭 무반응 수정 (`fix/m5-4d-windows-double-click`)

아래 배포 실기에서 잡은 P0를 바로 고쳤다. macOS가 v0.1.2에서 `launched_from_app_bundle()`로
번들 더블클릭을 창 모드로 돌렸지만 그 판정이 `.app` 전용이라, Windows는 탐색기 더블클릭·시작
메뉴 바로가기가 **콘솔만 번쩍이고 종료**됐다(콘솔 서브시스템 + 인자 없음 → 스캐폴드 출력 후 끝).

**판정 — "탐색기가 새 콘솔을 할당했는가".** `GetConsoleProcessList` 휴리스틱(Raymond Chen):
콘솔에 붙은 프로세스가 **자기 하나뿐(반환 1)** 이면 탐색기가 이 앱을 위해 콘솔을 새로 만든
것이고, 기존 터미널(cmd·pwsh)에서 부르면 셸까지 2개 이상이다. `plat::launch::from_gui_shell()`로
두고(비-Windows는 항상 false — macOS는 기존 번들 경로 판정 유지), main에서
`gui_launch = 번들(mac) || (무인자 && from_gui_shell())`. macOS 대칭을 Windows에 채운 것.

**남은 콘솔 창 제거.** 우리는 콘솔 서브시스템이라 창 모드로 가도 그 콘솔이 GUI 옆에 남는다 →
`hide_gui_console()`(`FreeConsole`)로 떼어낸다. 붙은 게 자기뿐(count==1)일 때만 호출하므로
마지막 detach가 되어 콘솔 창이 닫힌다.

**두 번째 방어선(NSIS).** 런타임 감지가 첫 방어선이고, 시작 메뉴 바로가기·완료 실행에
`--window --live`를 명시해 인자로도 GUI를 보장한다(둘 중 하나만으로도 되지만, 배포는
되돌리기 비싸다).

**실측(이 PC)** — ⓐ 터미널 무인자 실행 = 스캐폴드 출력(**CLI 동작 보존** — 콘솔 상속 count≥2) ·
ⓑ `Start-Process`(탐색기 방식 = 새 콘솔) = **"Nexa Beep" 창 전환·콘솔 잔존 없음**(RSS 16.6MB).
워크스페이스 **431 green** · clippy 0. ⇒ M5-4b(스토어 게시)의 마지막 걸림돌 해소 —
다음 릴리스(v0.1.3)에 실려 나가면 게시 가능.

**🔴 핵심 결함 — Windows 더블클릭이 macOS 번들 버그(v0.1.2 ⑤)의 미수정 쌍둥이다.**
포터블 exe는 **콘솔 서브시스템**(PE Subsystem=3)이고, 인자 없이 실행되면 `main`이 스캐폴드
안내만 찍고 끝난다([main.rs:95](../../crates/nexa-beep/src/main.rs) — `open_window || separate ||
bundled`가 false). 더블클릭 = **콘솔 창이 번쩍이고 사라짐**. macOS는 `launched_from_app_bundle()`
([main.rs:116](../../crates/nexa-beep/src/main.rs))로 번들 실행을 창 모드로 돌렸지만 **그 판정이
`.app/Contents/MacOS/` 전용 = Windows엔 대응이 없다.** 게다가 NSIS **시작 메뉴 바로가기·설치
완료 "실행"이 전부 인자 없이** exe를 부른다([installer.nsi:41,60](../../packaging/windows/installer.nsi))
— 즉 설치본도 **정식 실행 경로(시작 메뉴)가 같은 방식으로 깨져 있다.** 배포로 처음 손에 쥔 Windows
사용자의 경험 = "눌러도 반응 없음"(mac에서 v0.1.2로 고친 바로 그 문제).

처방 후보(코드 수정 → v0.1.3 · **M5-4d 등록**): ⓐ NSIS 바로가기·FINISHPAGE에 `--window --live`
인자 부여(가장 싸다 · 설치본만 고침) ⓑ Windows에서 "Explorer 실행"(부모 콘솔 없음 —
`GetConsoleProcessList==1` 등) 감지 → 창 모드(**포터블·설치본 둘 다 고침** · 권장) ⓒ GUI
서브시스템 별도 바이너리(과함). ⓑ가 macOS `launched_from_app_bundle`과 대칭이라 자연스럽다.

**결론** — 파이프라인·매니페스트·설치/제거/업그레이드는 **전부 정상**(체크섬·winget validate 통과).
M5-4b의 선행 조건("설치·제거·포터블 실행 실기")은 **더블클릭 결함 1건을 빼고 충족**. 게시 전
v0.1.3에서 M5-4d를 고치는 것이 맞다 — 안 그러면 스토어로 받은 사용자가 첫 실행에서 막힌다.
상세 자산·해시는 스크래치패드 `deploy-test/`.

## 인터랙티브 모드 종료 경로 정리 — `/quit` + 대기 중 입력 + 터미널 복원

사용자 지적: *"인터랙션 모드에서 종료를 Ctrl+C나 Ctrl+D로 안 되는데 `/quit` 명령으로
종료할 수 있게 설계에 넣어줘."*

### 실측으로 그림을 먼저 그렸다

pty로 네 조합을 재현했다. **"둘 다 안 된다"의 실체는 두 가지 다른 문제**였다.

| 상태 | Ctrl+C | Ctrl+D |
| --- | --- | --- |
| 상대 대기 중 | 종료됨(status 2) | **✗ 무반응** |
| 연결됨(raw) | 종료됨(status 2) | 종료됨 |

- ★ **대기 구간에는 입력을 읽는 쪽이 아예 없었다** — `accept()`/`incoming.recv()`에
  통째로 갇혀 있어 키가 어디로도 가지 않았다. `/quit`만 넣었다면 **같은 구멍이 남았을** 것이다.
- ★ **Ctrl+C는 종료되지만 `Drop`을 건너뛴다**(status 2 = 시그널 사망) → `RawTerm`이 복원되지
  않아 **터미널이 raw 모드로 남는다**(에코·줄 편집이 죽어 셸이 먹통처럼 보인다).
  사용자가 "종료가 안 된다"고 느낀 실체는 아마 이쪽이다.

### 조치 — 세 경로를 한 정리 절차로 모았다

1. **`/quit`·`/exit`·`/q`** + `/help` 명령. 안내 문구는 상수 하나(`HELP_COMMANDS`)로 —
   안내와 구현이 갈리면 그 자체가 거짓말이 된다.
2. **대기 구간도 stdin을 본다** — `RawTerm::enter_polling()` 신설(`VMIN=0`·`VTIME=1`).
   0.1초마다 돌아와 연결·종료 신호·키를 함께 본다. `--chat-serve`의 `accept()`는
   논블로킹으로, `--chat-live`의 `recv()`는 타임아웃으로 바꿔 같은 루프에 태웠다.
3. **채팅 모드에도 종료 포트**(`plat::shutdown`)를 건다. 이제 Ctrl+C가 기본 종료가 아니라
   플래그를 세우고, 루프가 정상 반환하며 **`Drop`이 터미널을 복원**한다(status 2 → 0).

### 검증(실측)

| 경로 | 결과 |
| --- | --- |
| 대기 중 `/quit` · Ctrl+D · Ctrl+C | 전부 status 0 |
| serve 대기 중 `/quit` | status 0 |
| 연결됨 `/quit` · Ctrl+D | status 0 |
| Ctrl+C 후 터미널 | **ECHO·ICANON 복원 확인**(pty termios 조회) |
| 파이프 `/quit`(연결 후) | status 0 · `[끝]` 출력 |
| 비-TTY 대기 중 `SIGTERM` | 정상 종료 |

⚠️ **비-TTY 대기 중에는 `/quit`을 읽지 않는다** — 자동화가 파이프로 보낸 줄은 대화용이지
대기용이 아니다. 그 경우는 `SIGTERM`/`SIGINT`로 끝낸다(위 실측). 문서에 명시.

④는 **구조를 추측한 대가**다. 이제 `*.installer.yaml`이 실제로 든 폴더를 찾는다.

### ★ macOS 격리 — 문서를 믿고 적었다가 틀렸다

참고 프로젝트 문서에 *"Homebrew Cask는 설치 시 quarantine을 제거하므로 서명 경고 없이
실행된다"* 고 적혀 있어 그대로 릴리스 노트에 옮겼다. **사실이 아니었다.**
brew로 설치한 뒤 실행해 보니 앱이 죽었고(`exit 137` = SIGKILL), **macOS가
`/Applications`에서 앱을 치워 버렸다**. 실측 결과:

| 상태 | 결과 |
| --- | --- |
| 서명 없음 + 격리 | `exit 137` · 앱 삭제됨 |
| **애드혹 서명** + 격리 | `exit 137` — **서명은 격리를 넘지 못한다** |
| 격리 제거(서명 유무 무관) | 정상 실행 |

`brew install --cask --no-quarantine`도 **이 Homebrew 버전엔 없는 옵션**이었다.
→ ① `.app`에 애드혹 서명(Apple Silicon은 서명 없는 번들을 아예 실행하지 않는다)
② **Cask `postflight`에서 격리 표식 제거** — 공증에는 Apple Developer 인증서가 필요해
그것 외에 방법이 없다. 무엇을 왜 하는지 `caveats`와 릴리스 노트에 그대로 밝혔다.
**사용자가 모르는 채로 보안 검사를 끄지는 않는다.**

> 교훈: **"문서에 그렇게 적혀 있다"는 실측이 아니다.** 네트워크만 추정 금지가 아니라,
> 플랫폼 동작도 마찬가지다. 이번엔 내가 쓴 릴리스 노트가 사용자에게 거짓을 말할 뻔했다.

### 포장 정책 정리(사용자 확정)

압축 형식을 **플랫폼 관례**로 맞췄다 — Windows는 zip(포터블 + `setup.exe`의 zip 사본:
실행 확장자를 막는 프록시 대비), macOS/Linux 포터블은 **tar.gz**(실행 권한이 보존된다).
`.dmg`/`.deb`의 zip 사본은 뺐다(이미 배포 형식이라 덧씌울 이유가 없다).

### ★ 앱을 더블클릭하면 아무 일도 없었다

brew 설치 후 Finder에서 열어 보니 **창이 뜨지 않았다.** macOS는 `.app`을 열 때
**인자를 하나도 주지 않는데**, 우리 `main`은 인자가 없으면 스캐폴드 안내를 찍고 끝난다.
터미널에서는 옳은 동작이지만 번들에서는 "눌러도 아무 일이 없다"가 된다.

→ 실행 파일 경로가 `*.app/Contents/MacOS/*`이고 **실질 인자가 없으면** 창 모드로 본다
(Finder가 붙이는 `-psn_...`은 인자로 세지 않는다). 번들 밖에서 부르면 해당하지 않아
CLI 동작은 그대로다. 번들 실행은 **실물 발견이 기본** — 데모 에코 봇을 보여 줄 자리가 아니다.

실측: 번들 바이너리 인자 없이 실행 → 계속 떠 있음(창 모드) · `open -a` → 프로세스 확인 ·
터미널 직접 실행 → 스캐폴드 출력 유지.

### ① macOS·Linux 클립보드 실물 (`5ad0c3d`)

지적: *"채팅입력란에서 붙여넣기 단축키가 미동작(⌘V, Ctrl+V)"*.

★ **원인은 단축키 배선이 아니라 클립보드 자체였다.** `app.rs`의 ⌘C/⌘X/⌘V 핸들러는
멀쩡히 있었고 라우팅도 정상이었다. `plat::clipboard`의 **비-Windows 구현이 통짜 스텁**
(`None`/`false` 반환 + "M3-1b에서" 주석)이라, ⌘V는 제대로 도착하고도 **읽어 올 내용이
없었다**. ⌘C도 마찬가지로 아무 데도 쓰지 않고 성공한 척만 하고 있었다.

> 08-10 9차에 "클립보드 왕복 테스트 실통과 = 어댑터 정상 확증"이라고 적었는데,
> **그 테스트가 Windows 경로만 태우고 있었다**. 스텁이 조용히 성공을 반환하니
> 테스트도 통과했다. **"성공한 척하는 스텁"은 테스트까지 속인다** — 이번에 추가한
> 왕복 테스트는 실제 OS 도구를 태우고, 도구가 없는 환경은 건너뛴다(거짓 green 금지).

- macOS `pbcopy`/`pbpaste` · Linux **Wayland `wl-copy`/`wl-paste` 우선, X11 `xclip` 폴백**.
  외부 크레이트 0(DR-5) — OS 기본 도구를 파이프로 쓴다.
- 도구가 없으면 **실패를 그대로 보고**한다. stdin을 명시적으로 닫아야 자식이 입력 끝을
  안다(안 닫으면 `wait`에서 멈춘다).

### ② 스크롤바 자동 숨김 — 호출 횟수 → 벽시계 (`f9a82d6`)

지적: *"드래그를 하면 잠깐 횡스크롤이 표시되었다가 금방 사라짐 (사라지는 시간 확인해줘)"*.

★ **원인 — 자동 숨김을 시간이 아니라 `tick()` 호출 횟수로 셌다**(`HIDE_TICKS = 6`).
호스트는 유휴일 때만 `wait_duration(200ms)`로 틱하고, **이벤트가 들어오면 그때마다**
`about_to_wait`를 돈다. 그래서 마우스 이동이 초당 수십 건 쏟아지는 드래그 중에는
6회가 **0.2초 만에** 다 깎였다. 질문("사라지는 시간")에 대한 답은 **"상황에 따라 다르다"** —
유휴 1.2초, 드래그 중 0.2초. 같은 코드가 6배 다르게 동작했다.

- `tick(now_ms)`로 **벽시계 마감**을 잰다 → 호출 빈도와 무관하게 항상 같다.
- 지연 **기본 2000ms**(사용자 확정) · 설정 `ui.scrollbar_hide`(숨기지 않음/1000/2000/
  3000/5000/10000 + 직접 입력). **0 = 항상 표시.**
- 지연은 **프로세스 전역**(`AtomicU64`) — 스크롤바가 목록·트리·갤러리·대화·설정에
  흩어져 있어 값을 인스턴스마다 들고 다니면 한 군데만 옛 값으로 남는다(핫스왑 원칙).
- **호버 유지 + 두껍게는 코드에 이미 있었는데 보이지 않았다** — 호버 전환에 재그리기
  요청이 없어 화면이 그대로였다. `dirty` 플래그를 `tick`이 호스트에 전달하게 했다.
- 드래그를 놓는 순간부터 지연을 다시 시작(놓자마자 사라지지 않는다).
- 회귀 테스트: **tick을 500번 몰아쳐도** 시계가 지연 안이면 유지.

부수: 툴바에서 **컨트롤 갤러리 제거**(사용자 요청) — 메뉴·⌘/Ctrl+G로 연다.

### ③ 우클릭 컨텍스트 메뉴 (`052cb4c`)

지적: *"우클릭으로 복사/잘라내기/붙여넣기 메뉴"* · *"글상자 우클릭시 바로 클립보드로
저장되는데 메뉴를 보이게 하고 복사할 수 있도록"*.

순서와 그룹핑 조정이 필요하다."* + 계층 고정 표시 요구.

★ **원인은 정렬이 아니라 정렬의 부재** — 우측 목록이 registry 선언 순서를 그대로 썼다.
같은 라벨("Accent", "Received bubble")이 그룹만 다른 채 반복되는 구조라, 순서가 섞이는
순간 **화면에 남는 단서가 하나도 없다**. 가운데의 "Accent"가 다크의 것인지 라이트의
것인지 알 방법이 없었다.

- **순서**: 상위 직속 설정 먼저 → 하위 그룹이 사이드바 순서대로(안정 정렬로 그룹 안
  registry 순서 유지).
- **하위 섹션 제목**을 각 그룹 첫 행 위에. 직속 구간에는 붙이지 않는다(상위 제목은
  고정 밴드가 늘 보여주므로 두 번 적을 이유가 없다).
- **상단 고정 밴드** — 윗줄 상위 / 아랫줄 현재 하위(직속이면 비움). 하위 설정이 길어
  제목이 스크롤로 사라져도 **무엇에 속한 값인지 계속 보인다**. ★ 밴드 높이는 하위 유무와
  무관하게 **고정** — 그룹 경계를 넘을 때 아래 내용이 튀면 읽던 자리를 잃는다.
- 밴드는 내용 **위에** 불투명하게 덮으므로 본문은 밴드 아래에서 시작하고, 밴드 영역의
  클릭은 삼킨다(안 막으면 **보이지도 않는 행의 콤보가 열린다**).

### ⑤ 긴 한 줄 가로 스크롤 · 제목 위계 (`28b48f4`)

지적: *"좌우 스크롤을 클릭해서 드래그할 수 없다"* · *"트랙패드 두 손가락 좌우 이동에도
스크롤바가 뜨지 않는다"* → 추가 관찰: *"5줄일 때는 되는데 1줄일 때는 안 된다"*.

★ **원인 — 가로 이벤트를 세로 조건으로 막고 있었다.** 입력창 스크롤바 처리 **전체**가
`count > INPUT_MAX_LINES`(세로 4줄 초과) 안에 들어 있어, 줄바꿈 없는 긴 한 줄은
**세로로 1줄**이라 통째로 걸러졌다. 그런데 **그리는 쪽은 따로** `needs_v || needs_h`를
보고 있었다 — 그래서 막대는 그려지는데 클릭·드래그·가로 휠은 닿지 않는,
정확히 "보이는데 잡히지 않는" 상태가 됐다. 사용자의 "5줄/1줄" 관찰이 조건을 정확히 짚었다.

> 교훈: **같은 판정을 두 곳에서 따로 쓰면 언젠가 갈라진다.** 그리기와 이벤트가 서로
> 다른 조건을 보고 있었고, 갈라진 지점이 곧 버그였다. 판정을 하나로 맞췄다.

설정 제목 위계(사용자 확정):
- 상위 제목 = 본문 글꼴 **+2px 굵게** · 하위 제목 = **+1px 굵게**. 절대 크기를 박지 않고
  **증분**으로 얹는다(`DrawCtx::select_font_sized` 신설) — 사용자가 글꼴 크기를 바꾸면
  제목도 같이 커야 위계가 유지된다.
- 하위 제목 상자 34→52px, 글자를 **아래쪽에 붙였다** — 남는 높이가 그대로 위 여백이
  되어 앞 그룹과 끊긴다.
