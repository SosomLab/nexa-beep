## (Win) 모바일 확장 기술 검토 + [43] 조사 문서 신설 — 소스 무변경

사용자 요청 — *"iOS/Android에서도 동일 네트워크 내 메시지 교환이 가능한가 · 구조 설계 방향과
프레임워크 추천 · UserId 멀티디바이스 검토 · 컨텐츠 서버 대화 동기화 반영 범위 확인 ·
모바일 지원 메신저 조사를 별도 문서로"*. ⚠️ **개발 요청이 아니라 기술 검토**이고, 구현은
별도 프로젝트 또는 같은 저장소의 다른 패키지가 될 수 있다(사용자 명시 · 결정은 아직 없다).

### ① 이식성 — 크레이트 의존 실측

| 구분 | 크레이트 | 외부 의존 |
|---|---|---|
| **그대로 재사용** | `nbeep-core`·`nbeep-safe`·`nexa-conf`·`nbeep-relay` | **0** |
| | `nbeep-crypto`(snow) · `nbeep-store`(chacha·getrandom) · `nbeep-net`(socket2) | 순수 Rust |
| **교체 대상** | `nbeep-gfx`·`nbeep-ctl`·`nbeep-ui`·`nbeep-plat` | 렌더·플랫폼 |

★ **프로토콜·암호·저장·상태 기계가 전부 순수 크레이트에 있다** — DR-21(외부 기술은 포트 뒤에)과
단방향 의존을 지켜 온 결과라, 이식 비용의 상당 부분은 이미 지불돼 있다.

### ② 구조적 장벽 넷 (모바일이 강제하는 것)

1. **iOS는 자식 프로세스를 못 띄운다** → `nbeep-imgdec` 격리 디코드 모델이 통째로 깨진다.
   R-5 완화를 iOS에서는 재설계해야 한다(권고 = OS 디코더 위임 — 격리를 OS가 대신).
2. **백그라운드 정지**(iOS 수 초 · Android Doze) → "실행 = 참여"(DR-1)가 모바일에서는
   **"앱을 보고 있을 때만 참여"** 가 된다. 백그라운드 수신 = 푸시 = 서버.
3. **멀티캐스트 권한** — iOS 엔타이틀먼트(애플 승인) · Android `MulticastLock`.
4. **셀룰러엔 LAN이 없다** — 사용 시간의 상당 부분에서 1급 전송 경로가 부재.

> ★ **그래서 나오는 결론** — 모바일을 지원하면 **[32 ADR-0013 서버 모드가 선택이 아니라 전제**가 된다.
> 다행히 그 준비(`nexa-beepd`·홀펀칭·릴레이 사다리)는 08-21~22에 끝나 있다 —
> **모바일이 서버 축의 첫 실수요자**가 되는 셈이다.

### ③ 프레임워크 권고 — Rust 코어 + 네이티브 UI(UniFFI)

조사에서 **Signal(libsignal)·Matrix(matrix-rust-sdk)·Delta Chat(deltachat-core-rust)** 이 목적이
서로 다른데도 **같은 구조로 수렴**했다. 틀리면 치명적인 것(와이어·암호·중복 제거)은 플랫폼 무관이고,
플랫폼마다 달라야 하는 것(입력기·알림·백그라운드·접근성)은 네이티브가 압도적이라서다.
★ 특히 **IME** — 데스크톱에서 H-1~27을 겪은 이 프로젝트가 모바일 IME를 자체 구현으로 다시 하는 것은
같은 고통의 반복이다. 대안 평가(Flutter = LocalSend 선례지만 런타임 수십 MB로 DR-5 충돌 ·
전체 Rust UI = 비권장 · 완전 별도 구현 = 와이어 표류 위험)는 [43 §4](43-mobile-messenger-survey.md).

### ④ 확인 결과 — 준비도가 항목마다 다르다

| 항목 | 상태 |
|---|---|
| **UserId 멀티디바이스** | ✅ 설계 Accepted(ADR-0007) + **v1 제약 4건이 코드에 이미 반영**(V1-1 `UserId` 타입 자리·V1-2 `Recipients` 팬아웃·V1-3 `sender_device`·V1-4 래핑 한 겹). 구현만 X-6 |
| **파일(blob) 동기화** | ✅ 모드② = 동기 저장소(B) 확정 · 기록 등급 L0~L2 · 에스크로 봉투 |
| **새 메시지 동기화** | 📐 sender copy 설계만(FR-M-8 · v2) |
| ★ **과거 이력 동기화** | ❌ **미설계** — ADR-0007 제약 3이 *"새로 묶은 기기는 대화가 비어 있다"* 로 명시 배제 · X-7로 분리("X-6로 안 풀리는 별개 설계") |

> ★ **모바일에서 ④의 마지막 줄이 치명적이 된다.** 데스크톱 1대 전제에서 감수할 수 있던 한계가,
> 다중 기기가 일상인 모바일에서는 **입장권 수준 요구**가 된다(폰을 붙였는데 대화가 비면 고장으로 읽힌다).
> 다행히 **V1-4(한 겹 래핑)가 문을 열어 뒀다** — 백업 키로 다시 감싸면 재암호화 없이 이전이 가능하다.
> 즉 **설계는 없지만 자리는 있다.**
