# 11 · ADR-0004 — 수신 파일 무해화 (`.beepq` 격리 컨테이너 · 위험 등급 · 승인 UX)

> **상태: ✅ Accepted (사용자 확정 08-17 — D-12)** · 제안 2026-08-08 · 결정자 Sangyong Bae
> **구현 완료**(M4-1 · `nbeep-safe` — 4단계 게이트·위험 등급·`.beepq`·승인 UX · 08-17 격리물 봉인 sealed 추가). 공식 확정만 남아 있던 것을 확정.
> [04 안전 송수신](04-safe-transfer.md)의 설계를 **구현 가능한 규격**으로 확정하는 문서. DR-13의 실체.
> 관련: [05](05-requirements.md) FR-S-5~17 · [01 §4-3](01-architecture.md)(데이터 흐름) · [02](02-roadmap.md) M4-1

## 1. 결정 요약

| # | 결정 |
|---|---|
| ① | 격리물은 **`.beepq` 단일 컨테이너 파일**. 원본은 승인 전까지 **파일시스템에 형태로 존재하지 않는다** |
| ② | **봉인 = 원본 선두 N바이트를 본문에서 잘라 메타 영역으로 옮긴다.** 본문만으로는 어떤 로더도 해석 불가 |
| ③ | 파일명은 **콘텐츠 주소** `<sha256>.beepq` — 원본 파일명을 파일시스템에 넘기지 않는다 |
| ④ | **위험 등급 4단계**를 확장자·매직·구조로 판정하고 **승인 마찰을 차등** |
| ⑤ | 실체화 시 **OS 격리 표식을 붙인 채로** 내보낸다 — 우리 승인이 OS 방어를 해제하지 않는다 |
| ⑥ | 상태 기계는 **fail-closed** — 어떤 예외도 "격리 유지"로 수렴 |

## 2. `.beepq` 컨테이너 규격

### 레이아웃 (v1)

| 오프셋 | 크기 | 필드 | 설명 |
|---:|---:|---|---|
| 0 | 4 | `magic` | `NXBQ` |
| 4 | 2 | `format_ver` | u16 LE. **미지 버전은 열지 않는다**(fail-closed) |
| 6 | 2 | `flags` | 봉인 여부 · 검사 완료 · AMSI 결과 등 비트 |
| 8 | 32 | `content_sha256` | **원본 전체**의 SHA-256 (봉인 전 기준) |
| 40 | 8 | `original_size` | u64 LE |
| 48 | 2 | `sealed_len` (N) | 본문에서 잘라낸 **선두 바이트 수** |
| 50 | N | `sealed_prefix` | **잘라낸 원본 선두 N바이트** — 본문에는 없다 |
| 50+N | 4 | `meta_len` | u32 LE |
| 54+N | 가변 | `meta` | 아래 메타 블록 |
| … | 가변 | `body` | **원본[N..]** — 연속된 원본이 아니다 |

**N 결정**: `min(512, original_size)`. 512B면 PE/ELF/Mach-O 헤더, 스크립트 셔뱅, 아카이브 로컬 헤더를 전부 덮는다.

### 메타 블록 (자체 TLV — 의존성 0)

| 키 | 내용 |
|---|---|
| `orig_name` | **원본 파일명 원본 바이트**(UTF-8, **정규화하지 않은 상태**로 보존) |
| `declared_ext` / `declared_mime` | 송신자가 **주장한** 형식 |
| `detected_kind` | 매직바이트로 **판정한** 형식 |
| `risk` | 위험 등급([§3](#3-위험-등급-판정)) |
| `sender` | 발신자 `PeerId`(키 지문) |
| `received_at` · `expires_at` | 수신 시각 · 자동 삭제 예정 |
| `scan` | `NotScanned` / `Scanned{clean}` / `Scanned{detected}` / `Unavailable` |
| `xfer` | 전송 세션 참조(대화 스레드 연결용) |

> **`orig_name`을 원본 그대로 보존하는 이유** — 정규화는 **표시할 때**와 **실체화할 때** 각각 한다. 저장 시점에 정규화해 버리면 "원래 어떤 이름으로 왔는가"를 잃고, 그러면 RLO 공격을 사후에 감사할 수 없다. 단 **UI에 넘기는 경로는 반드시 무해화를 거친다**(FR-S-13).

### 파일시스템 규칙

| 항목 | 규칙 |
|---|---|
| 이름 | `<hex sha256>.beepq` — **원본 파일명 미사용**(T-4 전체 차단) |
| 위치 | 전용 격리 폴더(데이터 경로 하위). **임시 폴더·시작 프로그램·자동 실행 경로 금지** |
| 권한 | 소유자 읽기/쓰기만. **실행 비트 없음** |
| 확장자 | `.beepq` — OS에 연결 프로그램을 **등록하지 않는다** |
| OS 표식 | 저장 즉시 [§5](#5-플랫폼별-격리-표식) 적용 |
| 중복 | 같은 SHA-256이면 **재사용**(디스크 절약). 메타의 `xfer`만 추가 |

## 3. 위험 등급 판정

**확장자 · 매직바이트 · 구조**를 **모두** 본다. 셋 중 하나라도 상위 등급을 가리키면 **상위 등급을 택한다**(fail-closed).

### 🔴 실행형 — 최고 마찰

| 플랫폼 | 확장자 |
|---|---|
| Windows | `exe com scr pif bat cmd msi msp msc cpl lnk hta vbs vbe js jse wsf wsh ps1 psm1 ps1xml psc1 reg inf sct scf url library-ms search-ms appx appxbundle msix` |
| macOS | `app pkg mpkg dmg command workflow terminal` |
| Linux | `sh bash run deb rpm AppImage snap flatpakref desktop` |
| 공통 | `jar class py rb pl php` |

> `.lnk`·`.url`·`.scf`·`.desktop`은 **매직바이트가 없거나 무의미**하다 — 확장자 판정이 유일한 방어선이다. 이것이 [04](04-safe-transfer.md)에서 "헤더 봉인만으로는 부족하다"고 한 이유.

### 🟠 능동 콘텐츠 문서 — 높은 마찰

`docm xlsm pptm dotm xltm potm xlam ppam` · `pdf` · `rtf` · `chm` · **`iso img vhd vhdx`**

> **`iso`/`vhd`를 여기에 넣은 이유** — 마운트하면 내부 파일이 **격리 표식을 물려받지 않을 수 있다**. 알려진 MotW 우회 경로라 데이터 취급하면 안 된다.

### 🟡 아카이브 — 중간 마찰 · **자동 해제 금지**

`zip 7z rar tar gz bz2 xz tgz cab lzh ace arj`

목록 조회 시 강제 검증:

| 검사 | 규칙 |
|---|---|
| **Zip Slip** | 항목 이름 정규화 후 **추출 대상 경로가 목적 디렉터리의 자식인지** 확인. 절대 경로·`..`·드라이브 문자·심볼릭/하드 링크 항목 **거부** |
| **압축 폭탄** | 총 해제 크기 상한 · **압축률 상한** · 항목 수 상한 · **중첩 깊이 상한** 초과 시 거부 |
| 이름 일관성 | 로컬 헤더와 중앙 디렉터리의 이름 불일치 시 거부 |
| 내부 항목 | 해제하더라도 **각 항목이 다시 이 게이트를 탄다**(재귀) |

### 🟢 데이터 — 낮은 마찰

위에 없는 것. **단 `svg`는 이미지가 아니라 문서**로 취급한다 — 스크립트·외부 참조가 가능하므로 **미지원**(FR-S-12).

### 형식 불일치 경고

`declared_ext`와 `detected_kind`가 어긋나면 **승인 화면 상단에 별도 경고**:
> *"PDF라고 전달되었지만 실제 내용은 실행 파일입니다."*

## 4. 상태 기계

```
        협상 수락
           ▼
      [Receiving] ──실패/취소──► [Discarded]
           ▼ 완료
      [Quarantined]  ← 이 시점에 이미 봉인·표식 완료
           ▼ 검사
      [Inspected(risk, scan)]
           │
     ┌─────┼──────────────┬─────────────┐
     ▼     ▼              ▼             ▼
 [Approved] [Rejected] [Expired]   [Failed]
     ▼         ▼           ▼            ▼
[Materialized] 삭제       삭제      격리 유지 + 사용자 고지
```

| 전이 | 규칙 |
|---|---|
| `Receiving → Quarantined` | **SHA-256 불일치면 즉시 폐기.** 부분 수신물은 남기지 않는다 |
| `Quarantined → Inspected` | 검사 실패·판정 불가는 `Failed`가 아니라 **`Inspected{scan: Unavailable}`** — 사용자에게 "검사 안 됨"으로 표시하고 승인 마찰을 **한 단계 올린다** |
| `Inspected → Approved` | **사용자 명시 승인만.** 자동 승인 경로는 코드에 존재하지 않는다 |
| `Approved → Materialized` | 실패 시 **`Quarantined`로 롤백**(부분 파일 삭제) |
| `→ Expired` | 보존 기간 경과. 기본값은 M4에서 확정, 사용자 조정 가능 |
| **모든 예외** | **격리 유지**(NFR-S-4 fail-closed). "잘 모르겠으니 통과"는 없다 |

### 실체화 절차 (`Approved → Materialized`)

1. 대상 경로를 사용자가 지정(기본 = 다운로드 폴더). **덮어쓰기 금지** — 충돌 시 이름 뒤에 번호.
2. **파일명 정규화** — RLO·제어문자·0폭 제거 · 경로 구분자 제거 · Windows 예약 장치명(`CON PRN AUX NUL COM1..9 LPT1..9`) 회피 · 끝의 점·공백 제거 · NTFS ADS 구분자(`:`) 제거 · 길이 상한.
3. 임시 이름으로 쓰고 → `sealed_prefix` + `body` 결합 → **SHA-256 재검증** → 원자적 rename.
4. **OS 격리 표식 부착**([§5](#5-플랫폼별-격리-표식)). **실행 비트는 부여하지 않는다**(Linux 포함).
5. 성공 후에도 **`.beepq`는 보존 기간까지 남긴다**(재실체화·감사용).

> **앱은 실체화한 파일을 열지도, 실행하지도 않는다**(FR-S-9). 제공하는 것은 **"폴더에서 보기"** 뿐이다.

## 5. 플랫폼별 격리 표식

| OS | 방법 | 비고 |
|---|---|---|
| **Windows** | **`IAttachmentExecute`** 우선(Chrome 방식) → 실패 시 **`Zone.Identifier` ADS 직접 기록**(`[ZoneTransfer]` / `ZoneId=3`) | ZoneId 3 = Internet → **SmartScreen** + Office **보호된 보기** 발동. FAT/exFAT 등 **ADS 미지원 볼륨이면 표식 불가** → 그 사실을 사용자에게 표시 |
| **macOS** | `com.apple.quarantine` 확장 속성 — 앱 `Info.plist`에 **`LSFileQuarantineEnabled`** 를 넣어 시스템이 자동 부착하게 하거나, **`qtn_file_apply_to_path`** 로 직접 | Gatekeeper·XProtect 검사 발동 |
| **Linux** | 표준 없음 — **실행 비트 미부여**가 1차. 파일시스템이 지원하면 `user.xdg.origin.url` 확장 속성 부기 | 데스크톱 환경마다 동작이 달라 **보증하지 않는다**(NFR-S-5) |

**공통 규칙**
- 표식을 붙이지 **못한 경우에도 실체화는 진행하되, "OS 보호 표식을 붙이지 못했습니다"를 명시**한다. 조용히 넘어가지 않는다.
- 표식 부착은 **파일을 최종 위치에 쓴 직후**. rename보다 먼저 붙이면 유실될 수 있다.

## 6. 검사 상세

| 검사 | 내용 | 실패 시 |
|---|---|---|
| 무결성 | 수신 SHA-256 = 협상 값 | 폐기 |
| 매직 대조 | `detected_kind` vs `declared_ext` | 경고 표시(차단 아님) |
| 등급 판정 | [§3](#3-위험-등급-판정) — 셋 중 최상위 | — |
| **AMSI**(Windows) | `AmsiInitialize` → `AmsiOpenSession` → **`AmsiScanBuffer`** — **디스크에 최종본을 쓰기 전** 버퍼 검사 | 미설치·미지원 = **`Unavailable`**. "검사됨"으로 표기 금지 |
| 아카이브 구조 | Zip Slip · 압축 폭탄 · 이름 일관성 | 거부(등급 유지, 목록 조회 불가) |
| 이미지 | **`imgdec` 별도 프로세스**로 디코드 → 재인코딩본만 미리보기. SVG 미지원 | 디코드 실패·상한 초과 = 미리보기 없음(파일은 격리 유지) |

> **"검사 통과 = 안전"이라고 절대 표기하지 않는다.** 표시하는 것은 `검사됨(탐지 없음)` / `검사됨(탐지)` / **`검사 안 됨`** 세 가지 사실뿐이다(NFR-S-5).

## 7. 승인 UX — 등급별 마찰

| 등급 | 화면 | 기본 버튼 |
|---|---|---|
| 🟢 데이터 | 1클릭 저장 | 저장 |
| 🟡 아카이브 | "저장만 됩니다. 자동으로 풀지 않습니다" 안내 | 저장 |
| 🟠 능동 문서 | 경고 + "보호된 보기로 열립니다" 안내 | **취소** |
| 🔴 실행형 | **2단계** — 위험 고지 → 명시적 재확인 | **취소** |

**공통**
- 발신자의 **신원 상태**(미검증 / 검증됨 / 지문 대조 완료)를 같은 화면에 표시한다([08](08-adr-0002-discovery-transport.md)). **미검증 발신자의 🔴 파일은 가장 강한 경고.**
- **형식 불일치 경고**는 등급과 별개로 최상단.
- 검사 결과를 **사실 그대로**.
- 🔴은 **기본 버튼이 항상 "취소"** — Enter 연타로 통과되지 않게.

## 8. 열린 질문

1. **격리 보존 기간 기본값** — 디스크 사용량과 재실체화 편의의 절충. M4에서 실사용 감각으로.
2. **격리 폴더 총 용량 상한**과 초과 시 정책(오래된 것부터 삭제 vs 수신 거부).
3. **`sealed_len` 512B**가 충분한지 — M4 착수 시 대표 형식으로 검증.
4. 🔴 재확인 UX의 구체 형태(체크박스 vs 문구 입력) — 과하면 학습된 무시를 부른다.
5. Linux 표식의 현실적 효과 — 데스크톱 환경별 실측 후 문서화.
