## 2. ★ 매트릭스가 알려준 것 — **표에 칸조차 없는 것이 우리 차별화다**

[03 §4](03-competitive-landscape.md)는 **경쟁 제품이 가진 기능**을 열거한 표다. 그래서 표를 다 채우면 **"잘 만든 경쟁 제품"** 이 될 뿐이다. 정작 우리 차별화 넷은 **표에 항목이 없다.**

| 우리 축 | 경쟁 현황 | 근거 |
|---|---|---|
| **수신 파일 무해화 게이트** | **표에 항목 없음 · 조사한 7종 중 0곳** | [04](04-safe-transfer.md) · DR-13 |
| **기록 저장 암호화** | 기록 저장은 **6/7**인데 **암호화하는 곳은 0** | [17](17-adr-0005-history-at-rest.md) · DR-17 |
| **키 인증(TOFU + SAS 육안 대조)** | "AES-256" 표기는 5/7이지만 **키 인증 방식을 문서화한 곳이 없다.** LocalSend의 즉석 TLS는 **MITM을 못 막는다**([03 §6-2](03-competitive-landscape.md)) | [08](08-adr-0002-discovery-transport.md) |
| **런타임 의존 0 · ≤10MB · 유휴 ≤30MB** | **전부 런타임 의존**(.NET·Flutter·Qt·JVM) — 이 축이 통째로 비어 있다 | DR-5 · [03 §6-4](03-competitive-landscape.md) |

여기에 **국내 공백**(제로 컨피그 P2P 메신저 부재 · 20년째 일본산 IPMsg가 대체)과 **Windows ARM64**(1/7)가 더해진다.

> **결론: 입장권은 매트릭스에서 가져오고, 차별화는 매트릭스 밖에서 만든다.** 아래 분류는 이 원칙을 그대로 따른다.

## 4. ★ v1.0 커트라인 추천

> **원칙: 출시 게이트는 "성공 기준 S-1~S-8을 판정할 수 있는 최소 집합"이다.** 그 집합 = **🅐 전부 + 🅑 전부 + 🅒 4건 + 🅓 4건.**

### v1.1로 미루기를 권하는 3건과 이유

| 대상 | 미루는 이유 | 미뤄도 되는 이유 |
|---|---|---|
| **D-5 공유 폴더 pull** | **새 프로토콜 표면**(목록·scope·가상경로 해석)이고 **M4 무해화 게이트 완성 이후**에나 붙는다. fail-closed 경로 해석은 회귀 테스트도 한 벌 더 필요하다 | **파일 전송(push · A-3/C-2)이 이미 입장권을 충족**한다. pull은 "있으면 좋은" 편의다 |
| **D-6 수신자 릴레이** | **TLS 스택 첫 도입**(R-14 · 크기 예산 미검증) + **인터넷으로 나가는 첫 경로**(보안 검토 표면) + 다중 어댑터 팬아웃 | 등급·알림·수신확인(D-1/D-2)이 **v1.0에 있으면 "확실성" 요구의 8할은 채워진다**. 릴레이는 나머지 2할 |
| **C-4 기록 전문 검색** | **블라인드 인덱스 + 한국어 음절 n-gram**([17 §5](17-adr-0005-history-at-rest.md))은 단독으로 큰 작업이고 **기록 저장(A-4)과 분리 가능**하다 | 저장이 되어 있으면 검색은 **뒤에 얹어도 데이터 마이그레이션이 없다**. 보편성도 3/7 |

여기에 **C-5 브로드캐스트**(그룹으로 대체 가능)와 **C-6 상태·타이핑**(프레즌스 트래픽 증가·없어도 성립)까지 미루면:

| | v1 FR(현재) | **v1.0 권고** |
|---|---:|---:|
| P0 | 69 | **≈ 55** |
| P1 | 25 | **≈ 10** |
| **소계** | **94** | **≈ 65** |

> ⚠️ **미루는 것은 "설계"가 아니라 "구현"이다.** ADR-0008/0009는 이미 Accepted이고 ADR-0010도 확정되면 **모델·프로토콜 자리는 v1.0에 함께 넣는다**([24 §7](24-adr-0010-message-priority-notification.md) N-1~N-4 · [20 §7](20-adr-0007-multi-device-identity.md) V1-1~4와 같은 논리). **나중에 넣으면 포맷 변경이고, 지금은 필드다.**

```
M1 발견        ──► 목록에 서로 뜬다
M2 대화·기록   ──► ★ 여기서 이미 "발견 + 암호화 1:1 대화 + 기록"이 된다 = 자체 사용(dogfooding) 시작점
M3 셸·UI      ──► 매일 켜 둘 만해진다 (A-5/A-6/B-6 + D-1~D-4)
M4 전송·무해화 ──► A-3·C-2·B-3 (기업 도입의 결정타)
M5 그룹·마감   ──► C-1 + 스팸 방어 + 2채널 배포 → v1.0
──────────── 출시 ────────────
v1.1          ──► C-4 검색 · C-5 브로드캐스트 · C-6 상태/타이핑 · D-5 공유 폴더 · D-6 수신자 릴레이
v2            ──► D-7 다중 기기 · 전송 릴레이(nexa-beepd) · 캡처/주석 · CLI
```

> **M2 종료 시점이 중요하다** — 그때부터 **우리가 이 프로그램으로 대화할 수 있다.** 자체 사용이 시작되면 우선순위 판단이 추측에서 경험으로 바뀐다. **M2를 앞당기는 것이 이 목록 전체보다 중요하다.**
>
> ★ **08-20 현재 위치** — M2는 종료됐고(M2-5b 08-18) 자체 사용이 실제로 돌고 있다(2-PC·3-신원·CLI 실기). 위 사다리 기준으로 **M4까지 사실상 도달**했고, v1.0 커트라인까지 남은 굵은 것은 **C-2 폴더 전송 · C-3 오프라인 큐 · M5-3 스팸 방어 · S4 유니캐스트(M1-8) · 검사 어댑터/권한 강등(B-3 잔여) · M5-4a 서명·M5-5 24h 누수** 정도다.
>
> ★ **08-21 갱신** — C-3 오프라인 큐 ✅·S4 3-OS 대칭 ✅(E-3 실기만) · **C-2 폴더 전송은 사용자 확정으로 v1.0에서 제외(⏸ — 안정성 확보 후 재검토)**. 남은 굵은 것 = **M5-3 스팸 방어 · 검사 어댑터/권한 강등 잔여 · M5-4a 서명 · M5-5 24h 누수**.
