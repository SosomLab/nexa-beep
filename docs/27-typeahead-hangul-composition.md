# 27 · 타입어헤드 한글 직접 조합 — IME 탈피의 기록 (2026-08-09 확정)

> **상태: ✅ 구현·실증 완료** · 결정자 Sangyong Bae(실기 재현·방향 확정) · 구현 2026-08-09
> 목록(피어 리스트) 타입어헤드에서 **macOS IME를 벗어나 한글 두벌식 조합을 앱이 직접 수행**하게
> 된 배경·실패의 연대기·최종 설계를 남긴다. "왜 표준 IME를 안 쓰는가"에 대한 항구적 답변.
> 관련: [docs/06 관통 원리 "네트워크는 추정 금지, 실측 필수"](06-network-stack.md) — **입력도 같았다.**

---

## 1. 문제 — 무엇이 계속 깨졌나 (실기 재현 4종)

목록 화면의 타입어헤드(이름 접두사 점프)는 "마지막 입력 후 2초가 지나면 초기화"가 규약이다.
영어는 항상 정상이었지만 한글은 **간헐적으로** 다음이 재현됐다(사용자 실기 보고, 08-09):

| # | 재현 절차 | 증상 |
|---|---|---|
| R1 | `bob` → 2초 → 한영 전환 → `김` 입력 | 조합 깨짐(`ㅣㅁ`만 표시 등) |
| R2 | 한영 전환 직후 첫 키 `ㄱ` | **ㄱ 유실**(무시), 이후 자모만 나열 |
| R3 | `김` → 2초 대기(HUD 소멸) → `최` | **"김최"** 로 표시(묵은 김이 살아 돌아옴) |
| R4 | `최`→2초→`김`→2초→`이` 연쇄 | 이전 잔여가 계속 섞임 |

핵심 관찰: **ESC를 누르면 그 다음부터는 정상**(95%+). 즉 ESC는 IME 조합 세션을 정식으로
끝내지만, **2초 타임아웃은 우리 화면만 지울 뿐 IME 세션을 끝내지 못한다**는 것.

## 2. 실패의 연대기 — IME 위에서 보정하려던 5번의 시도

원인 이해를 위해 남긴다. 각 시도는 부분적으로 옳았지만, 근본 원인(세션 소유권)에 닿지 못했다.

| 시도 | 내용 | 결과·실패 이유 |
|---|---|---|
| ① 자모 필터 | `KeyboardInput Character("ㄱ")`을 무조건 버림(조합 중복 가정) | R3의 이중 유입은 줄였으나 **R2를 만들었다** — 한영 전환 첫 키는 IME가 안 붙어 Character가 **유일한** 전달인데 그걸 버림 |
| ② `ime_composing` 가드 | Preedit 활성 중 KeyboardInput 전체 차단 | 조합 **중**의 중복은 해결. 조합 **시작 전** 경합(R2)은 못 봄 |
| ③ stale 접두사 제거 | 타임아웃 시 조합 텍스트를 기억, 이후 `Preedit("김최")`에서 "김"을 벗김 | 논리는 맞고 테스트도 통과했지만, R1·R2로 세션이 이미 꼬인 상태에선 이벤트 형태가 가정과 어긋나 재발 |
| ④ 보류-판정(pending) | 자모 Character를 150ms 보류 → Ime 이벤트가 따라오면 중복 폐기, 아니면 진짜 입력으로 방출 | R2 유실은 해결. 그러나 보류 지연 + 세션 경합 자체는 여전 |
| ⑤ `set_ime_allowed` 토글 | 타임아웃 시 off→on으로 세션 강제 종료 시도 | **macOS가 marked text를 버리지 않음** — 커밋도 취소도 안 되고 세션이 그대로 이어짐(R3 재발 확인) |

**판정**: winit/macOS 경로에서 조합 세션(marked text)의 시작·유지·확정·취소는 전부 OS 소관이고,
앱에는 세션을 끝낼 API가 없다(ESC 키만이 IME에 직접 닿는다). 이벤트 순서(KeyboardInput ↔
Ime::Preedit/Commit)도 상황(포커스 전환·입력 소스 전환)에 따라 달라진다.
→ **앱 레벨 보정으로는 "결정적 동작"을 보장할 수 없다.**

## 3. 설계 전환 — "입력도 실측·직접 제어" (사용자 확정)

사용자 제안("직접 핸들링")을 채택해 **타입어헤드에 한해 IME를 끄고, 키보드가 주는 raw 자모를
앱이 직접 조합**하기로 했다. 근거:

- 타입어헤드는 **검색 입력**이지 문서 입력이 아니다 — 자체 조합이 관례상 허용되는 영역(파일
  탐색기류 선례). 대화 입력은 실제 텍스트이므로 **IME를 그대로 유지**한다.
- IME를 끄면(macOS `set_ime_allowed(false)`) 두벌식 **키보드 레이아웃**이 키를 자모 문자로
  매핑해 `Character("ㄱ")`로 준다 — 세션·preedit·커밋이라는 개념 자체가 사라진다.
- 조합 상태가 **앱 소유**가 되므로: 2초 타임아웃 = 상태 리셋, ESC = 상태 리셋. **그게 전부**다.
  R1~R4가 구조적으로 불가능해진다(잔여 상태가 물리적으로 없음).

이 결정은 프로젝트 관통 원리의 입력판이다: *"OS가 어떻게 해줄 것"이라는 추정 대신, 실측(재현
4종)으로 소유권 경계를 확인하고 경계 안쪽(우리 조합기)으로 문제를 옮겼다.*

## 4. 사용된 개념 — 두벌식 조합 오토마타

구현체: [`crates/nbeep-ui/src/hangul.rs`](../crates/nbeep-ui/src/hangul.rs)

| 개념 | 내용 | 구현 위치 |
|---|---|---|
| 상태 기계 | `Empty → 초성 → 초+중 → 초+중+종` 5상태. 자모 하나가 들어올 때마다 전이하고, 글자 경계를 넘으면 완성 글자를 방출 | [`enum State`](../crates/nbeep-ui/src/hangul.rs) (L103) · [`Composer::feed`](../crates/nbeep-ui/src/hangul.rs) (L160) |
| 음절 합성 | 유니코드 공식 `0xAC00 + 초×588 + 중×28 + 종` | [`fn compose`](../crates/nbeep-ui/src/hangul.rs) (L74) |
| 자모 표 | 초성 19 · 중성 21 · 종성 27(+없음) — 유니코드 순서 = 인덱스 | `CHO`/`JUNG`/`JONG` (L13~26) |
| 겹모음 | ㅗ+ㅏ=ㅘ 등 7종 — 중성 상태에서 결합 시도 | `JUNG_COMPOUND` (L28) |
| 겹받침 | ㄱ+ㅅ=ㄳ 등 11종 — 종성 상태에서 결합 시도 | `JONG_COMPOUND` (L38) |
| **도깨비불** | 받침 있는 글자 뒤에 모음이 오면 받침(겹받침이면 뒤쪽)이 다음 글자의 초성으로 이동: `ㄱㅏㄱ+ㅣ→가기`, `김+ㅊㅗㅣ→김최`, `앉+ㅏ→안자` | `feed`의 `State::Full`+모음 분기 · [`fn jong_split`](../crates/nbeep-ui/src/hangul.rs) (L94) |

재현 케이스는 그대로 테스트로 고정했다: `basic_syllables`(김·최·한글·값) ·
`dokkaebi_final_moves_to_next_cho`(김최·가기·안자) · **`user_repro_cases_are_deterministic`**
(R1~R4의 리셋 결정성) · `backspace_is_jamo_wise_while_composing` · `non_jamo_flushes_and_passes_through`.

## 5. 구현 지도 — 데이터 흐름과 소스 위치

```
[키보드]                          (목록 모드: IME OFF)
   │  KeyboardInput Character('ㄱ')      ← 두벌식 레이아웃이 키→자모 매핑
   ▼
bin main.rs — 라우팅
   ├─ 목록 모드 판정(list_mode) → 자모 즉시 route    main.rs L1990
   ├─ (대화 등 IME ON 창) 자모 보류-판정 유지         main.rs L815 flush_pending_jamo
   └─ 대화↔목록 전환 시 IME 토글                     main.rs L823 set_main_ime
        · 주 창 생성: set_ime_allowed(false)         main.rs L1610
        · 대화 진입: true (2경로 L1288·L1687) · 목록 복귀: false (L1405)
   ▼
peer_list.rs — 목록 위젯
   ├─ Char → typeahead.push(c)                       peer_list.rs L411
   ├─ ↑↓ = 접두사 순환 + touch(타임아웃 유지)         peer_list.rs L344·356
   ├─ ESC = 즉시 초기화 + HUD 숨김                    peer_list.rs L373
   └─ ~200ms 틱 → typeahead_tick(타임아웃 판정)       peer_list.rs L170 (bin L1722에서 호출)
   ▼
typeahead.rs — 버퍼 + 조합기 소유
   ├─ push: 자모→Composer.feed(완성 글자만 buf에)     typeahead.rs L110
   ├─ composing() = buf + Composer.preview → HUD      typeahead.rs L56
   ├─ backspace: 조합 중=자모 단위, 아니면 글자 단위   typeahead.rs L141
   └─ tick/clear: buf.clear + Composer.reset = 끝     typeahead.rs L169·101
   ▼
hangul.rs — 두벌식 오토마타(§4)
```

레거시 IME 경로(`set_preedit`/stale)는 **대화 창 호환용으로만** 남아 있다 — 목록은 타지 않는다.

## 6. 최종 동작 모델 — 불변식

1. **목록 모드에서 IME 세션은 존재하지 않는다** → "묵은 조합" 유형의 버그는 정의상 불가능.
2. 조합 상태의 유일한 소유자는 `hangul::Composer`(앱) — 타임아웃·ESC·전환 시 `reset()` 하나로
   완전 초기화(결정적).
3. HUD 표시 = `buf(확정) + preview(조합 중)` — 입력 즉시 반영, 지연·보류 없음.
4. 대화 입력은 IME 유지(실제 텍스트) — 목록↔대화 전환이 IME on/off 경계.
5. 타임아웃(기본 2000ms · 설정 `ui.typeahead_timeout`) 기준은 **마지막 입력/순환 활동**이며,
   ↑↓ 순환은 `touch`로 유지된다.

## 7. 경계·후속

- **다른 플랫폼**: Windows/Linux에서 IME off 시 키가 자모로 오는지 **실측 필요**(D-8 계열).
  완성 음절이 그대로 오는 경우도 `feed`의 비자모 통과로 동작하지만, 자모 경로 검증이 우선.
- 세벌식 등 다른 자판은 미지원(두벌식 전제) — 요구 발생 시 레이아웃별 매핑 계층 추가.
- 대화 입력의 IME 경합(보류-판정 ④)은 그대로 유효 — 문서 입력은 IME가 정답이므로 유지.
- 설정 검색(TextBox)은 아직 IME 경로다 — 같은 증상이 관찰되면 조합기 재사용을 검토.

> **교훈 한 줄**: 소유권이 밖(OS)에 있는 상태를 안(앱)에서 보정하는 시도는 5번 모두 부분 성공에
> 그쳤다. 상태의 소유권을 앱으로 옮기자 문제 자체가 소멸했다.
