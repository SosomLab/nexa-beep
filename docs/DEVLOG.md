- **ADR-0007 다중 기기 신원 — UserId 1:M PeerId(D-20 — 사용자 제안 · DR-18 개정)**: [20 ADR-0007](20-adr-0007-multi-device-identity.md) — 질문은 *"여러 PC를 한 사용자로 묶어 일반 메신저처럼 쓰려면 **서버 모드**면 되나"* 였고 **답은 아니오**였다. ① **릴레이는 "닿는가"를 풀 뿐 "같은 사람인가"·"이력 공유"를 풀지 않는다** — `PeerId`가 기기 자체 생성 키라 릴레이는 `Locator`만 바꾸고([09](09-adr-0003-transport-abstraction.md)), 릴레이가 평문을 못 보므로 **서버 보관은 구조적으로 불가**하며 저장 마스터 키가 기기 키 파생이라 기록을 복사해도 못 연다([17 §8](17-adr-0005-history-at-rest.md)). 릴레이의 기여는 **오프라인 큐** 하나 — 필요조건이지 충분조건이 아니다 ② **사용자 제안(`UserId` 1:M `PeerId` + 그룹처럼 팬아웃)이 맞는 방향**이고 **팬아웃 재사용은 실제로 성립**한다 — FR-G-3이 이미 구성원별 팬아웃이라 `수신자 = PeerId 집합`으로 일반화하면 1:1·그룹·다중 기기가 **같은 함수**를 탄다 ③ ⚠️ **핵심 판단: "그룹처럼"은 전송 계층에서만 참이다.** 그룹은 **로컬 개념**(합의 불필요)이지만 `UserId`는 **상대가 믿어야 하는 주장**이라, 검증이 없으면 **공격자가 자기 PeerId를 피해자의 UserId에 속한다고 발표해 읽기 권한을 스스로 부여**할 수 있다 → **`UserId` 키가 기기 목록을 서명**하고 수신 측이 **Noise로 확정한 기기 키가 그 목록에 있는지** 검증(양방향 소유 증명). 폐기는 **단조 version + 본 최대값 기억 + 묘비 보존**으로 롤백 차단, **전파 즉시성은 보장 안 함**을 명시 ④ **부수 이득** — TOFU 대상이 `UserId`로 올라가 **재설치·기기 교체가 사칭 경고를 띄우지 않는다**(현재 TOFU의 아픈 점 해소) ⑤ **팬아웃으로 안 풀리는 것 셋** — 자기 기기에 **사본(sender copy)** 필요 · **파일 승인 상태는 기기 간 공유하지 않는다**(fail-closed 격리소가 기기마다) · **과거 이력은 별개 설계**(E2E 백업) ⑥ **DR-18을 폐기하지 않고 선택 계층으로 얹었다** — 기본은 노드 모델 그대로, 묶기는 **SAS 1회 대조**(계정·서버 주소 없음 → DR-1 무손상) ⑦ **가장 어려운 열린 질문 = `UserId` 개인키 보관**(복제 시 기기 1대 탈취 = 신원 전체 + 임의 기기 무한 추가 / 주 기기 전용은 분실 시 추가 불가) → **Q-1 사용자 확정 필요 · R-10 등록** ⑧ **v1 제약 4건을 지금 반영** — `UserId` 타입 자리(스레드·기록·차단 키를 `UserId`로) · 발신 경로 집합 일반화 · `sender_device` 필드 · **저장 마스터 키 한 겹 래핑**. 특히 V1-4로 [17 §3](17-adr-0005-history-at-rest.md)을 **무작위 마스터 키 + 래핑 키** 구조로 실제 개정했다(직접 파생이면 v2에서 전 기록 재암호화). DR-20 신설 · DR-18 개정 · FR-D-14·M-8/9·G-6·S-28~33 추가 · R-10/R-11. 상세 [journal/2026-08-08.md](journal/2026-08-08.md).
- **ADR-0006 수동 엔드포인트 등록 제안(D-19 — 사용자 요청)**: [19 ADR-0006](19-adr-0006-manual-endpoint.md) — *"public IP가 있다면 직접 IP를 등록해 대화 상태로 추가"*. ① **LAN 내 발견 실패(S6)와 LAN 밖 원거리 연결을 하나의 기능으로** 덮었다 — 주소를 안 뒤의 과정(TCP→Noise→TOFU)이 100% 같기 때문 ② **새 `Transport`를 만들지 않고 `Locator::Manual{host,port}` 추가** — 별도 전송으로 만들면 세션·재연결·백프레셔가 두 벌이 된다 ③ ⚠️ **핵심 판단: LAN을 벗어나면 위협 모델이 달라진다.** 지금까지 설계는 **"같은 물리 네트워크"라는 암묵적 신뢰 경계**에 기대고 있었는데 공인 IP 연결은 그걸 없앤다(MITM 범위가 경로 전체로, 스캔 노출이 인터넷 전체로, 상대를 확인할 사회적 맥락이 사라짐) → **원격 신뢰 등급**을 별도로 두고 **SAS 대조 전까지 파일 수신 차단**(텍스트만), **서브넷 밖 인바운드는 "요청 대기"**(자동 등록 금지), 인바운드 **속도 제한 + 실패 시 침묵**(포트 스캔 무응답), UI에 **원격 연결임을 항상 표시** ④ **DR-8/DR-18이 여기서 또 값을 했다** — 주소가 아니라 지문이 신원이라 **사무실에서 LAN으로 알던 노드를 집에서 공인 IP로 등록하면 자동 병합**되고 대화 스레드가 이어진다. 경로 우선순위 **LocalDirect > Manual > Relay** ⑤ **NAT 홀펀칭·STUN/TURN·UPnP는 하지 않는다**(DR-5·보안 — 자동 포트 개방은 위험) → **양쪽 다 NAT 뒤면 여전히 릴레이 몫**. 수동 등록은 릴레이를 **대체하지 않고 앞당긴다** ⑥ DR-19 · FR-D-11~13 · FR-S-24~27 추가 · M5-3b 삽입 · [18](18-build-and-test.md)에 원격 연결 회귀 추가. 상세 [journal/2026-08-08.md](journal/2026-08-08.md).
- **관통 원리 명문화 + 노드 모델 확정(DR-18 — 사용자 확정)**: ① 사용자가 *"봉투만 본다는 표현이 전체 보안을 관통하는 직관"* 이라고 짚어, 흩어져 있던 같은 패턴을 [10 §0](10-decision-record.md)에 **계층별 봉투/내용 대조표**로 격상 — 릴레이(목적지만)·발견 패킷(존재만·미검증 힌트)·전송(평문 안 봄)·`.beepq`(메타만)·저장 세그먼트(헤더만)·검색 인덱스(HMAC 토큰만)·계측 레저(횟수만)·로그(상태만). **새 기능 설계의 첫 질문 = "이 계층의 봉투는 무엇인가"** 로 규약화하고 [00 §3](00-vision.md)·CLAUDE.md에 반영 ② **DR-18 노드 모델 확정** — *"PC마다 다른 노드로 보는 게 가장 단순한 구조"*. **"사용자" 개념을 도입하지 않는다** — 신원·TOFU 핀·기록·그룹 구성원·계측이 전부 노드 단위. - **ADR-0005 기록 저장 암호화 제안(D-18 — Proposed · 사용자 요청)**: [17 ADR-0005](17-adr-0005-history-at-rest.md) — 전송 암호화와 **다른 문제**다. 전송 키는 매번 새로 만들지만 **저장 키는 계속 어딘가 있어야** 하고, **DR-1 때문에 비밀번호를 물을 수 없다.** ① **키 = 기기 키 파생(입력 0) 기본 + OS 보안 저장소·사용자 암호 선택 승격**. 승격 전환은 **마스터 키 재래핑만** 하므로 데이터 재암호화 불필요 ② **정직한 위협 모델 H-1~H-8** — 기본 구성은 **우발적·수동적 노출(동기화 폴더에 딸려 감·백업·폴더째 전달·포렌식 문자열 스캔)을 확실히 막고**, **기기 탈취(H-5)는 못 막는다**. - **ADR-0001 기술 스택 제안(D-6 — Proposed)**: [07 ADR-0001](07-adr-0001-stack.md) — 결정 3개(언어·렌더링 백엔드·플랫폼 계층)를 후보 비교로 정리. **① Rust**(런타임 0·메모리 안전·4타깃 크로스·퍼미시브 생태계 — Go/.NET은 NFR-B-3/B-5에서 즉시 탈락, C++는 "느려서"가 아니라 **"안전하지 않아서"** 탈락: 신뢰 못 할 패킷·이미지·아카이브를 직접 파싱하므로 메모리 안전이 곧 보안 요구 R-5) **② 자체 CPU 래스터라이저 + 자체 텍스트 스택**(플랫폼 네이티브 2D는 글자 모양이 갈려 NFR-C-1/S-7 위반, GPU는 상주 메모리·크기로 NFR-B-1/B-3 위반) **③ 플랫폼 계층은 창·입력·IME·폰트·DPI만 담당하는 얇은 경계** — 되돌리기 쉬운 결정이라 P2(퍼미시브 라이브러리)로 시작 후 실측에 따라 P1(직접 구현)으로 좁힘. **확정 전 SP-1 스파이크 필수**(빈 창 4타깃 ≤3MB·RSS ≤15MB·한글 IME·60fps·의존성 라이선스 전수 — R-8). 상태 **Proposed**, 사용자 확정 대기. 상세 [journal/2026-08-08.md](journal/2026-08-08.md).
