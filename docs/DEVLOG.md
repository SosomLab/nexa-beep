- **ADR-0007 다중 기기 신원 — UserId 1:M PeerId(D-20 — 사용자 제안 · DR-18 개정)**: [20 ADR-0007](20-adr-0007-multi-device-identity.md) — 질문은 *"여러 PC를 한 사용자로 묶어 일반 메신저처럼 쓰려면 **서버 모드**면 되나"* 였고 **답은 아니오**였다. ① **릴레이는 "닿는가"를 풀 뿐 "같은 사람인가"·"이력 공유"를 풀지 않는다** — `PeerId`가 기기 자체 생성 키라 릴레이는 `Locator`만 바꾸고([09](09-adr-0003-transport-abstraction.md)), 릴레이가 평문을 못 보므로 **서버 보관은 구조적으로 불가**하며 저장 마스터 키가 기기 키 파생이라 기록을 복사해도 못 연다([17 §8](17-adr-0005-history-at-rest.md)). 릴레이의 기여는 **오프라인 큐** 하나 — 필요조건이지 충분조건이 아니다 ② **사용자 제안(`UserId` 1:M `PeerId` + 그룹처럼 팬아웃)이 맞는 방향**이고 **팬아웃 재사용은 실제로 성립**한다 — FR-G-3이 이미 구성원별 팬아웃이라 `수신자 = PeerId 집합`으로 일반화하면 1:1·그룹·다중 기기가 **같은 함수**를 탄다 ③ ⚠️ **핵심 판단: "그룹처럼"은 전송 계층에서만 참이다.** 그룹은 **로컬 개념**(합의 불필요)이지만 `UserId`는 **상대가 믿어야 하는 주장**이라, 검증이 없으면 **공격자가 자기 PeerId를 피해자의 UserId에 속한다고 발표해 읽기 권한을 스스로 부여**할 수 있다 → **`UserId` 키가 기기 목록을 서명**하고 수신 측이 **Noise로 확정한 기기 키가 그 목록에 있는지** 검증(양방향 소유 증명). 폐기는 **단조 version + 본 최대값 기억 + 묘비 보존**으로 롤백 차단, **전파 즉시성은 보장 안 함**을 명시 ④ **부수 이득** — TOFU 대상이 `UserId`로 올라가 **재설치·기기 교체가 사칭 경고를 띄우지 않는다**(현재 TOFU의 아픈 점 해소) ⑤ **팬아웃으로 안 풀리는 것 셋** — 자기 기기에 **사본(sender copy)** 필요 · **파일 승인 상태는 기기 간 공유하지 않는다**(fail-closed 격리소가 기기마다) · **과거 이력은 별개 설계**(E2E 백업) ⑥ **DR-18을 폐기하지 않고 선택 계층으로 얹었다** — 기본은 노드 모델 그대로, 묶기는 **SAS 1회 대조**(계정·서버 주소 없음 → DR-1 무손상) ⑦ **가장 어려운 열린 질문 = `UserId` 개인키 보관**(복제 시 기기 1대 탈취 = 신원 전체 + 임의 기기 무한 추가 / 주 기기 전용은 분실 시 추가 불가) → **Q-1 사용자 확정 필요 · R-10 등록** ⑧ **v1 제약 4건을 지금 반영** — `UserId` 타입 자리(스레드·기록·차단 키를 `UserId`로) · 발신 경로 집합 일반화 · `sender_device` 필드 · **저장 마스터 키 한 겹 래핑**. 특히 V1-4로 [17 §3](17-adr-0005-history-at-rest.md)을 **무작위 마스터 키 + 래핑 키** 구조로 실제 개정했다(직접 파생이면 v2에서 전 기록 재암호화). - **ADR-0005 기록 저장 암호화 제안(D-18 — Proposed · 사용자 요청)**: [17 ADR-0005](17-adr-0005-history-at-rest.md) — 전송 암호화와 **다른 문제**다. 전송 키는 매번 새로 만들지만 **저장 키는 계속 어딘가 있어야** 하고, **DR-1 때문에 비밀번호를 물을 수 없다.** ① **키 = 기기 키 파생(입력 0) 기본 + OS 보안 저장소·사용자 암호 선택 승격**. 승격 전환은 **마스터 키 재래핑만** 하므로 데이터 재암호화 불필요 ② **정직한 위협 모델 H-1~H-8** — 기본 구성은 **우발적·수동적 노출(동기화 폴더에 딸려 감·백업·폴더째 전달·포렌식 문자열 스캔)을 확실히 막고**, **기기 탈취(H-5)는 못 막는다**. "키가 옆에 있으니 무의미하다"는 반박에는 **실무 유출의 대부분이 H-1/H-4**라는 근거로 답하되 과장하지 않고 표를 UI에도 노출 ③ **가장 어려운 부분은 전문 검색** — 평문 인덱스를 만들면 암호화가 무의미해진다(인덱스는 내용의 사본). **블라인드 인덱스**(HMAC 토큰) + **한국어 음절 n-gram**(형태소 사전은 수 MB라 DR-5 위반) + **후보 세그먼트 복호 정밀 대조**. 누출되는 것(토큰 빈도·문서 길이)도 명시 ④ **삭제 = 크립토 셰레딩** — SSD에서 덮어쓰기는 원본 블록에 닿는다고 보장할 수 없으므로 **데이터 대신 키를 지운다**. 그래서 대화별·세그먼트별 데이터 키를 파생하도록 설계 ⑤ **외부 노출 방지 9규칙** — 전송 함수 자체를 안 만듦 · **클라우드 동기화 폴더 감지 경고** · 크래시 덤프 최소화 · **zeroize**(단 T0 무권한에서 스왑 방지는 보장 불가라고 명시) · 임시 폴더 평문 금지(썸네일 포함) ⑥ **릴레이가 생겨도 기록은 클라이언트에만** — 서버가 평문을 못 보므로(FR-R-3) 구조적으로 서버 보관이 불가능하다. **기기 이전·다중 기기 동기화는 v1 범위 밖**이며 이 한계를 지금 명시하지 않으면 "기기 바꿨더니 대화가 없어졌다"가 결함으로 접수된다. - **ADR-0003 전송 계층 추상화 제안(D-9 — Proposed)**: [09 ADR-0003](09-adr-0003-transport-abstraction.md) — DR-8의 "2모드 전제"를 **4계층 경계**(App / Session / Transport / Link)로 구체화. 핵심 인식 = 나중에 전송을 끼워 넣을 때 발목을 잡는 건 전송 코드가 아니라 **상위로 새어 나간 전송 세부사항**(IP가 App 자료구조에 있음 · 연결=대화로 묶임 · 암호화가 전송 안에 있음 · 오프라인 큐가 로컬 전제)이라는 것. 타입 4종(`PeerId`/`Locator`/`Link`/`Session`)과 **누수 금지 규칙 5개**(모듈 가시성으로 강제)를 정의. **부수 효과가 더 컸다** — `InMemoryTransport`로 세션·대화·그룹·무해화를 **네트워크 없이 단위 테스트**할 수 있고, 이건 4타깃 CI에서 멀티캐스트를 쏠 수 없다는 현실을 생각하면 미래 투자가 아니라 **당장 필요한 것**. 릴레이가 보는 것/못 보는 것을 표로 명시(**메타데이터는 본다** — 숨기지 않음). 상세 [journal/2026-08-08.md](journal/2026-08-08.md).
- **ADR-0002 디스커버리·전송·암호 제안(D-7 — Proposed)**: [08 ADR-0002](08-adr-0002-discovery-transport.md) — ① **발견 = 자체 컴팩트 UDP**(≤512B, S1~S5 **단일 와이어 포맷**). mDNS 탈락 사유는 "표준이 아니어서 좋다"가 아니라 **폴백 사다리가 이미 필수라 어차피 자체 포맷이 필요**하고 mDNS를 얹으면 포맷·병합 로직만 하나 더 는다는 것(+ 시스템 응답기 유무·5353 바인딩 경쟁) ② **발견 패킷은 인증하지 않는다** — 서명을 넣어도 사칭을 못 막으므로 발견 결과를 **"미검증 힌트"** 로만 취급하고 **신원은 핸드셰이크로만 확정**. 패킷이 작아지고 보안 주장이 정직해진다(NFR-S-5) ③ **세션 = TCP 다중화**(제어/대화/파일 논리 스트림·프레임 상한·백프레셔). QUIC은 크기(NFR-B-3) 때문에 v1 미채택 ④ **암호 = Noise_XX**(X25519/ChaCha20-Poly1305/BLAKE2s) — 사전 등록이 없어 상대 키를 미리 알 수 없으므로 `IK` 계열은 첫 접촉에 쓸 수 없다. **정적 공개키 = 신원**이 DR-8·FR-D-6·FR-S-2를 한 번에 만족 ⑤ **TOFU** — 지문 변경 시 **기본 차단** + 이력 보존, 같은 지문·다른 IP는 경로만 갱신, 같은 이름·다른 지문은 **다른 사람**. Noise 핸드셰이크 해시에서 **SAS** 파생(선택 기능 — 강제하면 DR-1이 깨진다) ⑥ **포터블 신원 파일은 USB로 옮기면 신원도 따라간다**는 성질을 장점이자 위험으로 명시. **타이밍 파라미터 6종은 D-8 실측 후 확정**. 상세 [journal/2026-08-08.md](journal/2026-08-08.md).
