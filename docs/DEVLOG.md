## 2026-08-08

- **ADR-0002 디스커버리·전송·암호 제안(D-7 — Proposed)**: [08 ADR-0002](08-adr-0002-discovery-transport.md) — ① **발견 = 자체 컴팩트 UDP**(≤512B, S1~S5 **단일 와이어 포맷**). mDNS 탈락 사유는 "표준이 아니어서 좋다"가 아니라 **폴백 사다리가 이미 필수라 어차피 자체 포맷이 필요**하고 mDNS를 얹으면 포맷·병합 로직만 하나 더 는다는 것(+ 시스템 응답기 유무·5353 바인딩 경쟁) ② **발견 패킷은 인증하지 않는다** — 서명을 넣어도 사칭을 못 막으므로 발견 결과를 **"미검증 힌트"** 로만 취급하고 **신원은 핸드셰이크로만 확정**. 패킷이 작아지고 보안 주장이 정직해진다(NFR-S-5) ③ **세션 = TCP 다중화**(제어/대화/파일 논리 스트림·프레임 상한·백프레셔). QUIC은 크기(NFR-B-3) 때문에 v1 미채택 ④ **암호 = Noise_XX**(X25519/ChaCha20-Poly1305/BLAKE2s) — 사전 등록이 없어 상대 키를 미리 알 수 없으므로 `IK` 계열은 첫 접촉에 쓸 수 없다. **정적 공개키 = 신원**이 DR-8·FR-D-6·FR-S-2를 한 번에 만족 ⑤ **TOFU** — 지문 변경 시 **기본 차단** + 이력 보존, 같은 지문·다른 IP는 경로만 갱신, 같은 이름·다른 지문은 **다른 사람**. Noise 핸드셰이크 해시에서 **SAS** 파생(선택 기능 — 강제하면 DR-1이 깨진다) ⑥ **포터블 신원 파일은 USB로 옮기면 신원도 따라간다**는 성질을 장점이자 위험으로 명시. **타이밍 파라미터 6종은 D-8 실측 후 확정**. 상세 [journal/2026-08-08.md](journal/2026-08-08.md).
- **ADR-0001 기술 스택 제안(D-6 — Proposed)**: [07 ADR-0001](07-adr-0001-stack.md) — 결정 3개(언어·렌더링 백엔드·플랫폼 계층)를 후보 비교로 정리. **① Rust**(런타임 0·메모리 안전·4타깃 크로스·퍼미시브 생태계 — Go/.NET은 NFR-B-3/B-5에서 즉시 탈락, C++는 "느려서"가 아니라 **"안전하지 않아서"** 탈락: 신뢰 못 할 패킷·이미지·아카이브를 직접 파싱하므로 메모리 안전이 곧 보안 요구 R-5) **② 자체 CPU 래스터라이저 + 자체 텍스트 스택**(플랫폼 네이티브 2D는 글자 모양이 갈려 NFR-C-1/S-7 위반, GPU는 상주 메모리·크기로 NFR-B-1/B-3 위반) **③ 플랫폼 계층은 창·입력·IME·폰트·DPI만 담당하는 얇은 경계** — 되돌리기 쉬운 결정이라 P2(퍼미시브 라이브러리)로 시작 후 실측에 따라 P1(직접 구현)으로 좁힘. **확정 전 SP-1 스파이크 필수**(빈 창 4타깃 ≤3MB·RSS ≤15MB·한글 IME·60fps·의존성 라이선스 전수 — R-8). 상태 **Proposed**, 사용자 확정 대기. 상세 [journal/2026-08-08.md](journal/2026-08-08.md).
- **비전·요구사항 확정(D-4/D-5)**: [00 비전](00-vision.md) — 문제 정의(옆자리 파일 전송조차 계정·서버·인터넷을 요구하는 현실)·경쟁 좌표표·**성공 기준 S-1~8**(전부 측정 가능한 것만)·**정직하게 어려운 것 V-1~6**·하지 않는 것 6종·대상 사용자 5종. 이어 [05 요구사항](05-requirements.md) — **FR 57건**(발견10·메시징7·그룹5·전송7·보안17·UI8·플랫폼6·릴레이4)·**NFR-B-1~12 예산 게이트 수치 확정**(유휴 RSS ≤30MB·산출물 ≤10MB/타깃·**런타임 의존 0**·24h 누수 RSS ≤2MB·핸들 증가 0·발견 ≤3s P95·전송 링크속도 70%)·제약 C-1~6·**리스크 R-1~9**·수용기준 매핑. B-1/B-3은 스택 의존이라 **잠정 확정 → M0 게이트 실측에서 재확인**(R-8)으로 명시. 상세 [journal/2026-08-08.md](journal/2026-08-08.md).
- **네트워크 스택 L1~L4 저수준 설계(사용자 요청)**: [06 네트워크 스택](06-network-stack.md) 작성 — 계층별 역할(L1 링크 상태 **구독**·L2 이웃 테이블·L3 인터페이스별 멀티캐스트/브로드캐스트/링크로컬·L4 UDP+TCP), **발견 폴백 사다리 S1~S6**(IPv6 멀티캐스트→IPv4 멀티캐스트→브로드캐스트→**ARP/NDP 유니캐스트**→스캔→수동/릴레이), 소켓 옵션 크로스플랫폼 함정표, **실측 항목 E-1~E-9**. 핵심 판단 = **L2 원시 소켓은 권한·드라이버(Windows Npcap)가 필요해 DR-1·DR-4를 깬다** → **능력 등급 T0/T1/T2**로 분리하고 **T0(무권한)이 완전한 제품**임을 못 박음(DR-14). 상세 [journal/2026-08-08.md](journal/2026-08-08.md).
- **안전 송수신 설계(사용자 요청)**: [04 안전 송수신](04-safe-transfer.md) 작성 — 페이로드 3종(Text/Image/File) 정의 + **수신 파일 무해화 4단계 게이트**(협상 → `.beepq` 격리[**헤더 봉인**·콘텐츠주소 파일명·실행권한 없음·OS 격리표식] → 검사[SHA-256·매직 대조·위험등급 4단계·**AMSI**] → **승인 실체화**[복원 후에도 MotW/quarantine 유지·앱은 실행 API 미사용]). 업계 표준 5종 정리(MotW·Gatekeeper 격리·AMSI·CDR·디팽잉)하고 **헤더 변조 단독으로는 불충분**함을 명시(Windows는 확장자로 실행 결정, `.bat`/`.ps1`/`.lnk`는 매직바이트 없음) → 다층 방어로 설계(DR-13).
- **경쟁 전수 조사 + 핵심 결정 12건 확정(사용자 확정 연속)**: [03 경쟁 지형](03-competitive-landscape.md) 작성 — 국외 25종·국내 12종 **총 37종**을 4계층(직접경쟁/서버형/인접/P2P보안)으로 목록화하고 **23기능 × 7제품 매트릭스**로 "인기 기능" 집계(7/7 = 자동발견·1:1메시지·파일전송·트레이알림·다국어, 6/7 = 대화기록). 도출 4건 — 국내 제로컨피그 P2P 메신저 **부재**(일본산 IPMsg가 대체) · 현대적 크로스플랫폼 2종은 **전부 런타임 의존**(크기·메모리 축 공백) · **제로컨피그↔암호화 충돌**(TOFU 3안) · **클라이언트 격리로 멀티캐스트 차단**(다단 발견 필수). 이어 [10 DR-1~12](10-decision-record.md) 확정 — 4타깃 크로스플랫폼(Win ARM64 포함)·설치본+포터블·예산 게이트·**자체 렌더링 커스텀 컨트롤**·**E2E 암호화**·**전송 2모드 추상화**(서버리스 기본/릴레이 선택)·별도 저장소 `nexa-beepd`·**PolyForm NC**(nexa-dir2 동일·의존성 퍼미시브 온리). 상세 [journal/2026-08-08.md](journal/2026-08-08.md).
