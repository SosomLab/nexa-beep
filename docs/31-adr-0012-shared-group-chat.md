# 31 · ADR-0012 — 공유 그룹 채팅(진짜 그룹): 한 방에서 함께 대화 (📐 Proposed · 2026-08-13)

> **상태: 📐 Proposed — 사용자 확정 대기(D-28).** 방향은 사용자 확정(08-13):
> *"그룹창에서 구성원이 함께 대화를 할 수 있는 방식"* — 카카오톡류 단일 방(발신자
> 아바타·이름 라벨 + 전원의 메시지가 한 스레드에). FR-G-5를 v2에서 **v1.5로 승격**하는
> 설계다. 로컬 그룹(동보 전송 · M5-1 기반 커밋)은 이 설계의 **전송 기반**으로 재사용된다.

## 1. 목표와 비목표

**목표** — 구성원 전원이 **같은 방**을 본다: 같은 그룹명, 같은 구성원 목록, 서로의
메시지(발신자 라벨·아바타 포함), 답장이 방으로 모임.

**비목표(v1.5에서 안 한다)** —

- 서버·릴레이(DR-8 — v1은 로컬 직접만). 방은 **구성원 간 직접 연결의 합**이다.
- MLS급 그룹 키 합의 — LAN 규모(수십 명)에서는 **pairwise(1:1 Noise) 팬아웃**이면
  충분하고(Signal 초기 그룹과 같은 원리) E2E 보증이 기존과 동일하다(DR-7 유지).
- 오프라인 이력 완전 동기(참가 전 이력 공유) — 후속 단계(§8 G4)로 분리.
- 다중 기기 신원(DR-20)과의 결합 — v2에서 `UserId` 상승과 함께.

## 2. 핵심 결정 (제안)

| # | 결정 | 근거 |
|---|---|---|
| G-1 | **소유자(생성자) 모델** — 그룹의 진실은 소유자가 서명한 **roster**(명부) | 서버 없는 LAN에서 멤버십 합의의 최소 형태. DR-20(기기 목록 서명)과 같은 문법이라 설계 재사용 |
| G-2 | **GroupUid = 소유자 PeerId ‖ 로컬 일련 ‖ 생성 시각 해시** — 전역 유일·위조 시 서명 불일치 | 로컬 GroupId(u32)와 달리 **상대가 믿어야 하는 식별자**라 소유자 키에 묶는다 |
| G-3 | **암호화 = 기존 1:1 Noise 세션 위 팬아웃**(pairwise) — 그룹 키 없음 | E2E 불변(릴레이도 없음) · 구현 비용 최소 · N≤수십에서 O(N) 송신은 LAN에서 무시 가능 |
| G-4 | **참여는 초대 수락제** — roster에 올라도 **내가 수락해야** 내 화면에 방이 생긴다 | 무단 편입 금지(스팸·프라이버시 — R-4 결). 로컬 그룹(동보)이 "상대 모르게"인 것과 정반대 계약임을 명시 |
| G-5 | **순서 = 발신자별 seq + 도착순 병합**(전역 순서 합의 없음) | 서버리스에서 전역 순서는 비용>효용. 시각 표시로 충분(메신저 관례) |
| G-6 | **멤버십 변경은 소유자만**(v1.5) — 추가·제외·개명 = 새 roster 버전 서명·배포 | 대등 편집은 병합 충돌 해소가 필요(v2). 탈퇴는 누구나(소유자에게 통지 → roster 갱신) |
| G-7 | **와이어 = `StreamId::Group`(신설) · 전방 호환**(미지 종류 무시) | 기존 Chat/File/Control과 분리 — 봉투 원리(그룹 프레임은 그룹 일만) |

## 3. 데이터 모델

```text
GroupUid   = H(owner_peer_id ‖ local_seq ‖ created_unix)   // 32B — 전역 식별
Roster v N = { group_uid, name, owner, members: [PeerId], version: u64 }
             + sig = Sign(owner_identity_key, encode(Roster))
```

- **소유자 서명이 명부의 진실** — 수신자는 소유자 PeerId(= TOFU 핀 신뢰 축)의 키로
  검증한다. 소유자를 핀했다면 명부 위조는 곧 서명 실패다.
- roster `version` 단조 증가 — **낮은 버전은 무시**(구버전 재생 방지 · DR-20 폐기
  경쟁과 같은 규칙).
- 저장: 내 그룹(소유·참여 모두) = `groups.seg` v2 레코드 확장(기존 로컬 그룹과 공존 —
  `kind: Local | Shared{uid, owner, version, sig}`).

## 4. 프로토콜 (StreamId::Group)

| 메시지 | 방향 | 내용 |
|---|---|---|
| `Invite{roster}` | 소유자 → 신규 구성원 | 초대장 = 서명된 roster 전체. 수신 UI는 **수락/거절 카드** 표시(G-4) |
| `Accept{group_uid}` / `Decline{group_uid}` | 구성원 → 소유자 | 수락 시 소유자가 roster에 "확정" 표시 후 재배포(선택 — v1.5는 낙관 처리 가능) |
| `Roster{roster}` | 소유자 → 전 구성원 | 멤버십·이름 변경 배포(version 증가). 제외된 구성원에게도 마지막 1회(방 닫힘 표시) |
| `Msg{group_uid, sender_seq, body}` | 발신자 → 전 구성원 | 본문. **발신자가 전 구성원에게 직접 팬아웃**(자기 세션으로). 수신자는 roster에 있는 발신자만 수용(fail-closed) |
| `Leave{group_uid}` | 구성원 → 소유자 | 탈퇴 통지 → roster 갱신 배포 |

- **미연결 구성원** — 발신 시 세션 없는 구성원은 자동 연결 후 이어 전달(M5-1 기반
  `pending_group_sends` 그대로). 끝내 실패 = 그 구성원만 미전달 표시(FR-G-4).
- **소유자 오프라인** — 대화는 계속된다(메시지는 P2P 직접). 멤버십 변경만 소유자
  복귀 대기. 이 비대칭은 UI에 명시(§6).
- **재동기 = 발신자 보관 모델**(★ 사용자 확정 08-13 — "보관의 주체는 송신자"):
  **내가 보낸 메시지는 내가 보관**하고, 미전달 구성원이 접속(세션 성립)하면 **발신자가
  밀어준다**(push — 수신자 요청 불필요 · 기존 `pending_group_sends` 자동 연결-후-전달
  패턴의 확장). 자기 메시지의 진실은 자기에게 있어 위조·중복 문제가 없고, 발신자
  오프라인이면 그 발신자 메시지만 늦게 온다(정직한 한계 — 방 전체가 막히지 않는다).
  보관 상한은 **설정**으로: `group.resync_keep`(발신자별 미전달 보관 상한 · 기본 200 ·
  초과 시 오래된 것부터 폐기 + 스레드에 명시 — 큐 상한 필수 규칙 NFR-B-6).

## 5. 신뢰·보안 (봉투 원리 점검)

- **이 계층의 봉투** — 발견 패킷에 그룹 정보 **절대 미포함**(평문 수확 금지 — DR-22와
  동일 결). 그룹의 존재는 초대받은 사람만 안다.
- 초대 = 세션(암호화) 경유만. roster에 있는 PeerId라도 **핀 없는 상대의 메시지는
  Unverified 배지**로 표시(신뢰는 여전히 키에 — DR-28).
- 소유자 키 분실 = 그룹 고아(멤버십 동결 · 대화는 지속) — v1.5 한계로 문서화.
  소유권 이양은 v2(DR-20 `UserId`와 함께).
- 스팸: 초대 수락제(G-4) + 기존 상호 확인 규칙은 그룹 파일 전송(후속)에 그대로.

## 6. UI (스크린샷 합의 기준 — 카카오톡류)

- 방 스레드: **상대 메시지 = 좌측 + 발신자 아바타·이름 라벨**(기존 그룹 발신자 라벨
  재사용) · 내 메시지 = 우측. 시각·날짜 알약 동일.
- 헤더: 그룹명 + "구성원 N" 클릭 → **구성원 관리 모달**(사용자 확정 08-13 — 체크박스
  목록 + 검색 · 소유자만 편집 가능, 비소유자는 열람+탈퇴).
- 목록: 그룹 섹션 행에 공유 그룹 표시(로컬 동보 그룹과 아이콘 구분) · 미확인 배지 동일.
- 초대 도착: 수신 승인 카드(수락/거절 — 파일 오퍼 카드와 같은 문법).
- 소유자 오프라인 시 관리 버튼 비활성 + "소유자 접속 시 반영" 안내.

## 7. 기존 설계와의 관계

- **로컬 그룹(동보 전송)은 유지** — "내 방송 목록"(상대 모르게 · 합의 없음)과 "공유
  방"(모두가 알고 수락)은 **서로 다른 계약**이라 둘 다 존재한다. UI에서 아이콘·명칭
  구분("방송 그룹" vs "그룹 대화").
- 로컬 그룹 → 공유 그룹 **승격**: "그룹 대화로 전환" = roster 서명 + 전원 초대 발송.
- FR-G-6 팬아웃·자동 연결·FR-G-4 전달 상태 = M5-1 기반 커밋 그대로 재사용.

## 8. 단계 (구현 슬라이스)

| 단계 | 내용 | 크기 |
|---|---|---|
| **G1** | GroupUid·roster 서명/검증(core) + groups.seg v2 + 와이어 코덱(Group 스트림) | 중 |
| **G2** | 초대 발송/수락 카드 · roster 배포/적용 · 방 생성(양쪽 목록에 등장) | 중 |

| **G4** | 재동기(SyncReq — 최근 N) · 구성원 관리 모달 · 로컬 그룹 승격 | 중 |
