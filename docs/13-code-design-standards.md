# 13 · 코드 설계 표준 — 모듈화 · 추상화 · 횡단 관심사 · 인터셉터 · 계측

> **목적**: 소스의 **가독성·재사용성**을 규약으로 고정하고, **로그·검증·계측·정책**이라는 횡단 관심사를 **한 통로**로 모아 인터셉터로 확장 가능하게 만든다.
> 사용자 확정(2026-08-08): *"구조적이고 모듈화를 잘 구조화해 재사용성을 높일 것 · 디자인 패턴 준수·추상화 레벨 향상 · 기능 간 횡단 구조를 로그/검증에 유리하게 · 추상클래스/인터페이스로 인터셉터 확장 용이하게 · **과금을 위한 것처럼 기능·행위가 잘 기록되도록**"*
>

> **이 문서는 코드 리뷰 체크리스트로 쓴다.** 위반은 병합 거부 사유다.

## 0. ⚠️ 먼저 — 이 요구는 기존 결정 둘과 충돌한다

정면으로 부딪히므로 절충을 먼저 못 박는다.

| 충돌 | 내용 | 해결 |
|---|---|---|
| **추상화 ↔ DR-5 예산** | 트레이트·제네릭은 공짜가 아니다. 모노모픽화는 **바이너리를 불린다**(NFR-B-3 ≤10MB), 동적 디스패치는 간접 호출과 vtable을 낳는다 | **정적 디스패치가 기본**, 동적은 [§5 확장 지점](#5-인터셉터--확장-지점)에만. **계측 계층은 feature로 분리**해 최소 빌드에서 제거 가능([§6-7](#6-7-예산-통제)) |
| **계측 ↔ NFR-O-5 · DR-1** | "사용 기록"은 감시로 읽힐 수 있고, 우리는 *"네트워크 밖으로 나가는 것이 없다"* 고 약속했다 | **로컬 전용 · 자동 전송 절대 없음 · 내용 미포함 · 상대 식별자는 해시.** 내보내기는 **사용자가 직접** 할 때만([§6-3](#6-3-프라이버시-경계--타협하지-않는-선)) |

> **계측을 두는 정당한 이유**: 라이선스가 **PolyForm Noncommercial**(DR-12)이라 상업 사용은 별도 유료 라이선스다. 그때 **사용량을 근거로 제시**하려면 기능·행위가 측정 가능해야 한다. 목적이 분명하므로 **그 목적에 필요한 것만** 기록한다.

## 1. 모듈화 — 재사용성의 실체

### 1-1. 3단 경계

| 단위 | 기준 | 규칙 |
|---|---|---|
| **크레이트** | **"무엇을 모르는가"** — [01 §2](01-architecture.md) | 의존은 **단방향**. 역참조 금지 |
| **모듈** | **응집** — 함께 바뀌는 것끼리 | 모듈 하나가 개념 하나 |
| **타입** | **불변식 하나** | 불변식이 둘이면 타입을 쪼갠다 |

### 1-2. 공개 표면 최소화

```rust
// 기본은 비공개. 밖에 필요한 것만 승격한다.
pub(crate) struct SessionInner { … }   // 크레이트 안
pub struct Session { … }               // 밖으로 나가는 것

// ★ Locator는 net 밖으로 나가지 않는다 (ADR-0003 규칙 1)
pub(crate) enum Locator { LocalDirect { … }, Relay { … } }
```

- **`pub`은 계약이다.** 공개하는 순간 바꾸기 어려워진다 — 공개 항목에는 **문서 주석 의무**.
- 크레이트 루트에서 **재수출(`pub use`)로 표면을 설계**한다. 내부 모듈 경로를 그대로 노출하지 않는다.
- **`ADR-0003` 누수 금지 규칙은 가시성으로 강제**한다 — 문서로만 두면 반드시 샌다.

### 1-3. 재사용 판단 규칙

| 상황 | 판단 |
|---|---|
| 같은 코드가 **2번** 나왔다 | 그대로 둔다(우연의 일치일 수 있다) |
| **3번**째 나왔다 | 추출한다 |
| 두 곳이 **같은 이유로** 바뀐다 | 추출한다(횟수 무관) |
| 두 곳이 **다른 이유로** 바뀔 것 같다 | 코드가 같아 보여도 **합치지 않는다** |

> **"코드가 같다"가 아니라 "변경 이유가 같다"** 가 기준이다. 잘못 합친 추상화는 중복보다 비싸다.

### 1-4. 크기 상한 (초과 시 분할 검토 — 절대 금지선 아님)

| 대상 | 권고 | 초과 시 |
|---|---|---|
| 함수 | 50줄 | 이름 붙일 수 있는 단위로 분리 |
| 파일(모듈) | 800줄 | 개념이 둘 이상 섞였는지 확인 |
| 함수 인자 | 5개 | 파라미터 구조체로 묶기 |
| 중첩 깊이 | 4단 | 조기 반환(early return)으로 평탄화 |
| 공개 항목 | — | 문서 주석 **의무** |

## 2. 추상화 — 포트와 어댑터

### 2-1. OO 개념 ↔ Rust 매핑

요구를 그대로 받되 Rust 관용구로 옮긴다.

| 요구한 것 | Rust에서 |
|---|---|
| 인터페이스 | **`trait`** |
| 추상 클래스(일부 구현 포함) | **`trait` + 기본 메서드(default method)** |
| 추상 필드 | 트레이트 접근자(`fn x(&self) -> T`) |
| 다형 컬렉션 | `Box<dyn Trait>` / `&dyn Trait` |
| 템플릿 메서드 패턴 | 기본 메서드가 흐름을 잡고, 훅만 필수 구현 |

### 2-2. 헥사고날 — 도메인은 포트만 안다

```
        ┌──────── 어댑터(바깥) ────────┐
        │  net · store · plat · crypto │
        └───────────┬──────────────────┘
                    │ 포트(trait)
        ┌───────────▼──────────────────┐
        │      core — 순수 도메인       │  I/O를 모른다
        └──────────────────────────────┘
```

### 2-3. 핵심 포트 목록 (v1)

| 포트 | 책임 | v1 구현체 | 테스트 구현체 |
|---|---|---|---|
| `Transport` | 발견·`Link` 생성([ADR-0003](09-adr-0003-transport-abstraction.md)) | `LocalDirect` | **`InMemory`** |
| `SecureSession` | Noise 핸드셰이크·AEAD | `NoiseSession` | `PlainSession`(테스트 전용) |
| `TrustStore` | TOFU 핀 조회·고정·변경 이력 | 파일 기반 | 인메모리 |
| `Repository` | 대화·그룹·설정 영속 | 파일 기반 | 인메모리 |
| `QuarantineStore` | `.beepq` 보관·조회·GC | 파일 기반 | 인메모리 |
| `MalwareScanner` | 버퍼 검사 | `Amsi`(Win) / `NoopScanner` | `StubScanner` |
| `QuarantineMarker` | OS 격리 표식 | `Motw`/`AppleQuarantine`/`PosixNoExec` | 기록만 하는 스텁 |
| `ImageDecoder` | 격리 디코드 | `ProcessDecoder`(`imgdec`) | 인프로세스 스텁 |
| `LinkWatcher` | L1 링크 상태 구독 | 플랫폼 3종 | 수동 이벤트 주입 |
| `Notifier` | 트레이·알림 | 플랫폼 3종 | 수집 스텁 |
| **`Clock`** | 현재 시각·단조 시계 | 시스템 | **고정 시계** |
| **`Rng`** | 난수 | 시스템 | **고정 시드** |
| **`Meter`** | 사용 계측([§6](#6-계측--과금-가능-수준의-사용-기록)) | 레저 기록 | 수집 스텁 |
| **`Tracer`** | 구조적 로그·스팬([§7](#7-로깅--추적)) | 파일/콘솔 | 수집 스텁 |

> **`Clock`·`Rng`를 포트로 두는 것이 가장 값이 크다.** 이게 없으면 타임아웃·재시도·논스·세션 만료 테스트가 전부 비결정적이 된다. **`std::time::Instant::now()`와 시스템 난수를 도메인 코드에서 직접 부르는 것은 금지**한다.

### 2-4. 트레이트 설계 규칙

1. **좁게.** 메서드 3~5개. 큰 트레이트는 쪼갠다(인터페이스 분리 원칙).
2. **소비자 쪽에 정의한다.** `core`가 쓰는 포트는 `core`가 선언하고, 어댑터가 구현한다(의존성 역전).
3. **기본 메서드로 확장한다** — 새 메서드를 기본 구현과 함께 추가하면 기존 구현체가 깨지지 않는다(추상 클래스의 이점을 여기서 얻는다).
4. **트레이트에 I/O 형식을 새기지 않는다** — 반환은 도메인 타입. `Vec<u8>`·`serde_json::Value` 같은 형식 누수 금지.
5. **`Send + Sync`는 필요한 곳에만.** 습관적으로 붙이면 구현 선택지가 좁아진다.
6. **오류는 트레이트가 정의한다** — 구현체 오류를 그대로 노출하지 않는다([§9](#9-오류-모델)).

### 2-5. 정적 vs 동적 디스패치 (예산 규칙)

| 상황 | 선택 |
|---|---|
| 구현이 **컴파일 타임에 하나**로 정해짐(플랫폼별 어댑터) | **정적** — `cfg` + 제네릭 |
| 구현이 **둘 이상 공존**(`Transport` — LocalDirect + InMemory + 향후 Relay) | **동적** — `Box<dyn>` |
| **확장 지점**(인터셉터 체인) | **동적** — 목록으로 구성 |
| 뜨거운 경로(렌더 루프·바이트 복사) | **정적** — 간접 호출 금지 |

> 제네릭 남용은 **모노모픽화로 바이너리를 불린다**. 타입 파라미터가 3개를 넘어가면 `dyn`을 검토한다. **SP-1에서 두 방식의 크기 차이를 실측**해 기준을 확정한다.

## 3. 횡단 관심사 — 하나의 통로

### 3-1. 핵심 아이디어 — 모든 유의미한 행위를 `Action`으로

로그·검증·계측·정책을 **각 기능에 흩뿌리면** 반드시 빠뜨린다. 그래서 **의미 있는 행위를 전부 하나의 타입으로 표현**하고, **단일 파이프라인**을 통과시킨다.

```rust
/// 사용자가 인지할 수 있는 단위 행위 하나.
/// ★ 새 기능을 추가할 때는 ActionKind에 항목을 추가하는 것이 첫 단계다.
pub enum ActionKind {
    // 발견
    DiscoveryRoundStarted { tier: DiscoveryTier },
    PeerAppeared, PeerVanished,
    // 세션
    HandshakeAttempted, TrustPinned, TrustMismatchBlocked,
    FingerprintVerified,
    // 대화
    MessageSent, MessageReceived,
    GroupMessageFannedOut { members: u32 },
    BroadcastSent,
    // 전송
    TransferOffered, TransferAccepted, TransferCompleted,
    // 안전
    FileQuarantined { risk: RiskLevel },
    FileInspected { scan: ScanOutcome },
    FileApproved { risk: RiskLevel },
    FileMaterialized, FileRejected, FileExpired,
    ImageDecoded, ImageDecodeRejected { reason: RejectReason },
    // 정책
    RateLimited, SenderBlocked,
}
```

### 3-2. 파이프라인 순서 (고정)

```
   요청
     ▼
 ┌─ Trace ──────────────────────────────────────┐   ← 가장 바깥: 거절도 관측된다
 │ ┌─ Policy ─────────────────────────────────┐ │   ← 차단·속도 제한은 가장 먼저
 │ │ ┌─ Validate ───────────────────────────┐ │ │   ← 무해화·불변식
 │ │ │ ┌─ Meter(begin) ───────────────────┐ │ │ │
 │ │ │ │          Handler (실제 기능)      │ │ │ │
 │ │ │ └─ Meter(end, outcome) ────────────┘ │ │ │
 │ │ └──────────────────────────────────────┘ │ │
 │ └──────────────────────────────────────────┘ │
 └──────────────────────────────────────────────┘
     ▼
   결과
```

| 층 | 왜 이 위치인가 |
|---|---|
| **Trace** 최외곽 | 거절·실패도 남아야 한다. 안쪽에 두면 차단된 행위가 로그에 없다 |
| **Policy** 다음 | 차단 대상은 **검증도 계측도 하기 전에** 끊는다(자원 낭비·증폭 공격 방지) |
| **Validate** | 핸들러는 **이미 검증된 입력만** 본다 |
| **Meter** 가장 안쪽 | 실제로 수행된 것만 계측 — 거절된 시도는 `Rejected`로 별도 집계 |

### 3-3. 규칙

- **핸들러는 횡단 관심사를 모른다.** 핸들러 안에 `log!`·`meter!`를 쓰지 않는다. 쓰고 싶어지면 **`ActionKind`가 부족한 것**이다.
- **파이프라인 우회 금지.** 우회 경로를 만드는 순간 감사·계측에 구멍이 생긴다.
- **모든 층은 fail-closed** — 인터셉터가 실패하면 행위를 **수행하지 않는다**(NFR-S-4). 단 `Trace`·`Meter` 실패는 예외([§6-6](#6-6-실패-정책)).

## 4. 검증 (Validate)

### 4-1. Parse, don't validate

```rust
// ✗ 나쁨 — 검증했는지 타입이 모른다
fn send(name: &str, body: &str) { … }

// ✓ 좋음 — 생성에 성공했다는 사실이 곧 검증 완료
pub struct DisplayName(String);   // RLO·제어문자 제거 + 길이 상한 통과
pub struct MessageBody(String);   // 무해화 + 길이 상한 통과
impl DisplayName { pub fn parse(raw: &str) -> Result<Self, Invalid> { … } }
```

- **신뢰 경계에서 한 번만** 변환한다 — 네트워크 수신부·파일 수신부·UI 입력부.
- 변환 이후 도메인은 **검증을 다시 하지 않는다**(중복 검증은 "어딘가에서 했겠지"를 낳는다).
- **원본 보존이 필요한 곳은 예외** — `.beepq`의 `orig_name`은 원본 바이트로 두고 표시·실체화 시 각각 정규화한다([ADR-0004 §2](11-adr-0004-quarantine.md)).

### 4-2. 불변식 위치

| 불변식 | 사는 곳 |
|---|---|
| "메시지 본문은 무해화됨" | `MessageBody` 타입 |
| "PeerId는 32바이트 공개키" | `PeerId` 타입 |
| "격리물은 실행 권한이 없다" | `QuarantineStore` 어댑터 |
| "큐는 상한이 있다" | 큐 타입 자체 |

## 5. 인터셉터 — 확장 지점

### 5-1. 계약

```rust
/// 파이프라인에 끼어드는 확장점. 순서는 등록 순.
pub trait Interceptor: Send + Sync {
    /// 식별용 이름(로그·진단).
    fn name(&self) -> &'static str;

    /// 실행 전. Err를 반환하면 행위는 수행되지 않는다(fail-closed).
    fn before(&self, ctx: &mut ActionCtx) -> Result<(), Reject> { let _ = ctx; Ok(()) }

    /// 실행 후. 여기서는 결과를 바꿀 수 없다 — 관측 전용.
    fn after(&self, ctx: &ActionCtx, outcome: &Outcome) { let _ = (ctx, outcome); }
}
```

> **기본 메서드를 둔 이유** — 구현체는 필요한 훅만 덮어쓴다(추상 클래스의 템플릿 메서드와 같은 효과). 나중에 훅을 추가해도 **기존 구현이 깨지지 않는다**.

### 5-2. `ActionCtx` — 인터셉터가 공유하는 문맥

| 필드 | 내용 |
|---|---|
| `action_id` | **상관관계 ID** — 로그·계측·감사가 이 값으로 이어진다 |
| `kind` | `ActionKind` |
| `actor` | 자기 자신 / 상대 `PeerId`(계측에는 해시로) |
| `trust` | 미검증 / 검증됨 / 대조 완료 — **정책·UI 마찰 판단 근거** |
| `started_at` | `Clock` 포트에서 |
| `attrs` | 구조적 키-값(제한된 집합 — 자유 문자열 금지) |

### 5-3. 기본 제공 인터셉터

| 이름 | 역할 |
|---|---|
| `TraceInterceptor` | 스팬 시작/종료, 구조적 로그 |
| `PolicyInterceptor` | 차단 목록 · 발신자별 속도 제한 · 미확인 발신자 격리(FR-S-16) |
| `ValidationInterceptor` | 경계 무해화 확인(이중 안전망) |
| `MeterInterceptor` | 사용 계측([§6](#6-계측--과금-가능-수준의-사용-기록)) |
| `AuditInterceptor` | 보안 유의 행위만 별도 기록(신뢰 변경·승인·차단) |

### 5-4. 확장 규칙

- 등록은 **조립 시점(main)에서 한 번**. 런타임 동적 추가는 v1 범위 밖.
- 인터셉터는 **서로를 모른다**. 순서 의존이 필요하면 그건 설계 오류다.
- `after`는 **결과를 바꾸지 못한다** — 관측과 제어를 섞지 않는다.
- **비용 상한**: 인터셉터 하나가 행위당 추가하는 지연은 무시 가능해야 한다. 무거운 작업(디스크 쓰기)은 **채널로 넘겨 비동기 처리**.

## 6. 계측 — 과금 가능 수준의 사용 기록

### 6-1. 목적

**PolyForm Noncommercial(DR-12)** 하에서 상업 사용은 별도 유료 라이선스다. 그때 **"무엇을 얼마나 썼는가"** 를 근거로 제시할 수 있어야 한다. 부수적으로 **성능 회귀 추적**과 **버그 재현**에도 쓴다.

### 6-2. 계측 이벤트 모델 — 5W

| 요소 | 필드 | 예 |
|---|---|---|
| **누가** | `actor` | 자기 자신 / 상대(**솔티드 해시**) |
| **무엇을** | `action` | `MessageSent` · `FileMaterialized` |
| **언제** | `wall_ts` + `mono_ns` | 벽시계(집계용) + 단조(지연 측정용) |
| **얼마나** | `quantity` | `count` · `bytes` · `duration_ms` · `peers` |
| **결과** | `outcome` | `Ok` / `Rejected(code)` / `Failed(code)` |

### 6-3. 프라이버시 경계 — 타협하지 않는 선

| 기록한다 | **절대 기록하지 않는다** |
|---|---|
| 행위 종류·횟수·바이트 수·소요 시간 | **메시지 내용** |
| 결과(성공/거절/실패) 코드 | **파일 이름·경로·내용** |
| 상대 수(고유 피어 카운트) | **표시 이름** |
| 상대의 **솔티드 해시**(로컬 솔트, 기기별) | **평문 PeerId·IP·MAC** |
| 위험 등급·검사 결과 | **키 자료** |

- **자동 전송 없음.** 레저는 로컬 파일로만 존재한다(NFR-O-5).
- **내보내기는 사용자 행위** — 명시적으로 "사용 기록 내보내기"를 눌렀을 때만, 무엇이 포함되는지 보여준 뒤 파일로.
- **끌 수 있다.** 계측 비활성 옵션을 제공하고, 끄면 레저에 아무것도 쓰지 않는다.
- 상대 해시의 솔트는 **기기 로컬**이라 다른 기기의 기록과 대조되지 않는다.

### 6-4. 레저 구조 — append-only + 해시 체인

```
record {
  seq        u64        // 단조 증가, 빠짐 없음
  prev_hash  [u8;32]    // 직전 레코드 해시 — 삭제·수정 탐지
  wall_ts    u64
  mono_ns    u64
  actor      ActorRef   // Self | PeerHash([u8;16])
  action     u16        // ActionKind 안정 코드
  quantity   Quantity
  outcome    Outcome
  hash       [u8;32]    // 위 필드들의 해시
}
```

| 성질 | 방법 |
|---|---|
| **누락 탐지** | `seq` 연속성 |
| **변조 탐지** | `prev_hash` 체인 — 중간 레코드를 고치면 이후가 전부 깨진다 |
| **손상 복원** | 레코드 단위 길이 접두 + 체크섬 → 손상 지점 이후만 버린다 |
| **롤업** | 일 단위 집계 레코드를 만들고 원본은 보존 기간 후 정리 |

> ⚠️ **정직한 한계**: 로컬 레저는 **기기 소유자가 위조할 수 있다.** 해시 체인은 *우발적 손상과 부분 삭제*를 잡을 뿐, 처음부터 조작된 기록은 막지 못한다. 진짜 과금 근거가 필요하면 **서명된 레저를 릴레이(`nexa-beepd`)로 제출하는 v2 경로**가 있어야 한다 — v1은 그 자리만 남긴다(`Meter` 포트가 이미 그 접합점이다).

### 6-5. 안정 코드

`ActionKind` → `u16` 매핑은 **부여 후 불변**이다. 기능이 사라져도 코드를 재사용하지 않는다(문서 번호 규칙과 같은 이유 — [16 §2-8](16-doc-git-conventions.md)). 매핑표는 `core`에 표로 둔다.

### 6-6. 실패 정책

계측은 **본 기능을 방해하지 않는다** — 레저 쓰기가 실패해도 메시지 전송은 성공한다. 대신 **`meter_dropped` 카운터를 올리고 다음 성공 레코드에 반영**한다. 조용히 사라지지 않게 한다.
(→ [§3-3](#3-3-규칙)의 fail-closed 예외는 `Trace`·`Meter` 두 층뿐이다.)

### 6-7. 예산 통제

| 항목 | 규칙 |
|---|---|
| 레코드 크기 | 고정 폭 지향, 가변부 상한 |
| 쓰기 | **채널로 넘겨 배치 기록** — 행위 경로에서 디스크를 만지지 않는다 |
| 고빈도 행위 | 발견 라운드·프레임 단위는 **개별 기록 금지**, 집계만 |
| 파일 크기 | 상한 + 롤오버. 초과 시 오래된 것부터 롤업 후 삭제 |
| **빌드 분리** | `feature = "metering"` — **끄면 코드와 크기가 사라진다.** 최소 포터블 빌드 옵션 |

## 7. 로깅 · 추적

| 규칙 | 내용 |
|---|---|
| **구조적** | 문자열 조립 금지. `action_id` + 키-값 필드 |
| **상관관계** | 모든 로그에 `action_id`. 하나의 행위가 여러 계층을 지나도 **한 줄기로 추적** |
| **레벨** | `error`(사용자 영향) / `warn`(비정상이나 진행) / `info`(상태 전이) / `debug`(개발) / `trace`(상세) |
| **금지 필드** | 메시지 내용 · 파일명 · 경로 · 키 · 평문 PeerId. **`Display` 구현에서 원천 차단**(민감 타입은 `Debug`도 마스킹) |
| **위치** | **로컬 파일만.** 외부 전송 금지(NFR-O-5) |
| **회전** | 크기·기간 상한 |
| 예산 | 릴리스에서 `debug`·`trace`는 **컴파일 타임 제거** |

```rust
// 민감 타입은 실수로 찍히지 않게 만든다
impl fmt::Debug for MessageBody {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(f, "MessageBody({} chars)", self.0.chars().count())  // 내용 없음
    }
}
```

## 9. 오류 모델

```rust
pub enum DomainError { … }      // 예상된 실패 — 사용자에게 의미 있음
pub enum InfraError { … }       // I/O·플랫폼 — 재시도·복구 대상
```

| 규칙 | 내용 |
|---|---|
| **분리** | 도메인 오류와 인프라 오류를 한 열거형에 섞지 않는다 |
| **코드 안정성** | 사용자 노출·계측에 쓰이는 오류 코드는 **불변** |
| **문맥** | 원인 체인 보존. 단 **민감 정보는 오류 메시지에도 넣지 않는다** |
| **`unwrap`/`expect`** | 프로덕션 경로 **금지**. 불변식상 불가능하면 `expect`에 **이유를 쓴다** |
| **패닉** | 라이브러리 크레이트에서 금지. 경계에서 잡는다 |
| **fail-closed** | 판정 불가는 "통과"가 아니다(NFR-S-4) |

## 10. `unsafe` 정책

L1~L4 저수준(DR-14)·플랫폼 API 때문에 완전히 피할 수 없다.

| 규칙 | 내용 |
|---|---|
| **격리** | `plat`·`net`의 지정된 모듈에만. `core`·`ui`·`safe`에는 **한 줄도 없다** |
| **주석 의무** | 모든 `unsafe` 블록에 **안전성 근거**(`// SAFETY: …`) |
| **최소 표면** | 안전한 래퍼로 감싸고 밖에는 안전한 API만 노출 |
| **금지** | 성능만을 이유로 한 `unsafe` — 실측 없이 금지 |
| CI | `unsafe` 라인 수를 **추적**하고 증가 시 리뷰에서 근거 요구 |

## 11. 테스트 가능성

| 수단 | 효과 |
|---|---|
| **포트 인메모리 구현** | 네트워크·디스크 없이 상위 계층 전체 테스트([ADR-0003](09-adr-0003-transport-abstraction.md)) |

| **`ActionKind` 단위 단언** | "이 시나리오에서 정확히 이 행위들이 이 순서로 일어났다"를 테스트 |
| **테스트 인터셉터** | 불변식 위반을 테스트 중에만 검출(예: "파이프라인 우회 없음") |
| **골든 테스트** | `.beepq` 컨테이너·와이어 포맷 바이트 고정 |

## 12. 코드 리뷰 체크리스트

```
□ 새 기능이 ActionKind에 추가되었는가 (또는 추가할 필요가 없는 이유가 분명한가)
□ 핸들러 안에 로그·계측 호출이 없는가
□ 파이프라인을 우회하는 경로를 만들지 않았는가
□ 도메인 코드가 Instant::now()·시스템 난수를 직접 부르지 않는가
□ 신뢰 경계에서 타입으로 파싱했는가 (문자열을 그대로 흘리지 않았는가)
□ pub이 정말 필요한가 (기본은 pub(crate))
□ Locator·IP가 net 밖으로 새지 않는가
□ 민감 타입의 Debug/Display가 내용을 노출하지 않는가
□ 큐·버퍼·컬렉션에 상한이 있는가
□ unsafe에 SAFETY 주석이 있는가
□ unwrap/expect가 프로덕션 경로에 없는가
□ 3번째 중복인가 (2번은 두고, 변경 이유가 같으면 추출)
□ 공개 항목에 문서 주석이 있는가
```
