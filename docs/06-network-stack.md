# 06 · 네트워크 스택 저수준 설계 (L1 ~ L4)

> **목적**: 발견·전송을 **OSI L1~L4 각 계층에서 무엇을 직접 다루는지** 못 박는다. 상위 라이브러리에 맡기고 넘어가면 [03 §6-3](03-competitive-landscape.md)에서 확인한 사내망 제약(클라이언트 격리·VLAN 멀티캐스트 차단)에 그대로 무너진다.
> **작성 2026-08-08.** 프로토콜 **확정**은 [ADR-0002](10-decision-record.md)(TODO D-7), 근거 실측은 스파이크(TODO D-8). 이 문서는 **설계 골격과 제약**을 정리한다.
>
> ⚠️ **이 문서를 관통하는 제약 하나** — 저수준으로 내려갈수록 **권한(root/Administrator·드라이버)** 이 필요해지고, 그것은 **DR-1(실행 = 참여)** 과 **DR-4(포터블)** 를 정면으로 깬다. 그래서 계층을 "쓸 수 있으면 쓴다"는 **능력 등급(Capability Tier)** 으로 나눈다([§6](#6-능력-등급--권한이-없어도-반드시-동작한다)).

## 1. 계층별 역할 한눈에

| 계층 | 우리가 다루는 것 | 목적 | 권한 |
|---|---|---|---|
| **L1 / 링크 상태** | NIC 열거 · 링크 up/down · 매체 종류(유선/무선/가상/터널) · 속도 · MTU · **변경 이벤트 구독** | 네트워크가 바뀌는 순간을 **즉시** 알고 재발견·재바인딩 | 불요 |
| **L2 / 데이터링크** | MAC 주소 · **이웃 테이블(ARP/NDP) 조회** · 이더넷 브로드캐스트 · (선택) 원시 프레임 | 같은 브로드캐스트 도메인 확인, L3가 막혔을 때 최후 폴백 | 조회는 불요 / **원시 프레임은 권한 필요** |
| **L3 / 네트워크** | IPv4·IPv6 · **멀티캐스트(IGMP/MLD)** · 서브넷/제한 브로드캐스트 · 링크로컬 · TTL/hop limit · **인터페이스별 바인딩** · ICMP 도달성 | 발견 패킷을 **올바른 인터페이스로** 내보내고 **어디로 들어왔는지** 아는 것 | 불요(ICMP 일부 제외) |
| **L4 / 전송** | **UDP**(발견·소형 제어) + **TCP**(세션·파일) · 소켓 옵션 · 흐름 제어·백프레셔 · MTU 회피 | 신뢰성과 처리량 | 불요 |

> 상위(L5~L7 — 세션·암호화·메시지 포맷)는 [ADR-0003 전송 추상화](10-decision-record.md)와 [04 안전 송수신](04-safe-transfer.md) 소관. **암호화는 L4 위**에 둔다(DR-7 — 릴레이 경유든 직접이든 종단 간).

## 2. L1 — 링크 상태를 "구독"한다

> 노트북은 도킹하고, Wi-Fi를 바꾸고, VPN을 켠다. **폴링으로는 늦다.** 대부분의 LAN 메신저가 "목록이 안 갱신된다"는 불만을 듣는 지점이 여기다.

### 필요한 정보

인터페이스별 — 인덱스 · 이름 · MAC · **매체 종류**(유선/무선/루프백/가상/터널) · 링크 상태 · **MTU** · 할당된 IPv4/IPv6 주소와 프리픽스 · 브로드캐스트 주소 · 멀티캐스트 지원 여부.

### 플랫폼별 수단

| OS | 열거 | 변경 이벤트 |
|---|---|---|
| Windows | **IP Helper `GetAdaptersAddresses`** | **`NotifyIpInterfaceChange`** · `NotifyUnicastIpAddressChange` (콜백) |
| macOS/BSD | `getifaddrs` · `sysctl(NET_RT_IFLIST)` | **route 소켓(`PF_ROUTE`)** 메시지 · SystemConfiguration |
| Linux | `getifaddrs` | **netlink(`RTM_NEWLINK`/`RTM_NEWADDR`)** 구독 |

### 설계 규칙

- **가상·터널 인터페이스는 기본 제외**(VPN·Docker·VMware·Hyper-V) — 발견 패킷이 엉뚱한 곳으로 나가 지연과 오탐을 만든다. 사용자 재정의 가능.
- **무선 인터페이스는 별도 취급** — 멀티캐스트가 낮은 기본 전송률로 나가고 AP가 변환·폐기할 수 있어 신뢰도가 유선과 다르다([§3-2](#3-2-멀티캐스트--기본이되-믿지-않는다)).
- 링크 변경 이벤트 = **재발견 트리거**. 단 **디바운스**(연쇄 이벤트가 몰아친다)를 걸고, 기존 세션은 유지한 채 발견만 다시 돈다.
- **다중 인터페이스가 정상이다.** 한 대가 유선+무선에 동시에 붙어 있으면 **같은 피어가 두 경로로 보인다** → 신원(키 지문)으로 병합하고 경로는 후보 목록으로 관리한다([§5-3](#5-3-같은-피어가-여러-경로로-보인다)).

## 3. L3 — 발견 패킷이 나가고 들어오는 층

### 3-1. 인터페이스별 바인딩 — 여기서 대부분이 틀린다

- **`INADDR_ANY` 하나로 끝내지 않는다.** 어떤 인터페이스로 나갈지는 라우팅 테이블이 정하는데, 발견은 **모든 후보 인터페이스로 각각** 내보내야 한다.
- 송신: 인터페이스마다 **`IP_MULTICAST_IF` / `IPV6_MULTICAST_IF`** 를 지정해 개별 송신.
- 수신: **`IP_PKTINFO` / `IPV6_RECVPKTINFO`** 를 켜서 **어느 인터페이스로 들어온 패킷인지** 확인한다. 이 정보가 없으면 응답을 엉뚱한 경로로 보내게 된다.
- IPv6 링크로컬(`fe80::/10`)은 **스코프 ID(인터페이스 인덱스)가 주소의 일부**다. 이걸 빠뜨리면 연결이 안 된다.

### 3-2. 멀티캐스트 — 기본이되, 믿지 않는다

| 항목 | 설계 |
|---|---|
| 그룹 | IPv4 멀티캐스트 그룹 + IPv6 `ff02::`(링크로컬 스코프). mDNS 방식을 쓸 경우 `224.0.0.251:5353` / `ff02::fb` |
| **TTL / hop limit** | **기본 1** — 링크 밖으로 새지 않게. 서브넷 초과 발견은 별도 기능으로 명시적 상향([§3-4](#3-4-서브넷-너머)) |
| 루프백 | `IP_MULTICAST_LOOP` — 같은 PC에서 두 인스턴스 테스트에 필요. 운영 시 자기 자신 패킷은 **송신자 키로 걸러낸다** |
| 그룹 가입 | `IP_ADD_MEMBERSHIP`을 **인터페이스마다** — 가입은 IGMP(v2/v3)/MLD로 스위치에 알려진다 |
| **실패 전제** | **IGMP 스누핑·클라이언트 격리·VLAN 분리로 조용히 폐기될 수 있다.** "보냈다"가 "닿았다"가 아니다 → 반드시 폴백([§4](#4-다단-발견--폴백-사다리)) |

### 3-3. 브로드캐스트 — 오래됐지만 뚫리는 곳이 있다

- **제한 브로드캐스트 `255.255.255.255`**(라우터를 넘지 않음)와 **서브넷 지향 브로드캐스트**(예: `192.168.0.255`) 둘 다 후보. `SO_BROADCAST` 필요.
- IPv6에는 브로드캐스트가 없다 — 대응물은 **`ff02::1`(모든 노드 멀티캐스트)**.
- IP Messenger가 20년간 UDP 브로드캐스트로 버틴 이유 = **멀티캐스트보다 통과하는 환경이 있다.** 반대로 브로드캐스트를 막고 멀티캐스트를 여는 곳도 있다 → **둘 다 시도**한다.

### 3-4. 서브넷 너머

- 기본은 **링크 로컬 한정**(TTL 1). 그 이상은 사용자가 켜는 기능으로 분리한다.
- 수단: 지정 호스트 목록 유니캐스트 프로브 · IP Messenger의 **Member Master**(한 노드가 명단을 중계) 방식 · 궁극적으로는 **릴레이 모드**(DR-8 ②)가 정답.
- **DR-1을 지키는 선**: 서브넷 너머는 "설정하면 되는 추가 기능"이지, 기본 동작이 이걸 요구해선 안 된다.

### 3-5. 링크로컬 자동 주소

- DHCP가 없는 직결 환경(노트북 2대 크로스 연결 등)에서는 **IPv4LL `169.254.0.0/16` · IPv6 `fe80::/10`** 만 존재한다.
- **"실행 = 참여"를 지키려면 이 상태에서도 발견이 돌아야 한다.** 링크로컬 주소를 1급 시민으로 다룬다.

### 3-6. ICMP

- 도달성 확인(경로 후보 검증)에 유용하나 **원시 ICMP는 권한이 필요**한 경우가 많다.
- ⇒ **필수 경로에 넣지 않는다.** 도달성은 L4 프로브(UDP/TCP)로 판정하고, ICMP는 진단 기능(선택)으로만.

## 4. 다단 발견 — 폴백 사다리

> [03 §6-3](03-competitive-landscape.md)의 결론을 그대로 설계로 옮긴 것. **단계마다 성공/실패를 기록**해 [18](18-build-and-test.md)의 실측 대상으로 삼는다.

| 단계 | 수단 | 뚫는 상황 | 비용 |
|---|---|---|---|
| **S1** | IPv6 링크로컬 멀티캐스트(`ff02::`) | IPv6가 살아 있는 현대적 망 | 낮음 |
| **S2** | IPv4 멀티캐스트 | 표준 경로 | 낮음 |
| **S3** | UDP 브로드캐스트(제한 + 서브넷 지향) | 멀티캐스트만 막힌 스위치 | 낮음 |
| **S4** | **이웃 테이블(ARP/NDP) 기반 유니캐스트 프로브** — 이미 통신한 적 있는 L2 이웃에게 직접 | 브로드캐스트·멀티캐스트가 다 막혔지만 **유니캐스트는 되는** 환경(클라이언트 격리의 흔한 형태) | 중간 |
| **S5** | 서브넷 유니캐스트 스캔(속도 제한·범위 상한) — LocalSend의 폴백과 같은 발상 | 위가 전부 실패 | **높음** — /24 초과 자동 금지, 사용자 동의 필요 |
| **S6** | **수동 주소 입력**([ADR-0006](19-adr-0006-manual-endpoint.md) — IPv4/IPv6/DDNS · **LAN 밖 공인 IP 포함**) · 릴레이 모드(DR-8 ②) | 격리·분리망 · **원거리** | — |

**공통 규칙**
- 단계는 **순차 상승**하되, 성공한 단계는 **인터페이스별로 기억**해 다음부터 먼저 시도한다.
- **발표(announce)는 이벤트 기반 + 저빈도 주기**. 고빈도 폴링 금지(DR-5 — 유휴 자원 소모는 예산 위반이며, 무선에서는 배터리 문제이기도 하다).
- 이탈은 **명시적 goodbye + 무응답 타임아웃** 이중으로 판정한다.
- **S5는 기본 꺼짐.** 네트워크 스캔은 보안 장비에 공격으로 탐지될 수 있다 — 사용자에게 그 사실을 알리고 동의를 받는다.

## 5. L4 — 전송

### 5-1. UDP와 TCP의 역할 분담

| | UDP | TCP |
|---|---|---|
| 용도 | 발견·발표·이탈·상태(presence)·소형 제어 | 대화 세션 · **파일 전송** · 순서·신뢰가 필요한 모든 것 |
| 크기 | **패킷을 작게 유지**(IPv6 최소 MTU 1280 이하, 가급적 512B 이하) — 단편화된 UDP는 방화벽·무선에서 잘 죽는다 | 스트림 |
| 신뢰 | 없음 — 재시도·중복 억제를 우리가 | OS |

### 5-2. 소켓 옵션 — 크로스플랫폼에서 의미가 갈리는 것들

| 옵션 | 용도 | 주의 |
|---|---|---|
| `SO_REUSEADDR` / `SO_REUSEPORT` | 같은 포트 공유(멀티캐스트 수신·다중 인스턴스) | **의미가 OS마다 다르다** — Windows의 `SO_REUSEADDR`는 유닉스의 `SO_REUSEPORT`에 가깝고 하이재킹 위험이 있어 `SO_EXCLUSIVEADDRUSE` 고려가 필요하다. **플랫폼별로 따로 검증**한다 |
| `IP_PKTINFO`/`IPV6_RECVPKTINFO` | 수신 인터페이스 식별 | [§3-1](#3-1-인터페이스별-바인딩--여기서-대부분이-틀린다) 필수 |
| `IP_MULTICAST_IF/TTL/LOOP` | 멀티캐스트 송신 제어 | 인터페이스마다 설정 |
| `IPV6_V6ONLY` | 듀얼 스택 동작 | **기본값이 OS마다 다르다** — 명시적으로 설정 |
| `TCP_NODELAY` | 대화 메시지 지연 제거 | 파일 전송 구간과 정책을 분리 |
| keepalive | 죽은 피어 감지 | OS 기본값이 길다 → 앱 레벨 하트비트 병행 |
| 버퍼 크기 | 처리량 | 무한정 키우지 않는다(DR-5) |

### 5-3. 같은 피어가 여러 경로로 보인다

다중 인터페이스·듀얼 스택이면 **한 사람이 여러 주소로 발견되는 것이 정상**이다.

- **신원 = 키 지문**(DR-8) → 지문으로 병합해 **사용자 목록에는 한 명**으로.
- 주소는 **경로 후보 목록**으로 들고, 실제 연결 시 우선순위(같은 서브넷 > 유선 > IPv6 링크로컬 > …)로 시도. 실패하면 다음 후보.
- 연결 성공 경로를 기억하되, 링크 변경 이벤트가 오면 무효화한다.

### 5-4. 흐름 제어·자원 상한 (DR-5 직결)

- 동시 연결 수·전송 큐·수신 버퍼에 **명시적 상한**. 상한 없는 큐는 곧 메모리 누수다.
- 파일 전송은 **스트리밍**(전체를 메모리에 올리지 않는다) + 백프레셔.
- 발신자별 속도 제한 = 스팸 방어([04 T-8](04-safe-transfer.md))와 동일 메커니즘.
- **장기 실행 누수 0**(DR-5)은 여기서 결판난다 — 소켓·타이머·피어 엔트리·재조립 버퍼가 전형적 누수원. [18](18-build-and-test.md)에 장시간 상주 실측을 게이트로 넣는다.

## 5-1. 전송 대역 제어 — 관측 기반 페이싱 (M4-11 · 08-16 실기 개정)

전송 속도는 L4가 아니라 **앱 계층의 페이싱 수학**이 정한다(`nbeep-core::rate` —
OS 종속 코드 0 · OS·링크 특성 차이는 관측이 흡수한다).

**세 가지 값을 구분한다** — 이 구분이 무너져서 로컬 0.25MB/s 고착이 났다:

| 값 | 뜻 | 소유 |
|---|---|---|
| **페이싱 목표**(`target_bps`) | 내 발신을 조이는 속도 = `max(관측 peak × 0.5, 하한 256KiB/s)` | 발신자 |
| **공지 상한**(`advertised_cap`) | 상대에게 주장하는 내 수신 상한 — **Auto = 0(무주장)** · 명시(PerSec)만 주장 | 수신자 |
| **협상 결과**(`negotiate`) | 내 목표와 상대 공지 중 낮은 쪽(0 = 무제한) | 쌍방 |

**부트스트랩 원칙 — 첫 2MiB는 무페이싱 프로브다.** 전속으로 보내 meter가
**진짜 링크 능력**을 관측한 뒤, 경계에서 목표를 실측 기반으로 1회 재산출한다.
2MiB 이하 파일은 전체가 프로브(= 사실상 전속 · 작은 파일 페이싱은 무의미).

> ⚠️ **교훈(08-16 실기)** — *페이싱 중 관측은 링크 능력이 아니라 자기 목표를
> 재는 것이다.* 하한으로 조인 채 보내면 관측 속도가 하한에 머물고 peak가 영영
> 안 올라 **자동 대역이 하한에 고착**된다(되먹임). 관측과 조임은 반드시
> 분리된 구간에서 해야 한다. 같은 이유로 **관측 없는 쪽이 상한을 주장하게
> 하면 안 된다** — 종전 수신측은 observe 배선조차 없는 meter로 하한을
> 공지했고, 쌍방 negotiate가 그 하한에 갇혔다.

잔여(M4-11): 장기 전송 중 **주기 상향 프로브**(링크가 도중에 좋아진 경우 —
TCP 혼잡 제어와 같은 결) · 루프백 무제한(프로브로 localhost도 ~전속이라 후순위).

## 6. 능력 등급 — 권한이 없어도 반드시 동작한다

> ⚠️ **L2 원시 프레임은 매력적이지만 대가가 크다.**
> Linux `AF_PACKET`은 `CAP_NET_RAW`, macOS/BSD는 `/dev/bpf*` 접근 권한, **Windows는 원시 소켓 제약이 강해 Npcap 같은 별도 드라이버 설치가 사실상 필수**다. 드라이버 설치는 **포터블(DR-4)과 "실행 = 참여"(DR-1)를 동시에 깬다.**

| 등급 | 조건 | 사용 계층 | 기능 |
|---|---|---|---|
| **T0 — 기본(무권한)** | 아무 권한 없음. **포터블 실행 포함** | L1 조회 · L3 멀티캐스트/브로드캐스트 · **L2 이웃 테이블 조회** · L4 UDP/TCP | **전 기능 정상 동작.** S1~S4 발견 |
| **T1 — 방화벽 허용** | 최초 실행 시 OS 방화벽 예외 승인 | 동일 | 수신 포트 개방 → 발견 도달률 상승 |
| **T2 — 권한 상승(선택)** | 관리자/root, 또는 드라이버 설치(Windows) | + **L2 원시 프레임** | 진단·최후 폴백. **없어도 제품은 완전하다** |

**규칙 3가지**
1. **T0이 제품이다.** T1·T2는 개선일 뿐, 어떤 핵심 기능도 여기에 의존하지 않는다.
2. **권한 요구는 사용자가 그 이유를 이해할 수 있을 때만** 띄운다. 시작하자마자 관리자 권한을 묻는 메신저는 DR-1의 정신에 어긋난다.
3. **L2 이웃 테이블 "조회"는 T0** — Windows `GetIpNetTable2`, Linux netlink `RTM_GETNEIGH`, macOS `sysctl` 라우팅 테이블. 원시 프레임 없이도 L2 정보를 상당 부분 쓸 수 있다. **S4 폴백의 근거가 이것.**

### 7-1. 네트워크 계측 모드 — netmon (08-21 · 사용자 요청 "과도한 송수신 모니터링")

§7의 실측 규율을 **상시 제품 안에서** 쓸 수 있게 한 옵트인 도구. 주기 점검을 돌리면서
발견 광고 폭주·재연결 폭풍·자기 에코 과다 같은 "조용히 과한" 트래픽을 숫자로 잡는다
(08-20 CLI \[무시\] 로그 홍수류의 조기 발견 장치).

- **구조 = 세는 것 / 쓰는 것 분리**(`nbeep-net::netmon`):
  - **카운터는 상시** — 이음새 4곳(발견 소켓 tx/rx · TCP 링크 프레임 · 연결 시도/수락)이
    지나갈 때 relaxed 원자 덧셈 하나(ns 수준·할당 0). 꺼져 있으면 아무도 안 읽는다.
  - **기록은 옵트인** — `netmon.enabled`(기본 **off** · 설정 고급 › 네트워크 점검)일 때만
    호스트가 주기(`netmon.interval_s` 기본 10초)마다 스냅숏 델타 한 줄을
    `data/logs/netmon-YYYYMMDD.log`에 남긴다(M3-22 StatusLog 파이프라인 재사용 —
    bounded 큐·논블로킹·일자 회전·프리픽스별 보존 정리).
- **봉투 원리** — 남는 것은 **횟수·바이트 수뿐**. 주소·신원·내용은 세지도 않는다.
- **줄 포맷(안정 — 분석 파서 계약)**: `netmon dt_ms=… dtx=… drx=… dself=… co=… cok=…
  ci=… stxf=… srxf=… stxb=… srxb=…[ warn=태그,…]`
  (dtx/drx = 발견 발신/수신 데이터그램 · dself = 자기 에코 · co/cok/ci = 연결
  시도/성립/수락 · stx\*/srx\* = 세션 프레임/바이트).
- **과다 판정**(임계 = 코드 상수 · 초과 구간은 `warn=` 태그 + **상태바 경고** — 로그를
  안 열어도 폭주를 안다): 발견 발신 25pps · 발견 수신 100pps · 연결 분당 30회.
  세션 바이트는 경고하지 않는다(파일 전송이 정당한 대량 트래픽이라 — 기록만).
- 한계(정직): 상대별·주소별 분해는 없다(봉투 원리와 상충 — 필요해지면 별도 결정).
  CLI 수집은 `NEXA_NETMON` 환경변수(26 §3-5 6항).
- **점검 기록·기준선 = [39 네트워크 점검 기록부](39-netmon-records.md)** —
  회차별 실측이 시간 역순으로 쌓인다(1회차 08-21 = 기준선 수립).

## 8. 열린 질문 (ADR-0002에서 결정)

1. **자체 프로토콜 vs mDNS/DNS-SD 표준** — 표준은 상호운용·기존 인프라 친화, 자체는 크기·제어권. [03](03-competitive-landscape.md)에서 LocalSend는 mDNS, IP Messenger는 자체 UDP를 택했다.
2. **IPv6 우선 vs IPv4 우선** — 사내망 현실은 아직 IPv4 우세.
3. **TCP vs QUIC/DTLS** — 암호화를 L4에 붙일지 그 위에 둘지와 얽힌다(DR-7은 "전송 위"를 요구).
4. **발표 주기와 이탈 판정 타임아웃** — 목록 신선도 ↔ 트래픽·배터리(DR-5)의 트레이드오프. E-8 실측 후.
5. **S5(스캔) 기본값과 동의 UX** — 보안 장비 오탐 리스크.
