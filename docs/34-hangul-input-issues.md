## 0. 먼저 알아야 할 것 — **입력 경로가 두 갈래다**

이 앱은 한글을 **두 방식**으로 받는다. 이슈를 읽기 전에 이 구분이 필요하다.

| 경로 | 어디서 | 조합을 누가 하나 | 근거 |
|---|---|---|---|
| **A. IME 경로** | 대화 입력 · 프로필 · 주소 · 설정 등 **모든 텍스트 필드** | **OS IME**(preedit → commit) | 일반 텍스트 입력의 관례 |
| **B. 직접 조합 경로** | **목록 타입어헤드**(이름 점프) | **앱**(두벌식 오토마타) | IME 세션 소유권 문제 — [27 §2·3](27-typeahead-hangul-composition.md) |

> ★ **B가 존재하는 이유가 이 영역의 모든 것을 설명한다.** macOS·winit에서 앱은 **IME 조합 세션을
> 끝낼 방법이 없다**(ESC만 IME에 직접 닿는다). 타임아웃으로 화면을 지워도 **세션은 살아 있다.**
> 그래서 타입어헤드만 IME를 떠났다. 나머지는 여전히 IME 위에 있고, **아래 이슈 대부분은 그 위에서 났다.**

## 2. 이슈 상세

### 2-1. H-1~H-4 — 타입어헤드 조합 붕괴 (이 영역의 출발점)

| | |
|---|---|
| **증상** | 목록에서 이름을 치면 `ㅣㅁ`처럼 깨지거나(H-1), 한/영 전환 첫 키가 사라지거나(H-2), 2초 뒤 **묵은 글자가 되살아나거나**(H-3 — `김` → 대기 → `최` = `김최`), 잔여가 계속 섞였다(H-4) |
| **핵심 관찰** | **ESC를 누르면 그 뒤로는 정상**(95%+). 즉 2초 타임아웃은 **우리 화면만 지우고 IME 세션은 못 끝낸다** |
| **다섯 번의 헛수고** | 자모 필터 → `ime_composing` 가드 → stale 접두사 제거 → 보류-판정 → `set_ime_allowed` 토글. **전부 IME 위에서 보정하려 했고 전부 부분적으로만 맞았다** |
| **판정** | macOS는 **marked text를 앱이 버릴 수 없다.** 세션의 시작·유지·확정·취소가 전부 OS 소관이고 앱에는 끝낼 API가 없다 → **앱 레벨 보정으로는 결정적 동작을 보장할 수 없다** |
| **처방** | **타입어헤드만 IME를 끄고**(`set_ime_allowed(false)`) 키보드가 주는 raw 자모를 **앱이 두벌식 오토마타로 직접 조합**한다 |
| **근거** | [27 §1~§4](27-typeahead-hangul-composition.md) |

> ★ **이 결정이 나머지 모든 이슈의 배경이다.** "직접 제어"는 타입어헤드에만 적용됐고,
> 일반 텍스트 필드는 여전히 IME 위에 있다 — 그래서 §2-3~§2-6이 계속 나왔다.

### 2-2. H-5~H-6 — **Windows는 자모를 주지 않는다**

mac에서 만든 직접 조합이 Windows에서 **통째로 무동작**이었다.

| | |
|---|---|
| **증상** | 목록(IME off)에서 한글을 쳐도 **라틴만 온다.** 한/영 키도 안 듣는 것처럼 보였다 |
| **원인** | Windows는 IME를 끄면 **자모 자체를 안 준다**(mac은 준다). "IME off = raw 자모"라는 mac 관찰이 **Windows에서 성립하지 않았다** |
| **처방** | **QWERTY → 두벌식 매핑을 앱이 한다**(`jamo_from_qwerty`) + **한/영 상태를 앱이 소유**(`hangul_mode` 토글) |
| **H-6 반전** | 한/영 키는 **앱에 닿고 있었다** — `VK_HANGUL` → `NamedKey::HangulMode`(물리 `Lang1`)가 **IME 비연결 창에도 도달**한다(실기 실증). 못 닿는 게 아니라 **앱이 안 쓰고 있었다** |
| **근거** | [27 §8](27-typeahead-hangul-composition.md) · `345df9e` |

> ★ **교훈** — *"한 OS에서 관찰한 입력 동작을 다른 OS의 규칙으로 쓰면 안 된다."*
> 이 저장소가 반복해 밟은 함정이고, 조건부 컴파일 코드는 **반대편을 실행해 볼 수 없다**는 게
> 그 이유다([mux `recv_any` Group 누락](32-adr-0013-server-modes.md)도 같은 계열).

### 2-3. H-7 — 조합 중 Enter 잔향 (**결론이 두 번 뒤집혔다**)

| | |
|---|---|
| **증상** | Windows에서 조합 중 Enter가 **조합 확정에서 멈추지 않고 전송까지** 나갔다 |
| **원인** | **Windows IME는 조합을 끝낸 키를 앱에 또 준다** — `Commit` 직후 같은 Enter의 `KeyboardInput`이 별도 도착한다. macOS는 marked text가 삼켜서 안 온다. 기존 `ime_composing` 가드는 Commit이 플래그를 먼저 내려 이 **잔향**을 못 막는다 |
| **1차 수정** | 종료 직후 120ms 안의 Enter/Esc 키다운을 1회성으로 삼킴(`ime_cleared_ms` · `take_if`) → **조합만 확정, 전송은 두 번째 Enter** |
| **★ 사용자 확정으로 뒤집힘** | 재실기 결과 *"조합 완료와 전송이 **동시에**"* 가 원하는 동작. **잔향을 일부러 통과**시킨다 — `Commit`이 버퍼에 먼저 합류한 뒤 Enter가 전송하므로 한 번에 된다 |
| **왜 그게 맞나** | Windows 메신저 관례(카카오톡류) · `chat-live` 콘솔(conhost IME)과 동일 · **DR-16 "동작 = OS 네이티브"** |
| **Esc는 유지** | 조합 취소 잔향이 **화면 닫기로 새는 것**은 의도일 수 없다 → Esc만 계속 차단 |
| **mac은 그대로** | IME가 키를 삼켜 **확정만 되는 2단**. OS별 관례 차이를 그대로 둔다 |
| **근거** | `cf51c70` → `e1c2c7f` |

> ⚠️ **"홍길ㄷ" 잘림은 이 문제가 아니었다** — 마지막 음절을 치기 전에 Enter를 누른 **타이핑 타이밍**이다.
> `Commit`이 선행 합류하므로 잘리지 않는다. 증상 보고를 그대로 원인으로 받으면 틀린 것을 고치게 된다.

### 2-4. H-8~H-11 — **창이 늘어날 때마다 같은 구멍**

그룹 방(공유 그룹 채팅)이 생기자 IME가 **거기서만** 안 됐다.

| # | 증상 | 원인 | 처방 |
|:--:|---|---|---|
| **H-8** | 그룹 방에서 프리에딧 미표시 | `Ime::Preedit` 라우팅이 **1:1·목록에만** 있었다 | `group_chat_for()` 신설 · 대칭 배선 |
| **H-9** | 포커스 이탈 시 조합 중 음절 유실 | 창을 벗어나면 조합 중이던 것이 사라졌다 | `ime_preedit` 보존 + `Focused(false)`에서 확정 합류 · `Preedit("")` 선행 순서 역전 대비 **300ms 스태시** |
| **H-10** | 재포커스 때 `내` → `ㄴㅐ` | 유출된 자모가 조합되지 않고 낱개로 들어갔다 | **유출 조합기**(`leak` — 두벌식 Composer 재사용)로 음절 조합 |
| **H-11** | 조합 중 `?` 삼킴 | 보류-판정이 **자모만** 대상이었다 | 비자모 문자도 보류-판정 — Commit 본문에 있으면 폐기, 없으면 본문 뒤 방출 |
| **근거** | | | `3a3894f` |

> ★ **패턴이 보인다** — *새 입력 창을 만들 때마다 IME 배선을 빠뜨린다.* H-8은 그룹 방,
> [H-12](#2-5-h-12h-13--일반-필드와-단축키)는 프로필·주소 필드였다. **이게 [M3-1e 입력 스택 단일화](TODO.md)가 필요한 이유다.**

### 2-6. H-14~H-16 — **트레이스가 가설을 뒤집었다**

`NEXA_IME_TRACE=1`로 실제 이벤트 순서를 찍어 보고서야 그동안의 전제가 틀렸음이 드러났다.

```
key=Character("ㄴ")   ← ★ 첫 키는 keydown으로 유출된다
preedit="ㅏ"          ← IME는 둘째 키부터 조합한다
commit="ㅏ"
```

| # | 증상 | 뒤집힌 전제 | 처방 |
|:--:|---|---|---|
| **H-14** | 첫 글자가 버려진다 | *"Preedit 도착 = 보류 자모는 중복이니 폐기"* — **틀렸다.** 첫 키는 IME가 안 먹고 유출된다 | 프리에딧이 **그 자모로 시작할 때만** 폐기 · 아니면 유출 조합기에 합류 · 뒤따르는 낱개 Commit 자모도 feed해 `나`로 수렴 |
| **H-15** | 공백이 두 번 들어간다 | `commit=" "` 직후 `key=Named(Space)`가 **또** 온다 | `ime_commit_echo` — 120ms 안 같은 문자 키다운을 **1회 소비**(진짜 연타는 통과) |

### 2-7. H-22~H-24 — **"나다다": 표시를 세 번 고치고서야 입력 문제였다**

프로필 표시 이름에 `나다`를 치고 **작업 표시줄을 클릭**하면 `나다다`가 됐다.
**세 번 고쳐서야 잡혔고, 앞의 두 번은 엉뚱한 계층을 고치고 있었다.**

| 회차 | 무엇을 고쳤나 | 결과 |
|:--:|---|---|
| 1차 | H-22 — 아바타 이니셜이 **확정 버퍼만** 봐서 필드(`나다`)와 아바타(`나`)가 달랐다 → `display_text()`(프리에딧을 캐럿 자리에 끼운 표시용)를 아바타도 쓰게 | 아바타는 맞았지만 **`나다다`는 그대로** |
| 2차 | H-23 — 포커스 이탈 확정 때 Windows IME는 `Commit("다")`만 보내고 **화면 소거용 `Preedit("")`를 안 보낸다.** Commit 핸들러가 *"다음 Preedit가 온다"* 고 가정해 위젯 표시를 안 지웠다 → Commit에서 즉시 소거 | **여전히 재현** |
| **3차** | **H-24 — 증거를 다시 읽었다.** 아바타 `나다`는 **이니셜 2자 절단**이라 *버퍼가 맞다는 증거가 아니었다.* 버퍼가 진짜 `나다다`인 **이중 입력**이었다 | ✅ 해소 |

**H-24의 실제 원인 — 순서가 가정과 반대였다**

```
작업표시줄 클릭
  → Focused(false)  먼저 도착   → H-9 처방이 프리에딧 "다"를 수동 확정 합류 (의도대로)
  → Commit("다")    늦게 도착   → ★ 한 번 더 라우팅 = "나다다"
```

사용자 실측 *"Enter로 확정한 뒤엔 괜찮다"* 와 정합한다 — **Enter는 Commit을 정상 소비**해 잔향이 없다.

**처방** — `ime_selfcommit`: 수동 확정한 `(창, 본문, 시각)`을 기억하고 **1초 안 같은 창·같은 본문의
Commit을 1회 삼킨다**(표시 소거만, 라우팅 생략). 불일치·초과는 정상 입력.
Commit이 먼저 오는 **반대 순서에도 안전**하다 — 그땐 `ime_preedit`이 비어 수동 확정 자체가 없다.
**어느 순서든 정확히 한 번.**

**근거** — `9a08c0c`(1차) · `7526096`(2차) · `348e2bb`(3차) · `b2ce409`(사용자 확정 해소)

> ### ★ 여기서 두 가지가 드러났다
>
> **① 조합 종료 경로가 셋인데 소거 책임자가 달랐다** — *다음 Preedit* · *Enter* · *포커스 이탈 Commit*.
> 앞의 둘만 상정한 코드가 셋째에서 깨졌다.
>
> **② 잔향 억제가 이걸로 네 번째다** — H-7(Windows Enter) · H-15(mac Space 이중 배달) ·

> → [M3-1e ②](TODO.md)의 *"종료 경로별 잔향 표"* 가 정확히 이 자리다.

**H-25 · 전체 선택 후 조합 입력이 선택을 대체하지 않는다** (mac 실기 08-14)

**H-26 · 한글 조합 직후 1byte 문자 첫 타 유실** (mac · Windows 테스트 전부터 잔존)

1. **`ImeGate` 순수 상태기계**(입력: keydown/preedit/commit/focus 이벤트 스트림 → 출력:
   버퍼 반영 명령): 지금 app.rs에 흩어진 게이트·보류·잔향·유출 조합을 **한 타입**으로.
   **H-25의 "프리에딧 시작 = 선택 삭제"도 이 상태기계의 출력 명령**으로 정의한다(위젯별
   재구현 금지).
2. **트레이스 재생 회귀**: H-14~H-16·H-24 + 이번 수집분의 **실측 이벤트 순서를 그대로
   테스트 입력**으로 박제 — "고쳤다"의 정의가 *그 순서를 재생해도 버퍼가 맞다*가 된다.
3. 우선순위: **H-26 수집 → ImeGate 추출(기존 동작 보존 스냅숏) → H-25·H-26을 상태기계
   규칙으로 처방 → 위젯은 명령 소비만**. 이 순서를 지키면 이후 한글 이슈는 "규칙 추가
   + 재생 케이스 추가"로 끝난다.

## 3. 진단 도구 — 추정하지 말고 찍어 본다

```bash
NEXA_IME_TRACE=1 ./target/release/nexa-beep --window --live
```

IME 이벤트(`key=` · `preedit=` · `commit=`)를 도착 순서대로 출력한다.
**한글 입력 문제를 만나면 가설을 세우기 전에 이걸 먼저 켠다** — H-14~H-16은 전부 이걸로 뒤집혔다.

| 찍히는 것 | 읽는 법 |
|---|---|
| `key=Character("ㄱ")` | **IME를 거치지 않은 유출** — 이게 보이면 앱이 조합을 책임져야 한다 |
| `preedit="가"` | 조합 중(확정 전) — 화면에 밑줄로 보여야 한다 |
| `commit="가"` | 확정 — 버퍼에 합류 |
| `commit` 직후 같은 `key=` | **잔향**(Windows Enter·mac Space) — 억제 대상인지 판단 |

### 4-3. ★ 근본 처방 — [M3-1e 입력 스택 단일화](TODO.md)

**이 문서의 이슈 절반은 "새 창을 만들 때 IME 배선을 빠뜨려서" 났다.** 고칠 곳이 창마다 흩어져 있는 한
같은 종류가 계속 난다. 사용자 요청(08-13 — *"문제가 퍼지지 않고 한 군데서 해결"*)으로 등록됐다:

| | 내용 |
|---|---|
| ① **`TextInput` 공용 코어** | 편집 상태·프리에딧·선택 반전·드래그/자동 스크롤·우클릭 메뉴·⌘단축키를 **한 컴포넌트로**. 단일 행·다중 행·콤보가 위임해 쓴다 |
| ② **IME 중재 상태기계 추출** | 조합 게이트·보류-판정·유출 조합기·잔향 억제를 **순수 모듈**로 빼고, **트레이스 실측 순서를 회귀 테스트로 박제**(첫 키 유출·낱개 Commit·이중 배달·조합 중 이동 키) |

②가 특히 중요하다 — 지금 이 지식은 **`app.rs`의 조건 분기에만** 있고 테스트가 없다.
순서가 한 번 더 뒤집히면 **어디가 깨지는지 알 방법이 없다.**

### 4-4. 처방 계획 — 목표·대상·검증 (08-14 2차 수집 판정 기반)

**수정 목표 3** (착수 순서 = G3 → G1 → G2 · "하나씩" 원칙):

| # | 목표 | 성공 기준 |
|---|---|---|
| **G3** | **ImeGate 순수 상태기계 + 트레이스 회귀 박제**(선행 — 기존 동작 스냅숏) | app.rs의 IME 분기(pending_jamo·pending_arrow·leak·잔향·프리에딧 보존)가 ImeGate 호출로 대체 · `S1~S3.trace` 원문 재생 테스트 green(기대 버퍼 문자열 비교) |
| **G1** | **1byte 세션당 1회 소비 보충**(H-26 · winit 경계) | 재현 배터리에서 `홍길동123aBc최고다!!!` 전량 도달 · 평시 키 **이중 주입 0**(보충이 과하면 두 번 들어간다 — 반대 방향 회귀) |
| **G2** | **비-Enter 저장 트리거의 조합 확정**(이슈 ③ 잔여 + H-25) | "다" 조합 중 상태에서 Choose 클릭/공유 토글/필드 전환/창 닫기 → 저장·전파 값에 "다" 포함 · 전체 선택 + 조합 시작 = 선택 대체 |

**수정 대상**:

- G3: 신규 `ime_gate` 순수 모듈(입력 = keydown/preedit/commit/focus/tick 스트림 →
  출력 = 버퍼 명령) + 재생 하네스(트레이스 파서). app.rs는 명령 소비만.
- G1: ① **winit 조사 먼저**(현재 0.30.13 — 상류에 해당 이슈·수정 버전 있으면 갱신으로
  끝) ② 없으면 `nbeep-plat` mac 어댑터(NSEvent `addLocalMonitor` keydown 관측) +

  확정 규칙이 그대로 조건) · DR-21 이음새(trait 뒤) · 등록 해제 포함(13 §12-1).
- G2: ImeGate 출력 명령 `CommitPreedit`을 저장 트리거 직전(take_changes·창 닫기·
  포커스 전환)에 배선 — Focused(false)의 기존 확정 합류를 일반화.

**검증 체크리스트**(각 단계 후 게이트 + 자동 실기 배터리 재실행 — 이번 스크립트 재사용):
