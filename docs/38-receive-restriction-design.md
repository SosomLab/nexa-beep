# 38. 수신 제한(차단) 목록 — 4축 설계 📐 (M5-3 스팸 방어 1차 · 2026-08-21)

> **상태: 설계 확정(사용자 4문항 확정 08-21) · 구현은 요청 시.**
> 발단 = 사용자 요청: *"익명 메신저 특성상 불필요한 과다 송신자가 발생할 수 있으므로
> PeerId·UserId·IP·Display name 4가지 Layer로 제한 대상을 지정하고, 해당 목록
> 사용자의 패킷은 무시하도록"*. v1.0 커트라인의 마지막 실질 공백인 **M5-3 스팸
> 방어의 1차 슬라이스**가 된다(R-4).

## 1. 원칙 — 네 축은 등가가 아니다

기존 결정과의 정합이 설계의 뼈대다:

| 축 | 성격 | 근거 강도 | 기존 결정 |
| --- | --- | --- | --- |
| **PeerId** (기기 키) | **신원 차단** — v1 주축 | 암호학적(위조 불가) | v1은 PeerId=UserId 1:1 (DR-20 V1-1) |
| **UserId** (사람) | 신원 차단 — v2 승격 자리 | 암호학적(서명 검증) | **"차단은 기기가 아니라 사람 단위"**(DR-20 — 기기 차단은 새 기기 추가로 우회) |
| **IP / CIDR** | **경로 차단** — 새 키 재생성 우회 대응 | 약함(DHCP 재할당·NAT 공유 = 무고 차단 위험) | "IP는 병합·신뢰의 근거가 아니다" · DR-28(경로 등급은 경로에) |
| **DisplayName** | **표시 필터** — 저비용 스팸 이름 대응 | 가장 약함(공격자가 즉시 변경) | R-19 계열 — 이름은 사용자 주장일 뿐 |

정책 결합 = **OR**(어느 축이든 걸리면 무시). 판정 순서 = **비용 순**: IP(소켓
직후·파싱 전) → PeerId(핸드셰이크 확정 후) → DisplayName(발견 패킷 파싱 후).
각 층은 자기가 아는 것만으로 판정한다(봉투 원리).

## 2. 확정 결정 (사용자 4문항 · 08-21)

| # | 질문 | 확정 |
| --- | --- | --- |
| B-1 | 차단 가시성 | **그림자 차단** — 받는 쪽에서 조용히 폐기, 상대는 차단을 모른다(우회 동기 억제 · 스팸 방어 표준). 발견 응답도 평소처럼 |
| B-2 | IP 차단 적용 지점 | **TCP accept 즉시 끊기** — Noise 핸드셰이크 비용(CPU·메모리) 자체를 차단(연결 폭주 방어). 발견 UDP는 recv 직후 파싱 전에 폐기 |
| B-3 | 빈도 기반 자동 차단 | **포함 — 자동 '임시' 차단**(기본 10분) + 상태바 고지 + 목록에서 해제 가능. **영구 차단은 항상 사람이 결정** |
| B-4 | 기간·이름 매칭 | **기간부**(1시간/24시간/7일/영구 — IP 기본 24시간·신원 축 기본 영구) + 이름은 **정규화 후 정확 일치만**(부분 일치 오차단 배제) |

> B-2 유의(그림자와의 긴장): accept 즉시 끊기는 상대가 "연결 실패"로 인지한다 —
> 완전한 그림자는 아니다. 그러나 연결 실패는 오프라인·방화벽과 구분되지 않아
> **차단으로 특정되지 않는다**(자원 방어가 이 모호함보다 우선 — 확정 취지).

## 3. 판정 지점 (와이어 경로별)

```
발견 UDP recv ──[IP]──> Packet 파싱 ──[PeerId]──[이름]──> PeerTable 반영
TCP accept   ──[IP 즉시 close]──> Noise 핸드셰이크 ──[PeerId 즉시 종료]──> 세션
세션 수신(메시지·파일·그룹 초대·프로필) ──[PeerId]──> 표시/게이트
아웃바운드   ──차단 상대 자동 연결(재연결·큐 flush·그룹 팬아웃) 금지
```

- **발견**: 차단 상대의 광고는 버린다 → 목록에서 사라진다(그림자 — 내 광고 응답은
  평소대로 나간다: 응답 중단은 차단을 드러낸다).
- **세션 인바운드**: IP는 accept에서, PeerId는 핸드셰이크 **완료 시점**에(그전엔
  신원을 모른다 — 암호학적 확정 후 종료). 종료는 오류 회신 없이 소켓만 닫는다.
- **기존 대화**: 차단해도 스레드·기록은 남는다(뷰에서 숨김 · 해제 시 복귀).
  차단 중 수신분은 폐기(나중에 보이지 않는다 — "무시"의 뜻).
- **파일·그룹**: 세션이 애초에 안 서므로 자동 무시. 진행 중 전송은 차단 즉시 취소.

## 4. 자료 구조·영속

```rust
enum BlockAxis { Peer(PeerId), User(UserIdRef /* v2 */), Ip(IpCidr), Name(String /* 정규화 */) }
struct BlockEntry { axis: BlockAxis, added_unix: u64, until_unix: Option<u64> /* None = 영구 */,
                    auto: bool /* 자동 임시 차단 여부 */, note: Option<String> }
```

- 저장 = **신뢰 저장소(`trust.seg`) 확장**(래핑 키 봉인 — IP·이름은 PII라 평문
  3면 원칙 그대로). 기존 `blocked` bool(PinRecord)은 이 목록으로 **승격 이관**
  (부팅 1회 — Peer 축·영구·auto=false).
- 조회는 부팅 시 메모리 로드 + 변경 시 저장(핀과 같은 규약). 발견 hot path의
  IP 대조는 `HashSet<IpAddr>`+CIDR 목록(항목 수십 규모 — 선형 무해).
- 만료 = 조회 시점 게으른 판정(`until < now` = 통과·목록 정리는 부팅/저장 때).

## 5. 자동 임시 차단 (B-3 · netmon과의 관계)

- **계수는 상대별**이어야 한다 — netmon(06 §7-1)은 전역 합계라 판정 근거로 쓸 수
  없다. 앱 계층에 상대별 슬라이딩 창 계수기(`ledger` 곁)를 둔다:
  - 메시지: 같은 상대 **초당 5건 초과가 10초 지속** → 임시 차단(기본 10분).
  - 발견: 같은 (PeerId, IP)의 광고가 **정상 주기의 10배**(≈12pps) 초과 지속 →
    발견 반영 스로틀(목록 유지 · 갱신만 늦춤 — 차단이 아니라 감쇠).
  - 연결: 같은 IP의 인바운드 accept가 **분당 30회** 초과 → IP 임시 차단(10분).
- 발동 시 = 상태바 고지 + (log.enabled면) 상태 로그 한 줄 + 차단 목록에
  `auto=true`로 등재(해제·영구 승격은 사람이).
- 임계값은 코드 상수로 시작(netmon 임계와 같은 규약) — 실측 후 설정 승격 검토.

## 6. UI

- **목록/대화 우클릭 ▸ 차단**(Peer 축 · 기간 선택 서브메뉴) — 기존 우클릭 메뉴 확장.
- **설정 ▸ 차단 목록**(고급): 축·값·남은 기간·auto 표시 · 해제 · 수동 추가(IP/이름은
  여기서만 — 실수 방지) · IP 추가 시 무고 차단 경고 1줄.
- 차단 상태는 목록에서 **보이지 않는 것**으로 표현된다(별도 배지 불요 — 그림자).

## 7. 한계 (정직)

- **궁극의 우회는 막을 수 없다** — 익명 제로 컨피그(DR-1)에서 새 키+새 IP+새
  이름은 새 사람이다. 이 설계의 목표는 **우회 비용을 올리고 반복 소음을 없애는 것**
  (신원 축 = 정확 차단 · IP 축 = 재생성 우회의 마찰 · 자동 임시 = 폭주 감쇠).
- 완전한 방어는 M5-3 본편(FirstContact 승인제 · PoW/마찰 등)과 v2 UserId에서.
