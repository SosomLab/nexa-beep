# 15 · 개발 방법론 — 작은 단위 · 점진 프로토타이핑 · 단위별 커밋

> **출처**: `SosomLab/nexa-dir2` `docs/15-dev-methodology.md` 계승(2026-08-08 차용).
> 이 문서는 **개발 규율**, 기록·git 규약은 [16](16-doc-git-conventions.md)이 SSOT다.

## 1. 핵심 원칙

1. **수직 슬라이스** — 관찰·테스트 가능한 얇은 끝단 단위로 자른다(예: "브로드캐스트 1발 → 상대 목록에 1줄 뜬다").
2. **작게·순차로** · **초안 먼저, 확장은 별도 커밋** · **main 항상 green** · **단위 = 커밋 1개** · **테스트 동반**.
3. 큰 미지수는 **스파이크**(버릴 수 있는 실험)로 먼저 검증한다. 본 저장소의 대표 미지수 = **디스커버리가 실제 사내망에서 도달하는가**(멀티캐스트 차단·클라이언트 격리·다중 서브넷) → 설계 확정 전에 스파이크로 실측한다.

## 2. 본 저장소 추가 규율

- **네트워크는 문서보다 실측이 먼저.** 프로토콜 결정은 반드시 실측(도달률·지연·패킷 크기)을 근거로 남긴다. 추정으로 ADR를 쓰지 않는다.
- **기존 자산 우선** — 설계 전 [03 경쟁 조사](03-competitive-landscape.md)의 선행 사례를 먼저 확인(재발명 금지). 차용 시 출처를 커밋 본문에 명기.
- **브랜치**: 큰 단위마다 브랜치(`docs/…` `feat/…` `fix/…` `refactor/…`) → 세부 기능 단위 커밋 → green 확인 후 main 병합. **push는 사용자 명시 요청 시에만.**
- 커밋 규약: Conventional Commits `type(scope)` — scope는 아키텍처 확정 시 모듈명으로 고정하고 재사용한다(잠정: `disco` `net` `ui` `store` `pkg`).

## 3. 진행 추적

- 일자 상세 = `docs/journal/YYYY-MM-DD.md`(시간 역순) · 요약 = [DEVLOG](DEVLOG.md) · 기능/마일스톤 = [MILESTONES](MILESTONES.md) · 브랜치 이력 = [BRANCHES](BRANCHES.md).
- **한 작업 = 한 트랜잭션 갱신**: 코드 커밋 → journal 상세 → DEVLOG 한 줄 → MILESTONES/TODO 상태 → (브랜치 작업이면) BRANCHES 표.
