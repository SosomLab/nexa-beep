## 2. ① 발견 프로토콜 — 자체 컴팩트 UDP vs mDNS/DNS-SD

| 안 | 장점 | 단점 |
|---|---|---|
| **A. 자체 컴팩트 UDP**(단일 와이어 포맷을 S1~S5 전 단계에 재사용) | · **폴백 사다리 전 단계가 같은 포맷** — 멀티캐스트든 브로드캐스트든 유니캐스트 프로브든 코드가 하나<br>· 패킷 크기를 완전히 통제(<512B)<br>· **시스템 응답기에 의존하지 않는다**(Windows에 mDNS 응답기가 항상 있다고 볼 수 없고, Linux는 Avahi 유무가 갈린다)<br>· 5353 포트 점유 충돌 없음 | · 기존 도구와 상호운용 안 됨<br>· "표준이 아니다"라는 설명 부담 |
| **B. mDNS / DNS-SD**(LocalSend 방식) | · 표준 · 기존 인프라 친화<br>· 네트워크 진단 도구로 관찰 가능 | · **S1~S2만 커버** — S3(브로드캐스트)·S4(이웃 유니캐스트)·S5(스캔)는 어차피 별도 포맷이 필요하다<br>· 시스템 응답기와 **5353 바인딩 경쟁**(Avahi/Bonjour 유무·권한에 따라 동작이 갈림)<br>· TXT 레코드에 키 지문을 넣으면 크기·인코딩 제약<br>· 사내망에서 mDNS만 선택적으로 차단되는 사례가 있다 |
| **C. 둘 다** | 최대 도달 | 포맷 2벌 유지 + 중복 발견 병합 부담. **v1 범위 과다** |

### ✅ 결정: **A(자체 컴팩트 UDP)** — mDNS 광고는 v2 상호운용 옵션

**결정적 근거는 "폴백 사다리가 이미 필수"라는 점**이다. DR-14가 S1~S6를 요구하는 이상 **어차피 자체 포맷이 필요**하고, mDNS를 추가로 얹으면 **포맷이 둘, 병합 로직이 하나 더** 늘 뿐이다. 표준의 이점(상호운용)은 우리에게 지금 가치가 없다 — 우리와 대화할 상대는 우리뿐이다.

> v2에서 **DNS-SD 광고를 부가 기능으로** 얹을 수 있다(발견용 힌트로만). 그때도 **정본은 자체 포맷**이다.

### 와이어 포맷 (초안 — 바이트 배치는 M0에서 고정)

| 필드 | 크기 | 내용 |
|---|---|---|
| magic | 4B | `NXBP` |
| version | 1B | 프로토콜 버전. **미래 호환을 위해 미지 버전은 무시** |
| type | 1B | `HELLO` / `ANNOUNCE` / `PROBE` / `GOODBYE` |
| flags | 2B | 능력 비트(릴레이 지원·그룹·파일 등) |
| static_pubkey | 32B | **X25519 정적 공개키 — 이것이 곧 신원** |
| tcp_port | 2B | 세션 수신 포트 |
| epoch | 8B | 인스턴스 기동 시각(재시작 감지) |
| seq | 4B | 재전송·중복 억제 |
| name | 가변(상한) | 표시 이름 UTF-8. **정규화·제어문자 제거 후 저장**(FR-S-13) |

**총 512B 이하**를 강제한다(IPv6 최소 MTU 1280 여유 · 단편화 회피 — [06 §5-1](06-network-stack.md)).

### ★ 발견 패킷은 인증하지 않는다 — 대신 "미검증"으로 표시한다

발견 패킷에 서명을 넣으면 크기가 커지고, 넣어도 **재생 공격·신원 사칭을 완전히 막지 못한다**(공격자도 자기 키로 서명한 패킷을 뿌릴 수 있다). 그래서 **인증을 발견 단계에서 하지 않는다**:

- 발견 결과는 **"제안(hint)"** 일 뿐이다 — 이 시점의 목록 항목은 **미검증** 상태다.
- **신원은 오직 세션 핸드셰이크가 성립할 때 확정**된다([§4](#4--키-교환--인증--noise--tofu)).
- UI는 **미검증 / 검증됨(TOFU 고정) / 지문 대조 완료**를 시각적으로 구분한다.

> 이 선택이 패킷을 작게 유지하고(성능), 보안 주장을 정직하게 만든다(NFR-S-5 — 보증하지 않는 것을 보증하는 척하지 않는다).

### 포트

- 기본 **UDP/TCP 동일 포트 1개**를 쓰고 설정으로 변경 가능. 구체 번호는 M0에서 고정한다(IP Messenger의 2425 등 기존 사용 포트는 피한다).
- **바인딩 실패 시 대체 포트로 폴백**하고, 발견 패킷이 `tcp_port`를 실어 나르므로 세션은 여전히 성립한다.

## 3. ② 전송 · 세션

| 항목 | 결정 |
|---|---|
| 세션 | **TCP** — 순서·신뢰를 OS에 맡긴다. 대화·파일 모두 같은 세션 위에서 다중화 |
| QUIC | **채택하지 않는다**(v1) — 의존성·바이너리 크기가 NFR-B-3을 위협하고, LAN에서 TCP 대비 이득이 작다. 릴레이 모드(v2)에서 재검토 |
| 다중화 | 한 세션 안에서 **제어 / 대화 / 파일**을 논리 스트림으로 분리. 대용량 파일이 대화를 굶기지 않도록 **라운드로빈 + 청크 상한** |
| 프레이밍 | 길이 접두 프레임. **최대 프레임 크기 상한**을 강제(메모리 고갈 방어 — [04](04-safe-transfer.md) T-6) |
| 백프레셔 | 수신 측 윈도우로 송신 속도 제어. 큐에 **명시적 상한**(무한 큐 = 누수 — NFR-B-6) |
| 재연결 | 링크 변경(FR-D-5) 시 경로 후보를 순서대로 재시도. **세션 재수립 시 키 지문이 같아야 같은 대화로 이어 붙인다** |
| 대화 순서 | 논리 시퀀스 번호로 순서 보장. 오프라인 큐(FR-M-3)와 병합 시 시각이 아니라 시퀀스 기준 |

## 4. ③ 키 교환 · 인증 — Noise + TOFU

### 후보

| 안 | 평가 |
|---|---|
| **A. Noise Protocol Framework** — `Noise_XX`, X25519 + ChaCha20-Poly1305 + BLAKE2s | **✅ 채택.** 형식 분석이 된 표준 프레임워크, WireGuard 등 실전 검증. **정적 공개키 = 신원**이 우리 모델과 정확히 일치. 구현이 작아 NFR-B-3에 유리. 핸드셰이크 해시가 **SAS(지문 대조) 재료**를 그대로 준다 |
| B. TLS 1.3 + 자체 서명 인증서 핀닝 | 널리 쓰이나 **인증서라는 개념이 우리에게 잉여**다(발급자가 없다). LocalSend가 이 길을 갔고 [03 §6-2](03-competitive-landscape.md)에서 확인했듯 **MITM을 못 막는다**. 구현체도 무겁다 |
| C. 직접 조립(X25519 + AEAD 수동 핸드셰이크) | **NFR-S-3 위반** — 자체 암호 프로토콜 설계 금지. 검토 대상 아님 |

### ✅ 결정: `Noise_XX` (X25519 / ChaCha20-Poly1305 / BLAKE2s)

`XX` 패턴을 고르는 이유 — **양쪽이 핸드셰이크 중에 서로의 정적 공개키를 전달**한다. 사전 등록이 없는(DR-1) 우리 상황에서 상대 키를 미리 알 수 없으므로, 미리 아는 것을 전제하는 패턴(`IK` 등)은 **첫 접촉에 쓸 수 없다**.

> **최적화 여지**: 이미 TOFU로 고정된 상대와의 **재연결**에는 상대 정적 키를 알고 있으므로 왕복이 적은 패턴으로 전환할 수 있다. v1은 단순함을 위해 `XX` 하나로 통일하고, 성능 문제가 실측되면 그때 추가한다.

### TOFU 규칙 (FR-S-3)

| 상황 | 동작 |
|---|---|
| 최초 성립 | 상대 정적 공개키를 **고정(pin)** 하고 지문을 저장. 상태 = **검증됨** |
| 같은 지문으로 재연결 | 정상 진행 |
| **지문이 바뀜** | 🔴 **기본 차단**. 눈에 띄는 경고 + "재설치/기기 교체일 수 있고, 사칭일 수도 있습니다" 안내. 사용자가 명시 수락해야 갱신하고, **이력을 남긴다** |
| 같은 지문, 다른 IP | 정상 — 경로만 갱신(다중 인터페이스·DHCP 변경은 일상) |
| 같은 이름, 다른 지문 | **다른 사람으로 취급.** 이름은 표시일 뿐 신원이 아니다(FR-S-2) |

> ⚠️ **TOFU가 막지 못하는 것을 문서에 남긴다** — **최초 접촉 시점**에 이미 중간자가 있으면 그 키가 고정된다. 이건 신뢰 앵커가 없는 시스템의 구조적 한계이고(R-1·V-1), 그래서 **SAS**를 둔다.

### 지문 대조(SAS — FR-S-4)

- Noise **핸드셰이크 해시**에서 짧은 인증 문자열을 파생한다. 양쪽 화면에 **같은 값**이 뜬다.
- 표기: **한국어 단어 나열** 또는 **이모지 시퀀스** — 전화·대면으로 읽어 대조하기 쉬운 형태. (구체 인코딩은 M1에서 UX와 함께 확정)
- **선택 기능**이다. 강제하면 DR-1(설정 0개)의 감각이 깨진다. 대신 **중요 대화·파일 승인 화면에서 "아직 대조 안 됨"을 눈에 띄게** 표시해 자연스럽게 유도한다.

### 키 관리

- 최초 실행 시 **X25519 정적 키쌍 자체 생성**. 개인키는 **로컬에만**(NFR-S-1).
- **포터블 모드(DR-4)** 에서는 실행 파일 옆 데이터 폴더에 저장 → **USB로 옮기면 신원도 따라간다.** 이 성질을 문서에 명시한다(장점이자 위험 — 매체 분실 시 신원 유출).
- 키 저장은 OS 자격 증명 저장소가 아니라 **파일 + 파일 권한**으로 시작한다(포터블 요구와 T0 무권한 요구 때문). 강화 옵션은 v2.
- **키 재생성(신원 초기화)** 기능 제공 — 상대에게는 "지문 변경"으로 보인다.

### 암호 사용 규칙

- 세션 데이터는 Noise 트랜스포트 단계의 **AEAD**로 보호. 논스 관리는 프레임워크 규칙을 따른다.
- **파일 전송도 같은 세션 암호를 탄다** — 별도 경로를 만들지 않는다.
- **암호화는 전송 계층 "위"**(DR-8) — 릴레이 모드(v2)에서도 서버는 봉투만 본다(FR-R-3).

## 5. 발견 절차 (S1~S6 구체화)

> 각 단계의 **타이밍·재시도 횟수는 D-8 실측 후 확정**한다. 여기서는 **순서와 판단 규칙**만 정한다.

```
기동 → 인터페이스 열거(L1) → 후보 인터페이스마다 병렬로:
  S1 IPv6 링크로컬 멀티캐스트 ANNOUNCE
  S2 IPv4 멀티캐스트 ANNOUNCE           (S1과 동시 시도 — 순차 대기 금지)
  S3 UDP 브로드캐스트(제한 + 서브넷 지향)
      ↓ 위에서 아무 응답 없음
  S4 이웃 테이블(ARP/NDP) 조회 → 각 이웃에 유니캐스트 PROBE   ← 클라이언트 격리 대응
      ↓ 여전히 없음 · 사용자가 켠 경우에만
  S5 서브넷 유니캐스트 스캔(속도 제한 · /24 초과 금지 · 사전 동의)
      ↓
  S6 수동 주소 입력(ADR-0006 — LAN 밖 공인 IP 포함) · 릴레이 모드(v2)
```

**규칙**
- **S1~S3은 동시에** 쏜다(순차로 기다리면 NFR-B-8 ≤3초를 못 지킨다). S4 이후만 순차 상승.
- **성공한 단계를 인터페이스별로 기억**해 다음부터 먼저 시도한다.
- 발표는 **이벤트 기반(기동·링크 변경·수동 새로고침) + 저빈도 주기**. 고빈도 폴링 금지(NFR-B-7).
- 이탈 = **GOODBYE 수신** 또는 **무응답 타임아웃**(FR-D-8). GOODBYE는 유실될 수 있으므로 타임아웃이 정본.
- **자기 자신 패킷은 정적 공개키로 걸러낸다**(멀티캐스트 루프백 대응).

## 6. 위협 대응 매핑

| 위협 | 대응 |
|---|---|
| **MITM(최초 접촉)** | 구조적으로 완전 차단 불가(R-1). TOFU 고정 + **SAS 대조 유도** + 지문 변경 시 기본 차단 |
| 신원 사칭(발견 단계) | 발견은 **미검증 힌트**일 뿐. 핸드셰이크 성립 전까지 신원 주장 없음 |
| 재생 공격 | `epoch`·`seq` + Noise 트랜스포트 논스 |
| 발견 패킷 홍수 | 발신 IP/키별 **속도 제한**, 목록 상한, 미검증 항목 별도 취급(FR-S-16) |
| 메시지 스팸 | 세션 성립 후에도 발신자별 속도 제한 + 차단 목록(FR-S-16) |
| 대용량 프레임으로 메모리 고갈 | 프레임 상한 + 백프레셔(§3) |
| 스캔 오탐(보안 장비) | S5 기본 꺼짐 + 사전 동의(FR-D-4) |

## 7. 결과 (Consequences)

### 긍정
- **폴백 사다리 전 단계가 하나의 와이어 포맷**을 공유 → 코드·테스트가 한 벌.
- Noise 채택으로 **자체 암호 설계 위험 0**(NFR-S-3)이면서 구현 크기가 작다.
- **정적 공개키 = 신원**이 DR-8(2모드), FR-D-6(다중 경로 병합), FR-S-2를 **한 번에** 만족시킨다.
- 발견을 미검증으로 취급해 **보안 주장이 정직해진다**.

### 부정 · 감수
- **표준 프로토콜과 상호운용되지 않는다.** 기존 LAN 메신저·mDNS 도구와 대화 불가.
- TOFU는 **최초 접촉 MITM을 막지 못한다** — SAS를 쓰지 않는 사용자에게는 남는 위험.
- 포터블 신원 파일은 **매체 분실 시 신원 유출** 위험.
- QUIC 미채택으로 릴레이 모드(v2)에서 NAT 통과 설계를 다시 해야 할 수 있다.
