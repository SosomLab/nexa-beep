# 05 · 요구사항 (FR / NFR / 제약 / 리스크)

> [00 비전](00-vision.md)을 **검증 가능한 요구**로 옮긴 문서. 근거는 [03 경쟁 조사](03-competitive-landscape.md), 결정은 [10](10-decision-record.md), 설계는 [04](04-safe-transfer.md)·[06](06-network-stack.md).
> **작성 2026-08-08.** 각 요구는 [18 빌드&테스트](18-build-and-test.md)에서 검증 절차를 갖는다.
>
> **범위**: `v1` = 1차 출시 · `v2` = 이후 · **우선**: P0(정체성·게이트) · P1 · P2.
> **ID 규칙**: `FR-<영역>-n` / `NFR-<영역>-n` — 부여 후 **불변**.

### 1-5. 보안 (Security)

| ID | 요구 | 우선 | 범위 | 근거 |
|---|---|:--:|:--:|---|
| **FR-S-1** | 모든 대화·파일은 **단말 간 종단 암호화(E2E)** 된다. **전송 경로(직접/릴레이)와 무관** | P0 | v1 | DR-7 |
| **FR-S-2** | **신원 = 기기 키 지문.** 계정·IP·MAC은 신원이 아니다. 키쌍은 최초 실행 시 자체 생성. **PC 1대 = 노드 1개**가 기본이다. **개정(08-08 · DR-20)**: "사용자 개념을 두지 않는다"를 **"기본은 두지 않되 선택 계층으로 얹는다"** 로 정정 — **대화 스레드·기록·차단 목록의 키는 `UserId`** 로 두고 **v1은 `UserId == PeerId` 1:1**(V1-1) | P0 | v1 | DR-8 · **DR-18** · **DR-20** |
| **FR-S-3** | 키 인증은 **TOFU 기본** — 최초 접촉 시 공개키를 고정하고, 이후 키가 바뀌면 **경고**한다 | P0 | v1 | [03 §6-2](03-competitive-landscape.md) · ADR-0002 |
| **FR-S-4** | **지문 확인(SAS)** 을 선택 기능으로 제공한다 — 짧은 인증 문자열/이모지를 양쪽에 표시해 육안 대조 | P1 | v1 | ADR-0002 |
| **FR-S-5** | 수신 파일은 **4단계 게이트**(협상→격리→검사→승인 실체화)를 반드시 거친다 | P0 | v1 | DR-13 · [04 §4](04-safe-transfer.md) |
| **FR-S-6** | 격리물은 **`.beepq` 컨테이너**로만 존재한다 — 헤더 봉인 · 콘텐츠 주소 파일명(`<sha256>.beepq`) · 실행권한 없음 · OS 격리 표식 | P0 | v1 | [04 §4-1](04-safe-transfer.md) |
| **FR-S-7** | **원본 파일명은 승인 전까지 파일시스템에 쓰지 않는다** | P0 | v1 | [04](04-safe-transfer.md) T-4 |

| **FR-S-9** | **앱은 수신 파일을 실행하지 않는다** — 실행/열기 API를 코드에 두지 않고 "폴더에서 보기"만 제공 | P0 | v1 | [04 §4-3](04-safe-transfer.md) |

| **FR-S-11** | 아카이브는 **자동 해제하지 않는다**. 목록 조회 시 Zip Slip·압축폭탄을 방어한다 | P0 | v1 | [04](04-safe-transfer.md) T-5 |

| **R-13** | **내가 켠 릴레이 규칙이 나를 때린다** — 수신자 통제 구조라 발신자는 채널을 고를 수 없지만, **무인증 상대의 `Urgent`가 내 규칙을 격발**시킬 수 있다. 그러면 내 폰·메일이 폭격당하고 **앱을 꺼도 계속되며**, 동시에 우리가 **외부 서비스에 폭주 발송원**이 된다 | 높음 | **FR-S-46** — 안전한 기본값(검증된 상대만 · 사용자가 넓힐 수 있음) + **끌 수 없는 속도·일일 상한**(외부 영향은 내 결정권 밖) + 묶음 발송 + 차단 우선 제외 + 억제 보고. **기본 비활성** → [24 §6-6](24-adr-0010-message-priority-notification.md) | 🔴 **설계 반영 · 확정 대기** |
| **R-14** | **TLS 스택 도입이 크기 예산(NFR-B-3)을 흔들 수 있다** — Webhook/SMTP는 HTTPS를 요구하고, 이는 **첫 TLS 의존성**이다(현재 릴리스 0.40MB) | 중간 | **SP-2 스파이크로 실측 후 결정**(Q-24-1). 초과하면 FR-S-43을 v2로 미루거나 OS TLS로 좁힌다 → [24 §8](24-adr-0010-message-priority-notification.md) | ☐ |
| **R-15** | **시스템 폰트 파일 힙 로드가 유휴 RSS 예산을 잠식** — mac 한글 TTC **55MB** · Windows 맑은 고딕 **12.84MB**를 `fs::read`로 통째 적재. Windows 실측 유휴 RSS **28.5MB = NFR-B-1(30MB)의 95%** | 높음 | **memmap2 파일 백드 매핑으로 교체**(08-08 · 사용자 확정) — 사용 글리프 페이지만 상주하고 압박 시 스왑이 아니라 **폐기**로 회수된다. **실측 mac 138.1 → 85.7MB(−51MB)** | ✅ **해소(08-08)** |
