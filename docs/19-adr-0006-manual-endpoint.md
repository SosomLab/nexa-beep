# 19 · ADR-0006 — 수동 엔드포인트 등록 (직접 IP로 노드 추가)

> **상태: 📐 Proposed (사용자 확정 대기)** · 제안 2026-08-08 · 결정자 Sangyong Bae
> **사용자 확정 요구(2026-08-08)**: *"public IP가 있다면 직접 IP를 등록해서 대화 상태로 추가할 수 있는 기능을 설계에 포함."*
> [ADR-0002 §5](08-adr-0002-discovery-transport.md)의 **S6 단계**를 구체화하고, **LAN 밖 연결**로 확장한다.
> 관련: [ADR-0003](09-adr-0003-transport-abstraction.md)(`Locator`) · [10 DR-8](10-decision-record.md)(2모드) · [05](05-requirements.md) FR-D/FR-S

---

## 1. 배경

자동 발견([06 §4](06-network-stack.md))이 닿지 않는 두 경우를 하나의 기능으로 덮는다.

| 경우 | 상황 |
|---|---|
| **A. LAN 내부인데 발견 실패** | 클라이언트 격리·VLAN 분리·서브넷이 다름 — S1~S5가 전부 실패(S6) |
| **B. LAN 밖** | 상대에게 **공인 IP**(또는 포트포워딩된 주소·DDNS 이름)가 있다 |

두 경우 모두 **"주소를 안다"** 는 공통점이 있고, 그 뒤 과정(TCP 연결 → Noise 핸드셰이크 → TOFU)은 **완전히 동일**하다. 그래서 하나의 기능으로 설계한다.

### DR-1(설정 0개)과 충돌하는가 — 아니다

| | |
|---|---|
| **기본 경로는 여전히 자동 발견**이다. 수동 등록은 **자동이 실패했거나 범위 밖일 때의 추가 경로** | ✅ DR-1 유지 |
| 수동 등록을 **하지 않아도 제품은 완전**하다 | ✅ |
| 다만 **UI에서 "고급"으로 숨기지 않는다** — 필요한 사람이 찾을 수 있어야 한다 | |

> [06 §6](06-network-stack.md)의 능력 등급과 같은 논리다 — **T0이 완전한 제품**이고 그 위는 선택.

---

## 2. ⚠️ LAN을 벗어나면 위협 모델이 달라진다

**이것이 이 ADR의 핵심이다.** 지금까지의 설계는 **"같은 물리 네트워크"라는 암묵적 신뢰 경계**에 기대고 있었다. 경우 B는 그 경계를 없앤다.

| 항목 | LAN 내부 | **공인 IP 연결** |
|---|---|---|
| MITM 가능 범위 | 같은 브로드캐스트 도메인 — **물리적 접근 필요** | **경로상의 모든 중간 지점** — ISP·중계망·악성 라우터 |
| 스캔 노출 | 사내망 | **인터넷 전체.** 봇이 상시 두드린다 |
| 상대 확인 | 대개 옆자리 사람 | **누구인지 확인할 사회적 맥락이 없다** |
| TOFU의 위험 | 최초 접촉 MITM 확률 낮음 | **상당히 높아진다** |

### ⇒ 이 차이를 설계에 반영한다 (핵심 결정)

| # | 규칙 |
|---|---|
| **1** | **수동 등록 노드는 "원격" 신뢰 등급**으로 별도 취급한다 — LAN 발견 노드와 같은 취급을 하지 않는다 |
| **2** | **SAS 지문 대조를 강하게 유도**한다. 대조 전까지는 **파일 수신을 기본 차단**하고 텍스트만 허용 |
| **3** | **인바운드는 기본 "요청 대기"** — 서브넷 밖에서 걸려 온 핸드셰이크는 **목록에 자동 등록되지 않는다**. 사용자가 승인해야 한다 |
| **4** | 인바운드에 **강한 속도 제한 + 실패 시 침묵** — 포트 스캔에 정보를 주지 않는다 |
| **5** | UI에 **원격 연결임을 항상 표시**한다. "이 대화는 인터넷을 통해 연결되어 있습니다" |

> ⚠️ **정직한 고지**: 공인 IP를 열면 **우리 포트가 인터넷에 노출된다.** 이건 기능의 부수 효과가 아니라 **전제**다. 활성화 시 그 사실과 위험을 명시적으로 알린다(NFR-S-5).

## 3. 결정

| # | 결정 |
|---|---|
| **①** | **`Locator::Manual { host, port }` 을 추가**한다. 새 `Transport`를 만들지 않는다 — 같은 TCP + Noise 경로를 탄다 |
| **②** | 등록 단위는 **주소가 아니라 노드**다. 주소는 **경로 힌트**이고 **신원은 여전히 키 지문**(DR-8·DR-18) |
| **③** | **호스트명·DDNS 이름 허용** — 동적 IP 환경에서 IP만으로는 실용성이 없다 |
| **④** | 등록 노드는 **고정(pinned)** — 오프라인이어도 목록에 남고, 백오프로 재연결을 시도한다 |
| **⑤** | **원격 신뢰 등급 + 파일 차단 기본값**([§2](#2--lan을-벗어나면-위협-모델이-달라진다)) |
| **⑥** | **인바운드 원격 연결은 요청 대기** — 자동 등록 없음 |

### `Locator` 확장 ([ADR-0003 §3](09-adr-0003-transport-abstraction.md))

```rust
pub(crate) enum Locator {
    LocalDirect { ip: IpAddr, port: u16, if_index: u32 },   // 자동 발견
    Manual      { host: HostSpec, port: u16 },              // ★ 추가 — IP 또는 이름
    Relay       { server: ServerId, peer: PeerId },         // v2
    InMemory    { id: u32 },                                // 테스트
}
```

> **누수 금지 규칙은 그대로다** — `Locator`는 `net` 밖으로 나가지 않는다. 상위 계층은 등록 시에도 **문자열을 넘기고 `PeerId`를 돌려받을 뿐**이다.

### 왜 새 `Transport`가 아닌가

발견 방식만 다를 뿐 **연결 후 경로가 100% 같다**(TCP → Noise_XX → Session). 별도 `Transport`로 만들면 세션·재연결·백프레셔 코드가 두 벌이 된다. **`Transport`에 등록 API를 추가**하는 것으로 충분하다:

```rust
pub trait Transport {
    fn discover(&self) -> PeerHintStream;
    fn connect(&self, peer: PeerId) -> Result<Link>;
    fn listen(&self) -> IncomingStream;

    /// ★ 수동 엔드포인트 등록 — 연결·핸드셰이크 후 PeerId를 확정해 돌려준다.
    /// 실패해도 등록은 남는다(오프라인일 수 있으므로).
    fn add_endpoint(&self, addr: EndpointSpec) -> Result<PeerId, AddError>;
    fn remove_endpoint(&self, peer: PeerId) -> Result<()>;
}
```

## 4. 등록 흐름

```
사용자: "노드 추가" → 주소 입력 (예: 203.0.113.10:PORT · beep.example.com:PORT)
   ▼
[검증] 형식·포트 범위 · 사설/루프백/링크로컬 여부 판정 → 원격이면 위험 고지
   ▼
[연결] TCP → 실패 시 등록만 저장하고 백오프 재시도
   ▼
[핸드셰이크] Noise_XX → 상대 정적 공개키 획득
   ▼
[신원 확정] ┌ 처음 보는 지문 → TOFU 고정 + 🔴 "원격 노드입니다. 지문을 대조하세요"
            ├ 이미 아는 지문  → 같은 노드! 기존 대화에 경로만 추가(★ §5)
            └ 지문 불일치     → 차단 + 경고([08 §4](08-adr-0002-discovery-transport.md))
   ▼
[목록 등록] 고정 항목 · "원격" 배지 · 대조 전까지 파일 수신 차단
```

### 입력 형식

| 형식 | 예 |
|---|---|
| IPv4 + 포트 | `203.0.113.10:PORT` |
| **IPv6 + 포트** | `[2001:db8::1]:PORT` — IPv6는 공인 주소가 흔해 **실제로 가장 현실적인 경로** |
| 호스트명 / DDNS | `beep.example.com:PORT` |
| 포트 생략 | 기본 포트 사용 |

## 5. 이미 아는 노드를 수동 주소로 등록하면

**병합한다.** DR-18의 원칙이 여기서 다시 값을 한다.

| 상황 | 처리 |
|---|---|
| 사무실에서 LAN으로 알던 노드를, 집에서 공인 IP로 등록 | **같은 지문 → 같은 노드.** 대화 스레드가 이어진다. 경로 후보에 `Manual`이 추가될 뿐 |
| 경로 우선순위 | **LocalDirect > Manual > Relay**(v2) — 같은 LAN에 있으면 인터넷으로 우회하지 않는다 |
| 신뢰 등급 | 이미 LAN에서 **대조 완료**였다면 그 상태를 유지한다 — 지문이 같으므로 |

> **주소가 아니라 지문이 신원**이라는 결정([DR-8](10-decision-record.md)·DR-18)이 없었다면, 여기서 "같은 사람인데 다른 항목"이 생겼을 것이다.

## 6. 인바운드 정책

우리가 포트를 열면 **아무나 핸드셰이크를 걸 수 있다.**

| 발신 출처 | 처리 |
|---|---|
| **같은 서브넷**(자동 발견 범위) | 기존과 동일 — 목록에 등장 |
| **서브넷 밖 · 이미 등록·대조한 노드** | 정상 연결 |
| **서브넷 밖 · 처음 보는 노드** | 🔴 **요청 대기** — 목록에 자동 등록되지 않는다. **"원격 연결 요청" 알림 1건**만 뜨고, 사용자가 승인해야 대화가 시작된다. 승인 전 메시지는 표시하지 않는다 |
| 반복 시도·스캔 | **속도 제한** + **실패 시 침묵**(잘못된 프로토콜·핸드셰이크 실패에 응답하지 않아 포트 스캔에 정보를 주지 않는다) |
| 인바운드 전면 차단 | **설정으로 제공** — "내가 등록한 노드에만 연결" 모드 |

## 7. 릴레이 모드(DR-8 ②)와의 관계

| | **수동 엔드포인트**(이 ADR · v1) | **릴레이**(v2 · `nexa-beepd`) |
|---|---|---|
| 서버 | 없음 | 필요 |
| 조건 | **한쪽에 도달 가능한 주소**가 있어야 함 | 양쪽 다 NAT 뒤여도 됨 |
| 메타데이터 | 상대에게만 노출 | **서버가 봉투를 본다**([09 §5](09-adr-0003-transport-abstraction.md)) |
| 설정 | 주소 입력 | 서버 주소 + 서버 운영 |

> **양쪽이 모두 NAT 뒤면 수동 등록으로는 해결되지 않는다.** 그게 릴레이가 남아 있는 이유다. 수동 등록은 릴레이를 **대체하지 않고 앞당긴다** — 공인 IP·포트포워딩이 가능한 사용자는 **서버 없이** 원격 대화를 할 수 있다.

## 8. 하지 않는 것

| 안 하는 것 | 이유 |
|---|---|
| **NAT 홀펀칭 · STUN/TURN · UPnP 자동 포트 개방** | 복잡도·크기(DR-5)와 보안(자동 포트 개방은 위험). 포트포워딩은 **사용자 책임** |
| 등록 주소 목록의 클라우드 동기화 | DR-1·NFR-O-5 위반 |
| QR·링크로 노드 초대 | 좋은 UX지만 v1 범위 밖 — 포스트 v1 후보 |
| 사설 IP 대역 자동 스캔 | S5와 구분. 여기는 **사용자가 준 주소만** |

## 9. 예산 영향

| 항목 | 영향 |
|---|---|
| 크기 | 거의 없음 — 기존 TCP·Noise 경로 재사용. **호스트명 해석**만 추가 |
| 메모리 | 등록 목록(상한 있음) + 재연결 타이머 |
| 유휴 CPU | **백오프 재연결이 NFR-B-7(≤0.2%)을 깨지 않도록** 지수 백오프 + 상한. 오프라인 노드를 공격적으로 재시도하지 않는다 |
