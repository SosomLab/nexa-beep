# 54. 그룹 초대 생애주기 — 재초대 · 거절 · 차단 ✅ (GINV-1 · DR-30 · 2026-11-04)

> 상태: ✅ **확정**(11-04 사용자 · §8 GINV-Q1~Q4 = 권고안 그대로 · [10 DR-30](10-decision-record.md)) · S1 ✅(`8409384` · 재기동 실측 `f541301`) · S2 ✅(`563cd6e`) · S3·S4 다음.
> 내용 결정 = 개발 세션 · 작성 = 협업 세션([53 §3](53-collab-session-operation.md)).
> 관련: [31 ADR-0012 공유 그룹 채팅](31-adr-0012-shared-group-chat.md)(명부·Invite/Accept/Decline/Suggest 와이어) · [38 수신 제한 4축](38-receive-restriction-design.md)(차단 목록 · 이 문서가 "그룹 초대" 축을 더한다) · [24 ADR-0010](24-adr-0010-message-priority-notification.md)(DR-25 미검증 무음).

## 0. 배경 (사용자 11-04)

다른 PC 사용자를 그룹에 초대하면 상대에게는 수락/거절 카드가 뜨고, 초대한 PC에는 그 구성원이 "초대 대기"로 남는다.
상대가 거절했거나 아무것도 누르지 않으면 이 표시는 **영영 남는다**.

요구는 셋이다.

1. 초대한 쪽이 **다시 초대**할 수 있어야 한다.
2. 거절한 쪽은 **반복 재초대를 막고** 싶다.
3. 그래도 몰라서 못 눌렀거나 **실수로 거절**한 경우에는 다시 받고 싶다.

## 1. 현 코드 (11-04 사실 · S1 이전)

| 자리 | 동작 | 문제 |
|---|---|---|
| 명부 `Roster.members` | 초대 즉시 구성원으로 들어간다 · 구성원 상태 필드 없음 | "초대 대기"와 "수락함"을 명부로 가를 수 없다 |
| 수락 확인 `App.group_accepts` | **메모리 HashMap만** | 소유자가 재시작하면 **전원이 "초대 대기"** 로 보인다 · 상대가 resync 재초대에 Accept를 되돌려 줘야 치유된다(08-19 자가 치유 = 상대 기동에 의존) |
| 거절 `SGroupMsg::Decline{uid}` | 소유자가 명부에서 빼고 재배포 · 거절한 쪽은 `remove_shared` | 거절은 되돌릴 수 없고 반복 재초대를 막을 수단도 없다 |
| 초대 카드 `open_choice` | 2택(수락/거절) | 모르면 거절을 누르게 된다 · 나중에 다시 볼 자리가 없다 |
| 미연결 상대 초대 | `pending_invites` 큐 + 자동 연결(resync_keep 상한) | — |

## 2. 원칙

> **초대는 소유자의 의사, 거절은 피초대자의 의사. 어느 쪽도 상대를 영원히 묶지 않는다.**

- 소유자는 재초대할 수 있지만 **빈도 제한**이 있다(피초대자 괴롭힘 방지를 발신측에서 먼저).
- 피초대자는 거절·차단할 수 있지만 **스스로 되돌릴 통로**가 있다(실행 취소 · 차단 해제).
- 초대가 응답 없이 남으면 **만료**로 정리된다.

**이 계층의 봉투는 무엇인가**(10 §0 관통 원리):

| 층 | 보는 것 | 보지 않는 것 |
|---|---|---|
| 명부(와이어 · 전원 공유) | 구성원 PeerId만 | 초대 대기·거절·차단 상태 |
| 구성원 상태 메모(소유자 로컬) | 상대별 Invited/Joined/Declined · 시각 · 횟수 | — |
| 초대 차단 목록(피초대자 로컬) | 차단한 그룹 uid | — |
| 거절 와이어 | 거절 사실 + `hard` 비트 1개 | 거절 사유 · 차단 목록 내용 |

## 3. 설계 (A~G)

### A. 소유자 측 구성원 상태 = 로컬 영속 — **S1 ✅**

- `groups.seg` **v4** · `SharedGroup.members_meta: Vec<(PeerId, MemberMeta{state, at_ms, tries})>` · `MemberState {Invited, Joined, Declined}`.
- 직렬화 꼬리 = `count u32 · {peer 32 · state u8 · at u64 · tries u8}` · v3 이하 파일 = 빈 목록으로 읽는다(전방·후방 호환).
- 규칙 `note_member`: Invited는 Joined를 **내리지 않는다** · 첫 초대 시각 보존 · 횟수 포화 +1 · 명부 밖 상대 거부 · 바뀐 때만 write-through · 명부 갱신 때 빠진 상대의 메모는 걷는다.
- 앱: `group_accepts` 삭제 → 초대 송신 3곳(방 생성 · 구성원 추가 · 제안 수락)이 `Invited`, Accept 수신이 `Joined`를 기록.
- 구성원 목록 표시 = "초대 대기 · n분/n일 전"(첫 초대 시각) / "거절함"(`Msg::MemberDeclined`).
- **명부 와이어는 무변경**이다. 명부 = 진실, 상태 = 소유자의 로컬 메모.
- S1 구조에는 아직 `hard` 구분이 없다 → S4에서 `Declined`에 차단 여부를 더한다(§3-E).

### B. 재초대

- 구성원 모달의 "초대 대기"·"거절됨" 행에 **[재초대]** 버튼 → 같은 `Invite` 프레임을 다시 보낸다(멱등 · 피초대자가 Invited 상태면 카드를 다시 띄운다).
- 제한 = **같은 상대·같은 방 24시간에 1회**(`at_ms`·`tries`로 판정 · 설정 **`group.reinvite_hours`** 기본 24 · ✅ GINV-Q1) · 초과 시 안내 "n시간 뒤 다시 초대할 수 있습니다".
- 상대가 `hard` 거절(§E)했으면 [재초대]는 비활성이다.

### C. 초대 만료

- 소유자 로컬 `Invited.at` + **7일**(설정 **`group.invite_expire_days`** 기본 7 · ✅ GINV-Q2)이 지나면 명부에서 자동 제거 후 재배포하고, 방 스레드에 한 줄 남긴다.
- 의미 = 상대가 Invite를 못 받았거나 누르지 않았다 · 다시 초대하면 새로 시작한다.
- 피초대자 측 카드(Invited)는 만료 없이 다음 기동 때도 뜬다(지금과 같다).

### D. 피초대자 카드 3택

- **[수락] [거절] [나중에]**(✅ GINV-Q3 · 영 Later · 중 稍后 · 일 あとで) — "나중에" = 카드만 닫고 Invited 유지 · 목록의 "초대됨" 행에서 다시 연다.
- 지금의 2택은 모르는 사용자를 거절로 몰아간다. "나중에"가 "몰라서 못 누름"을 푼다.
- 거절에는 체크박스 **"이 그룹 초대 다시 받지 않기"**(기본 꺼짐).

### E. 거절 와이어 `DeclineV2` + 초대 차단 목록

- 새 kind **`DeclineV2{uid, hard: bool}`**. 구버전 소유자는 미지 kind를 버리므로 **기존 `Decline`도 함께** 보낸다(해석기 먼저 배포 규약과 같은 결).
- `hard=false`(기본): 소유자 모달 "거절됨 · [재초대]"(B의 24시간 제한 적용).
- `hard=true`: 소유자 모달 "거절됨 · 재초대 불가(상대가 차단)" · [재초대] 비활성.
- 피초대자는 로컬 **`invite_block: {uid}`** 에 넣는다 — `trust.seg` 봉인 확장 · [38](38-receive-restriction-design.md) 수신 제한의 "그룹 초대" 축.
- 차단된 uid의 Invite는 **카드 없이 조용히 자동 `DeclineV2{hard}`** 로 답한다.
- 해제 = **설정 › 고급 › 수신 제한 목록**에서 지운다(✅ GINV-Q4 · [38](38-receive-restriction-design.md) 4축 목록과 통합 · 그룹 목록 보조 진입점은 두지 않는다) → 다음 초대부터 카드가 다시 뜬다. "실수로 영구 거절"의 회복 통로다.

### F. 실수 거절 회복 = 5초 실행 취소

- 거절을 누르면 와이어로 바로 보내지 않고 HUD "초대를 거절했습니다 · 실행 취소"를 5초 띄운다(nexa-sql `hud.*` 이식분 재사용 · 11-02 "복사됨" HUD와 같은 장치).
- 취소하면 와이어 0. 5초가 지나면 그때 Decline을 보낸다.
- 소유자는 아무것도 모른 채 끝난다 — 양쪽 모두에게 가장 싼 회복이다.

### G. 넣지 않는 것 — 역방향 "다시 초대해 달라"(JoinRequest)

- 피초대자 → 소유자 역방향 와이어가 하나 더 생기면 스팸 축이 늘고 DR-25(미검증 무음)와 충돌한다.
- D(나중에)와 F(실행 취소)로 대부분 해소된다.
- 필요해지면 새 kind 대신 기존 `Suggest{uid, members:[me]}` 재사용을 검토한다(구성원용 제안 와이어가 이미 있다).

## 4. 상태 전이 (소유자 로컬 메모)

```
          초대 송신                Accept 수신
 (없음) ───────────▶ Invited ───────────────▶ Joined
                      │  ▲
       Decline/V2 수신 │  │ [재초대] (24h 1회 · hard면 불가)
                      ▼  │
                    Declined{hard}
                      
 Invited + 7일 무응답 ──▶ 명부 제거 + 재배포 (메모 걷음)
 명부에서 빠짐(제외·탈퇴) ──▶ 메모 걷음
```

피초대자 로컬: `카드 표시(Invited)` → 수락 / 나중에(유지) / 거절 → 5초 HUD → 전송 · 체크 시 `invite_block` 추가.

## 5. 호환

| 상대 | 동작 |
|---|---|
| 구버전 소유자 ← 신버전 피초대자 거절 | `Decline` + `DeclineV2` 동시 송신 → 구버전은 `Decline`만 처리(종전과 같음) |
| 신버전 소유자 ← 구버전 피초대자 거절 | `Decline`만 도착 → `Declined{hard=false}` |
| `groups.seg` v3 이하 | 메모 빈 목록 → 전원 상태 미상 · 다음 Accept/resync로 채워진다 |

## 6. 한계 (정직)

- 상태는 **소유자 PC 한 대의 로컬 메모**다. 같은 사용자의 다른 기기(X-13 형제)에는 동기되지 않는다(필요 시 S4 따라잡기 확장 · 별도 결정).
- 24시간 제한은 소유자 앱의 자율 규칙이다. 개조 클라이언트는 무시할 수 있다 → 피초대자 쪽 방어는 E(hard 차단)와 [38](38-receive-restriction-design.md) 수신 제한이 맡는다.
- `invite_block`은 **그룹 uid 단위**다. 같은 소유자가 새 방을 만들어 초대하면 카드가 다시 뜬다 → 사람 단위 차단은 [38](38-receive-restriction-design.md) 신원 축(PeerId/UserId)으로.
