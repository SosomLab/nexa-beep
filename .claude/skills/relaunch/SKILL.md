# 기준 재기동 — 종료 → 재빌드 → 3신원 → 발견 확인

사용자가 재기동을 요청하면 **한 번에** 처리한다. 단계를 나눠 묻지 않는다.

```bash
./tools/relaunch.sh
```

스크립트가 다섯 단계를 순서대로 하고, 마지막에 **셋이 서로 보이는지까지** 확인한다:
① 전부 종료 → ② 릴리스 빌드(`nexa-beep` + `nbeep-imgdec`) → ③ 3신원 폴더 준비 →
④ 기동 → ⑤ 프로브로 상호 발견 확인.

## 인자 — 요청에 따라 고른다

| 사용자가 말한 것 | 쓸 인자 |
|---|---|
| 그냥 "재기동", "다시 띄워줘" | *(없음)* — **기존 신원 유지** |
| "새 신원으로", "초기화해서", "핀 지우고" | `--fresh` |
| "게이트도 돌려줘", "테스트까지" | `--gate` |
| "빌드는 됐고 실행만" | `--no-build` |

## ★ 기본은 신원 보존이다

`--fresh`를 **먼저 묻지 말고 붙이지도 말 것.** A·B 폴더를 지우면 그 신원의
**핀·그룹·프로필·설정이 통째로 사라진다** — 진행 중이던 그룹 테스트를 처음부터
다시 해야 한다(실제로 한 번 날렸다). 초기화는 사용자가 말할 때만.

## 결과 보고

실행 후 사용자에게 **발견된 3신원의 지문·이름**을 그대로 보여준다. 창이 떴다는 것만으로는
부족하다 — 발견이 막히면 아무것도 못 한다.

실패(창 3개 미만 또는 발견 3명 미만)면 스크립트가 exit 1과 함께 로그 경로를 알려준다:
`/tmp/beep-base.log` · `/tmp/beep-multi/{A,B}/out.log`.

## 배경

- 신원이 갈리는 원리 = **`data/`는 작업 디렉터리가 아니라 실행 파일이 있는 곳을 따라간다**
  (포터블 규칙 DR-4). 폴더가 곧 신원이다 — [26 §3-4](../../../docs/26-run-and-manual-test.md).
- 3명인 이유 = 그룹은 **3명 이상**이어야 1:1과 구분된다 —
  [33 §2](../../../docs/33-group-chat-test-guide.md).
- `nbeep-imgdec`를 함께 복사하는 이유 = 없으면 **경고 없이** 아바타·이미지만 죽는다.
